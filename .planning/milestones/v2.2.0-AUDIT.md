## Gaps & Tech Debt

### GAP: R5.3 — No `sendMessage({ triggerTurn: true })` Push Delivery

**Severity:** LOW  
**Impact:** Subagent results require explicit polling via `luca_subagent_result`. The LLM must actively check for completion rather than being notified.  
**Rationale:** The `pi.sendMessage()` API would inject a message into the primary agent's conversation when a subagent completes. Current polling approach is simpler, more predictable, and avoids race conditions. Push delivery can be added later if needed.  
**Recommendation:** Defer to v2.3.0+ if user feedback indicates polling is insufficient.

### GAP: R5.7 — Team → Subagent Dispatch Integration

**Severity:** LOW  
**Impact:** `luca-teams.ts` doesn't automatically spawn subagents when dispatching. Teams dispatch is advisory — the LLM chooses whether to use subagents.  
**Rationale:** Tight coupling between teams and subagents would add complexity. The current design lets the LLM orchestrate as appropriate.  
**Recommendation:** Consider a `luca_dispatch_team_parallel` tool in a future milestone if the pattern proves useful.

### TECH DEBT: Environment-Dependent Tests

**Severity:** LOW (pre-existing)  
**Impact:** 3 tests in `todo-parser.test.ts` and `planner integration` assume `.planning/todos/pending/` is non-empty. They fail when all todos are moved to `done/`.  
**Recommendation:** Make these tests use fixture data instead of live filesystem state.

### TECH DEBT: Acceptance Criterion #4 — "Live Pi Session" vs E2E Mock

**Severity:** LOW  
**Impact:** The E2E test suite uses a mock `Pi ExtensionAPI`, not an actual Pi process. This validates code structure and logic but not Pi version compatibility.  
**Recommendation:** A manual smoke test checklist or a CI step that runs `pi --extensions .pi/extensions/luca-state.ts --mode json -p "test"` would close this gap.
