# Requirements — v1.3.0 Claude Code Plugin Distribution

## Overview

Package the Luca framework as a Claude Code plugin for cross-platform distribution. Leverages the existing compiler architecture (src/ → .claude/ + .cursor/) to add a third compilation target: a self-contained Claude Code plugin package distributable via GitHub marketplace.

**Core Value:** Zero-friction adoption of structured AI workflows — now on both Cursor IDE and Claude Code
**Motivation:** v1.2.0 made agents intelligent. v1.3.0 makes Luca distributable beyond Cursor IDE. Claude Code's plugin system bundles skills, agents, hooks, and MCP servers into namespaced, installable units. Luca's existing compiler infrastructure makes this a natural extension.

## Out of Scope

| Feature                                 | Reason                                                          |
| --------------------------------------- | --------------------------------------------------------------- |
| npm distribution                        | Not yet fully implemented in Claude Code                        |
| MCP server bundling                     | Luca doesn't currently use MCP servers; add when needed         |
| LSP server integration                  | Not applicable to workflow framework                            |
| Cross-IDE plugin (VS Code)              | Separate effort, different plugin system                        |
| Plugin lifecycle hooks (init/uninstall) | Not available in Claude Code yet (Issue #11240)                 |
| Automated CLAUDE.md injection           | Not supported by plugin system; rules-as-skills workaround used |
| Plugin auto-update mechanism            | Handled by Claude Code's marketplace infrastructure             |

## Research Summary

Research conducted via web search and documentation analysis covering: Claude Code plugin spec (create plugins, plugin reference), marketplace system (distribution, installation), plugin component types (skills, agents, commands, hooks, MCP, LSP), namespacing patterns, lifecycle limitations, and distribution strategies.

Key research findings informing requirements:

1. **Plugin manifest is minimal** — Only `name` is required; auto-discovery handles the rest (PLUG-01, PLUG-02)
2. **No CLAUDE.md injection** — Rules must be converted to skills for auto-invocation (PACK-04)
3. **npm distribution not ready** — Use GitHub marketplace as primary distribution (DIST-01, DIST-02)
4. **`${CLAUDE_PLUGIN_ROOT}` for paths** — All hook/script paths must be plugin-relative (HOOK-01, HOOK-02)
5. **No lifecycle hooks** — SessionStart is the only initialization point (HOOK-03)
6. **Lazy loading for skills** — Keep descriptions concise; Claude only loads full content when needed (PACK-05)
7. **Plugins copied to cache** — External dependencies must be self-contained (HOOK-02)
8. **Namespace prefix** — All components auto-prefixed with plugin name (PACK-01, PACK-02, PACK-03)
