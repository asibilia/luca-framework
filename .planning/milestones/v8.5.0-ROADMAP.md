## Architecture

Each decomposed skill follows the validated pattern:

- **Thin orchestrator** — Zero inline logic, only Skill() calls + context reads + state transitions
- **State machine** — Per-skill XState v5 definition via createSkillStateMachine factory
- **Context schema** — Zod schema with read/write helpers, context_version field, /tmp/ context files
- **Enforcement hook** — Pre-step hook validates state before sub-skill invocation
- **Registry entries** — Hook registry + skill registry for each sub-skill
