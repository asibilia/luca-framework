# v4.2.0 — Workflow Unification & Memory Architecture

## Overview

Rework complexity gating so it no longer skips workflow steps, and formalize multi-vault MuninnDB architecture with scoped recall/write strategies. These are architectural prerequisites for v5.0.0 (plugin ecosystem).

## Absorbs

- **#38** — Rework complexity gating: remove step gating, unify lu/autopilot pipeline
- **#39** — Multi-vault MuninnDB: default vault for cross-cutting, repo vaults for project-specific

## Phases

### Phase 01 — Complexity Gating Audit & Step Removal

- **Goal:** Remove all step-gating conditionals from skills. Every workflow step (research, discussion, planning, verification, code review, UAT, learning capture) runs at every complexity level.
- **Scope:** Audit all skills that gate steps on complexity, remove conditionals, align /lu and /autopilot to share the same pipeline.
- **Absorbs:** #38 tasks 1-3
- **Depends on:** None
- [x] PLAN.md — Complexity Zero-Value Fix & /lu Routing Alignment

### Phase 02 — Complexity Rule & Schema Alignment

- **Goal:** Update the complexity-gating rule, config.json schema, and complexity matrix to reflect model-tier-only scope. Remove iteration count scaling that represents step-gating. Keep model routing table.
- **Scope:** Rule files, config schema, complexity domain schemas.
- **Absorbs:** #38 tasks 4-7
- **Depends on:** Phase 01
- [x] PLAN.md — Complexity Rule Model-Tier-Only Scope Alignment

### Phase 03 — Multi-Vault Architecture & Migration

- **Goal:** Formalize vault roles (default = cross-cutting, repo = project-specific). Split brain tree into project brain and user brain. Migrate luca-framework memories from default vault. Research and implement `luca-bridge init-vault` CLI command.
- **Scope:** MuninnDB memory migration, brain tree restructuring, bridge CLI extension.
- **Absorbs:** #39 tasks 1, 3 (CLI)
- **Depends on:** None
- [x] PLAN-01.md — init-vault Bridge CLI Command
- [ ] PLAN-02.md — Memory Migration & Brain Tree Split (requires human checkpoints)

### Phase 04 — Skill Dual-Vault Integration

- **Goal:** Update all skills and agents for scoped dual-vault recall (type-based vault routing with merged scoring) and write routing heuristic ("useful in another repo?" → default, otherwise repo vault).
- **Scope:** lu-cognition, lu-learner, all skills with MuninnDB recall/write, global CLAUDE.md instructions, config schema.
- **Absorbs:** #39 tasks 2-3 (infrastructure)
- **Depends on:** Phase 03
- [ ] PLAN pending

## Success Criteria

- All workflow steps run at every complexity level (TRIVIAL through CRITICAL)
- /lu and /autopilot follow identical pipeline (autopilot = autonomous decisions only)
- Complexity controls model tier only (MODEL_ROUTING_TABLE unchanged)
- Multi-vault recall works: project identity from repo vault, patterns/pitfalls from both vaults merged by score
- Write routing: cross-cutting → default vault, repo-specific → repo vault
- `luca-bridge init-vault` creates vault, generates API key, configures project
- Brain tree split: project brain in repo vault, user brain in default vault
