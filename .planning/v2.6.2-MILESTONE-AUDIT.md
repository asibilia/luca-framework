## Tech Debt

### Barrel Import Compliance (Systematic — MEDIUM)

The most systemic issue: 6+ files in `agents/__helpers/` and `skills/__helpers/` import directly from `~/shared/__helpers/*` paths instead of the `~/shared` barrel. All symbols are re-exported from the barrel. While the module boundary rule allows shared direct imports as an exception, barrel-first is preferred and these should be consolidated.

**Files affected:** `verification-tribunal.ts`, `root-cause-tribunal.ts`, `milestone-debate.ts`, `pr-verdict-debate.ts`, `milestone-debate.schemas.ts`, `metrics-collector.ts`, `convergence.ts`

### Additional DRY Opportunities (HIGH)

Two remaining DRY patterns identified that were not in the v2.6.1 audit scope:

1. **H1:** `detectT1T3Conflict()` — 3 near-identical safeParse blocks → extract `buildConflictSignal()` helper
2. **H2:** `pr-verdict-debate.ts` — `majorityIsValid` + derived values repeated 4× → extract `resolveSplitPerspective()` helper
3. **M6:** `safeParseOrNull` pattern (safeParse → check → console.error → return null) repeated ~8× across metrics-collector builders and tribunal resolvers

### sanitizeForTemplate T0/T3 Divergence (MEDIUM)

The T3 copy (`hooks/pi-extensions/__helpers/sanitize.ts`) was not updated with the v2.6.2 hardening (complete `${...}` stripping, bidi defense). The two copies are documented as intentionally separate but should have matching security behavior.

### Defense-in-Depth Sanitization Gaps (MEDIUM)

Zod-enum-validated fields (`conflict_type`, `t1_status`, `t3_status`) interpolated in prompt templates without `sanitizeForTemplate()`. Not exploitable through normal paths but inconsistent with adjacent free-text field treatment.
