# Plan 31-01: TDD Integration Design + lu-test-writer Agent

## Objective

Create the `lu-test-writer` LLM prompt agent that translates plan verification criteria into executable test files. This agent receives a plan's tasks, verification checklists, and success criteria, then generates `bun:test` test files that encode those criteria as automated assertions. The agent is the foundation of the TDD-first pattern: its output is what the executor runs in the Red phase (tests must fail before implementation) and the Green phase (tests must pass after implementation).

## Context

@src/agents/base/base-agent.ts -- BaseAgentImpl class that all agents extend. Constructor validates config with Zod schema.
@src/agents/types/agent.types.ts -- AgentConfig, AgentFrontmatter, AgentSection, BaseAgent interfaces.
@src/agents/types/agent.schemas.ts -- Zod schemas for agent config validation (agentConfigSchema, agentFrontmatterSchema, etc.).
@src/agents/index.ts -- Agent registry. Maps agent names to factory functions. New agent must be imported and registered here.
@src/agents/general/lu-plan-checker.agent.ts -- Example of a general agent with cognition config, context isolation, and structured prompt sections. Follow this pattern.
@src/agents/general/qa-plan-generator.agent.ts -- Example of a test-generation-adjacent agent. Follow naming and section conventions.
@CLAUDE.md -- Project conventions (Bun-first, bun:test, no classes rule applies to user code but agents extend BaseAgentImpl per established pattern).

## Tasks

### Task 1: Create the lu-test-writer agent definition file

**Goal:** Create `src/agents/general/lu-test-writer.agent.ts` following the established agent definition pattern. The agent is an LLM prompt agent -- its sections contain natural language instructions that tell the LLM how to generate test files from plan verification criteria.

**Files:** `src/agents/general/lu-test-writer.agent.ts` (create)

**Steps:**

1. Create the file with standard imports:

   ```typescript
   import { BaseAgentImpl } from "../base/base-agent";
   import type { AgentConfig } from "../types/agent.types";
   ```

2. Define the agent config with frontmatter:
   - `name`: `"lu-test-writer"`
   - `description`: `"Generates test files from plan verification criteria. Translates plan tasks, verification checklists, and success criteria into executable bun:test test suites. Spawned by lu-executor during TDD cycle."`
   - `tools`: `["Read", "Write", "Bash", "Grep", "Glob"]`
   - `color`: `"cyan"`
   - `cognition`: `{ default_tier: "T1", promotable_to: "T2", memory_tags: ["testing", "patterns", "conventions"] }`
   - `context`: `{ default_tier: "T1", promotable_to: "T2", isolation: "none" }`

3. Define the sections array with the following ordered sections:

   **Section 1 - "role" (order: 1):**
   The role section must instruct the LLM to:
   - Act as a test-first writer that generates failing tests from plan specifications
   - Read plan verification criteria, success criteria, and task descriptions
   - Generate `bun:test` test files using `import { describe, test, expect } from "bun:test"`
   - Write behavior-focused tests (what the code should do, not how it does it)
   - Follow project conventions from BRAIN.md and CLAUDE.md (kebab-case files, functional patterns)
   - Include cognition integration block (T1 memory-reader) for recalling test patterns and pitfalls

   **Section 2 - "test_generation_process" (order: 2):**
   The process section must instruct the LLM to follow these steps:
   - Step 1: Parse the plan content. Extract task descriptions, file paths from task files lists, verification checklists, and success criteria.
   - Step 2: Determine test file location. Use `__tests__/` directory mirroring the source file path. For a file at `src/agents/general/lu-test-writer.agent.ts`, the test goes at `__tests__/src/agents/lu-test-writer.test.ts`. Use kebab-case.
   - Step 3: Generate test structure. Create one `describe()` block per task. Create one `test()` per verification checklist item and per success criterion. Tests must be concrete -- import the module under test, call functions, assert expected behavior.
   - Step 4: Ensure tests are RED-ready. Tests must reference the code that will be created but does not yet exist. They should fail with import errors or assertion failures, NOT with syntax errors. Use `try/catch` around dynamic imports if the file might not exist yet.
   - Step 5: Write the test file using the Write tool.
   - Step 6: Run `bun test <test-file>` to confirm tests fail (Red phase confirmation). Report the failure count and types.

   **Section 3 - "test_patterns" (order: 3):**
   The patterns section must provide guidance on:
   - Agent compilation tests: For new agents, test that the agent config validates against `agentConfigSchema`, the agent has required sections, `name` matches expected value, `toCursorFormat()` and `toClaudeFormat()` return strings.
   - Agent registration tests: Test that the agent is registered in `agentRegistry` with the correct key.
   - Function/module tests: For utility functions, test inputs/outputs, edge cases, error handling.
   - Integration tests: For skill modifications, test that the skill compiles and sections reference expected content.
   - Use `bun:test` exclusively. Never use jest or vitest imports.
   - Prefer `toContain`, `toBe`, `toEqual`, `toThrow` assertions.
   - Do NOT test implementation details -- test observable behavior.

   **Section 4 - "non_testable_detection" (order: 4):**
   The non-testable detection section must instruct the LLM on:
   - How to detect non-testable work: documentation-only tasks, configuration changes, research tasks, planning updates
   - When a task is non-testable, return a structured response indicating `testable: false` with a reason
   - The executor will skip the TDD cycle for non-testable tasks and fall back to goal-backward verification
   - Criteria for testable: creates or modifies `.ts` or `.tsx` files, has verification criteria that can be expressed as assertions

   **Section 5 - "output_format" (order: 5):**
   The output format section must define the return structure:

   ```
   ## Test Generation Complete

   **Test file:** {path to test file}
   **Tests generated:** {count}
   **Testable tasks:** {count} / {total tasks}
   **Non-testable tasks:** {list with reasons}

   ### Test Summary
   | Task | Tests | Status |
   |------|-------|--------|
   | {task name} | {count} | RED (expected) |
   | {task name} | 0 | Non-testable: {reason} |
   ```

4. Export the class:

   ```typescript
   export class LuTestWriterAgent extends BaseAgentImpl {
     constructor() {
       super(luTestWriterConfig);
     }
   }
   ```

- [ ] Agent config validates against `agentConfigSchema` (Zod parse in constructor)

### Task 3: Write compilation and registration tests for lu-test-writer

**Goal:** Create a test file that verifies the lu-test-writer agent compiles correctly, validates against the schema, and is properly registered.

**Files:** `__tests__/src/agents/lu-test-writer.test.ts` (create)

**Steps:**

1. Create the test file with:

   ```typescript
   import { describe, test, expect } from "bun:test";
   import { LuTestWriterAgent } from "../../../src/agents/general/lu-test-writer.agent";
   import { agentRegistry } from "../../../src/agents/index";
   ```

2. Add a `describe("lu-test-writer agent")` block with these tests:

   a. **Test: agent instantiates without error.** `new LuTestWriterAgent()` should not throw. This validates the config passes `agentConfigSchema.parse()`.

   b. **Test: agent has correct name.** `agent.name` should equal `"lu-test-writer"`.

   c. **Test: agent has correct description.** `agent.description` should contain `"test files from plan verification criteria"`.

   d. **Test: agent has required tools.** `agent.config.frontmatter.tools` should include `"Read"`, `"Write"`, `"Bash"`.

   e. **Test: agent has cognition config.** `agent.config.frontmatter.cognition` should exist with `default_tier: "T1"`.

   f. **Test: agent has all required sections.** `agent.config.sections.length` should be at least 5. Section titles should include `"role"`, `"test_generation_process"`, `"test_patterns"`, `"non_testable_detection"`, `"output_format"`.

   g. **Test: toCursorFormat returns string.** `agent.toCursorFormat()` should return a non-empty string.

   h. **Test: toClaudeFormat returns string.** `agent.toClaudeFormat()` should return a non-empty string.

   i. **Test: agent is registered in agentRegistry.** `agentRegistry["lu-test-writer"]` should be a function. Calling it should return an instance with `name === "lu-test-writer"`.

**Verification:**
