# Improve stale session lock cleanup in build system

## Goal

Improve the DX of `bun run build:all` when a stale session lock blocks the build. The auto-cleanup at 4h is already functional. This plan focuses on better error messaging and an explicit cleanup flag.

## Context

@scripts/build-all.ts — lines 29-64 contain the session lock guard

- Line 47: Auto-cleans locks older than 4 hours
- Lines 57-62: Error message when lock is fresh and --force not used

The current error message says:

```
Build blocked: an active session is in progress (Xh old)
Run with --force to override, or end the session first.
```

This should be expanded with clearer recovery options.

## Tasks

### t1: Improve error message with recovery options

Update the error message in the `else` branch (lines 57-62) to read:

```
Build blocked: an active session is in progress (Xh old).

Recovery options:
  1. Wait for the session to end naturally
  2. Run with --force to override the lock and build anyway
  3. Manually delete the lock: rm .claude/.session-lock
  4. Run with --cleanup-stale-locks to remove the lock without building

Locks older than 4 hours are automatically removed.
```

### t2: Add --cleanup-stale-locks flag

At the top of `main()`, before the lock check block, add handling for `--cleanup-stale-locks`:

- If the flag is present and the lock file exists, remove it and print confirmation, then exit 0
- If the flag is present and no lock file exists, print "No stale lock found" and exit 0
- This provides a safe, explicit way to clear a stale lock without building

## Verification

1. `bunx --bun tsc --noEmit` passes (no type errors)
2. Run `bun scripts/build-all.ts --cleanup-stale-locks` — exits cleanly with informational message
3. Error message text in source includes all four recovery options
4. The 4h auto-cleanup threshold is preserved (not changed to 12h)
