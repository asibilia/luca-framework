# Plan 23-01: Plugin Structure and Manifest Spec-Conformance Tests

## Objective

Create automated tests that validate the `dist/plugin/` output against the **Claude Code plugin specification** -- not against our own compiler output (that is the drift tests' job). These tests answer the question: "If Claude Code loaded this plugin directory, would it find everything it expects in the format it expects?" This plan covers two of the five requirements: TEST-01 (structure validation) and TEST-02 (manifest validation).

The tests live in a new file `scripts/plugin-spec-structure.test.ts` and run as part of the standard `bun test` suite.

## Context

@dist/plugin/ -- The plugin output directory. Contains subdirectories: `.claude-plugin/` (manifests), `agents/`, `skills/`, `hooks/`, `scripts/`. This is the directory under test. Note: `commands/` was removed as it is a legacy approach — skills/ handles both auto-invocation and slash commands.

@dist/plugin/.claude-plugin/plugin.json -- The plugin manifest. Must conform to the Claude Code spec: `name` (kebab-case, required), `version`, `description`, `author`, `license`, `keywords`. Must NOT contain component arrays (commands, agents, skills, hooks) -- Claude Code auto-discovers those from directories.

@dist/plugin/.claude-plugin/marketplace.json -- The marketplace manifest. Must have `name` (required), `owner` with `name` (required), `plugins[]` array where each entry has `name` (required) and `source` (required).

@src/compilers/plugin.types.ts -- Contains the Zod schemas (`pluginManifestSchema`, `pluginAuthorSchema`, `KEBAB_CASE_REGEX`) that define the spec. The tests should import and use these schemas for validation rather than re-implementing schema checks.

@scripts/check-drift.test.ts -- The existing drift test suite (781 lines). Contains 5 describe blocks covering output freshness, registry completeness, orphan detection, plugin output freshness, and plugin orphan detection. **DO NOT duplicate any of these tests.** The drift tests check "does output match compiler?" -- this plan checks "does output match the Claude Code spec?"

@scripts/build-shared.ts -- Shared build utilities. Exports `PLUGIN_EXCLUDED_HOOKS` which is needed to understand the expected plugin composition.

@23-CONTEXT.md -- Phase 23 context decisions. Decision 1 (spec-first, no duplication) and Decision 3 (structural + schema validation depth) are directly relevant.

## Tasks

### Task 1: Create the test file with directory structure validation (TEST-01)

**Goal:** Create `scripts/plugin-spec-structure.test.ts` with a `describe("Plugin Directory Structure")` block that validates the required directory layout matches what Claude Code expects when loading a plugin.

**File:** `scripts/plugin-spec-structure.test.ts` (create)

**Steps:**

1. Create the file with the standard test imports:

   ```typescript
   import { describe, test, expect } from "bun:test";
   import { readdirSync, existsSync, statSync } from "node:fs";
   import path from "path";
   ```

2. Define the plugin root constant:

   ```typescript
   const PLUGIN_ROOT = path.resolve(import.meta.dir, "..", "dist", "plugin");
   ```

3. Add the first describe block -- `"Plugin Directory Structure (TEST-01)"`:

   a. **Test: required top-level directories exist.** Claude Code expects these directories at the plugin root:
   - `.claude-plugin/` (manifests)
   - `agents/` (agent markdown files)
   - `skills/` (skill directories with SKILL.md)
   - `hooks/` (hooks.json config)
   - `scripts/` (hook shell scripts)

   For each directory, assert `existsSync(path.join(PLUGIN_ROOT, dir))` is true.

   b. **Test: agents directory contains only .md files.** Read `dist/plugin/agents/` and assert every file ends with `.md`. This validates that no stray files (e.g. `.ts`, `.json`) leaked into the agents directory.

   c. **Test: skills directory contains only subdirectories with SKILL.md.** Read `dist/plugin/skills/`, assert every entry is a directory, and assert each subdirectory contains a `SKILL.md` file.

   d. **Test: hooks directory contains hooks.json.** Assert `dist/plugin/hooks/hooks.json` exists and is valid JSON.

   e. **Test: scripts directory contains only .sh files.** Read `dist/plugin/scripts/` and assert every file ends with `.sh`.

   f. **Test: no unexpected top-level entries.** Read the plugin root directory and assert the only entries are the 5 required directories plus `README.md`. This catches accidental files or directories that would confuse Claude Code.

**Verification:**

- [ ] `scripts/plugin-spec-structure.test.ts` exists
- [ ] `bun test scripts/plugin-spec-structure.test.ts` passes
- [ ] All 6 tests in the "Plugin Directory Structure" block pass
- [ ] No overlap with tests in `scripts/check-drift.test.ts`

### Task 2: Add plugin.json spec-schema validation (TEST-02, part 1)

**Goal:** Add a `describe("Plugin Manifest Spec-Conformance (TEST-02)")` block that validates `plugin.json` against the Claude Code plugin specification using the Zod schema from `src/compilers/plugin.types.ts`.

**File:** `scripts/plugin-spec-structure.test.ts` (modify -- append to the file created in Task 1)

**Steps:**

1. Add imports for the Zod schemas:

   ```typescript
   import {
     pluginManifestSchema,
     KEBAB_CASE_REGEX,
   } from "../src/compilers/plugin.types";
   ```

2. Add the describe block `"Plugin Manifest Spec-Conformance (TEST-02)"`:

   a. **Test: plugin.json is valid JSON.** Read `dist/plugin/.claude-plugin/plugin.json`, parse with `JSON.parse()`, and assert no error.

   b. **Test: plugin.json passes Zod schema validation.** Use `pluginManifestSchema.safeParse()` on the parsed JSON and assert `result.success === true`. Log `result.error` if it fails for debugging.

   c. **Test: plugin.json name is kebab-case.** Extract `name` from the parsed JSON and assert `KEBAB_CASE_REGEX.test(name)` is true.

   d. **Test: plugin.json has no component arrays.** Assert that the parsed JSON does NOT have `commands`, `agents`, `skills`, or `hooks` properties. Claude Code auto-discovers these from directories; having them in the manifest is a spec violation that could cause confusion.

   ```typescript
   const FORBIDDEN_COMPONENT_KEYS = ["commands", "agents", "skills", "hooks"];
   for (const key of FORBIDDEN_COMPONENT_KEYS) {
     expect(manifest).not.toHaveProperty(key);
   }
   ```

   e. **Test: plugin.json contains only spec-valid fields.** Assert that every key in the parsed JSON is in the set: `name`, `version`, `description`, `author`, `homepage`, `repository`, `license`, `keywords`. This catches undocumented fields that might cause issues.

   ```typescript
   const VALID_FIELDS = new Set([
     "name",
     "version",
     "description",
     "author",
     "homepage",
     "repository",
     "license",
     "keywords",
   ]);
   for (const key of Object.keys(manifest)) {
     expect(VALID_FIELDS.has(key)).toBe(true);
   }
   ```

**Verification:**

- [ ] 5 new tests pass in the "Plugin Manifest" block
- [ ] Zod schema validation catches any spec-violating fields
- [ ] Forbidden component arrays are explicitly checked
- [ ] `bun test scripts/plugin-spec-structure.test.ts` passes

### Task 3: Add marketplace.json spec-schema validation (TEST-02, part 2)

**Goal:** Add marketplace.json validation within the same TEST-02 describe block, validating the marketplace manifest's required fields and structure per the Claude Code marketplace specification.

**File:** `scripts/plugin-spec-structure.test.ts` (modify -- add tests to the existing TEST-02 describe block or add a nested describe)

**Steps:**

1. Add a nested `describe("marketplace.json")` within the TEST-02 block:

   a. **Test: marketplace.json is valid JSON.** Read and parse `dist/plugin/.claude-plugin/marketplace.json`.

   b. **Test: marketplace.json has required root fields.** Assert `name` (string, required) and `owner` (object with `name` string, required) exist.

   c. **Test: marketplace.json has plugins array.** Assert `plugins` is an array with at least one entry.

   d. **Test: each plugin entry has required fields.** For each entry in `plugins[]`, assert `name` (string) and `source` (string) exist. These are the minimum required fields per the marketplace spec.

   e. **Test: plugin entry name is kebab-case.** For each plugin entry, assert the `name` passes `KEBAB_CASE_REGEX`.

   f. **Test: marketplace.json has no $schema violation.** If `$schema` is present, assert it is a string (informational -- the URL may not resolve, but the field must be a string if present).

**Verification:**

- [ ] 6 new marketplace.json tests pass
- [ ] Required fields (name, owner, plugins) are validated
- [ ] Plugin entries validated for name + source minimum
- [ ] `bun test scripts/plugin-spec-structure.test.ts` passes with all tests green
