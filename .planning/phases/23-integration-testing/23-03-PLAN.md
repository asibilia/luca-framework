# Plan 23-03: End-to-End Static Spec-Conformance Suite

## Objective

Create a comprehensive end-to-end test that simulates what Claude Code would validate when loading a plugin -- without requiring the Claude Code CLI to be installed. This test acts as the "load test" by combining all spec-conformance checks from 23-01 and 23-02 into a single cohesive validation that exercises the complete plugin from directory root to individual file content. It covers TEST-05 (end-to-end plugin loading test) using static analysis as the mechanism (per the Phase 23 context decision for static validation only).

The test lives in a new file `scripts/plugin-spec-e2e.test.ts` and provides the final integration guarantee: if this test passes, the plugin is structurally ready for Claude Code to load.

## Context

@scripts/plugin-spec-structure.test.ts -- Created in Plan 23-01. Contains plugin directory structure validation (TEST-01) and manifest schema validation (TEST-02). This file validates individual structural aspects in isolation.

@scripts/plugin-spec-hooks-format.test.ts -- Created in Plan 23-02. Contains hook event type validation, path resolution (TEST-03), and compilation format checks for SKILL.md/agent.md frontmatter (TEST-04). This file validates individual format aspects in isolation.

@dist/plugin/ -- The complete plugin output directory. This is the directory under test. At the time this plan executes, Plans 23-01 and 23-02 have already validated individual aspects. This plan validates the plugin **as a whole**.

@dist/plugin/.claude-plugin/plugin.json -- Plugin manifest. Already schema-validated by 23-01, but this plan cross-references its `name` field against directory contents.

@dist/plugin/.claude-plugin/marketplace.json -- Marketplace manifest. Already validated by 23-01, but this plan verifies `plugins[0].name` matches `plugin.json` `name`.

@dist/plugin/hooks/hooks.json -- Hooks config. Already event-type-validated by 23-02, but this plan verifies hooks reference real scripts and that the overall hook count is sensible.

@src/compilers/plugin.types.ts -- Zod schemas for validation. Exports `pluginManifestSchema`, `KEBAB_CASE_REGEX`.

@scripts/build-shared.ts -- Shared build utilities. Exports `PLUGIN_EXCLUDED_HOOKS`, `SKILL_CATEGORIES`.

@23-CONTEXT.md -- Phase 23 context. Decision 2 (static validation only) is the governing principle for this plan. Decision 1 (spec-first) means we validate what Claude Code expects, not what our compiler produces.

@scripts/check-drift.test.ts -- Existing drift tests. **DO NOT duplicate.** The E2E test should compose higher-level assertions, not repeat individual file checks.

## Tasks

### Task 1: Create the E2E test file with plugin discovery simulation

**Goal:** Create `scripts/plugin-spec-e2e.test.ts` with a top-level `describe("End-to-End Plugin Spec-Conformance (TEST-05)")` that simulates Claude Code's plugin discovery process: find `plugin.json`, read it, discover components from directories.

**File:** `scripts/plugin-spec-e2e.test.ts` (create)

**Steps:**

1. Create the file with imports:

   ```typescript
   import { describe, test, expect } from "bun:test";
   import { readdirSync, readFileSync, existsSync, statSync } from "node:fs";
   import path from "path";

   import {
     pluginManifestSchema,
     KEBAB_CASE_REGEX,
   } from "../src/compilers/plugin.types";
   ```

2. Define the plugin root and a helper to extract frontmatter:

   ```typescript
   const PLUGIN_ROOT = path.resolve(import.meta.dir, "..", "dist", "plugin");

   /**
    * Extract YAML frontmatter from a markdown file.
    * Returns null if no frontmatter found, otherwise a key-value map.
    */
   function extractFrontmatter(content: string): Record<string, string> | null {
     const match = content.match(/^---\n([\s\S]*?)\n---/);
     if (!match) return null;

     const fields: Record<string, string> = {};
     for (const line of match[1].split("\n")) {
       const colonIndex = line.indexOf(":");
       if (colonIndex > 0) {
         const key = line.slice(0, colonIndex).trim();
         const value = line.slice(colonIndex + 1).trim();
         fields[key] = value;
       }
     }
     return fields;
   }
   ```

3. Add the outer describe block and the first test group -- `"Plugin Discovery"`:

   a. **Test: plugin root is a valid directory.** Assert `PLUGIN_ROOT` exists and is a directory.

   b. **Test: .claude-plugin/plugin.json is discoverable and valid.** Read and parse `plugin.json`, validate with `pluginManifestSchema.safeParse()`, and assert success. This is the first thing Claude Code does when loading a plugin.

   c. **Test: plugin name from manifest matches directory convention.** Assert `plugin.json` `name` is a non-empty kebab-case string. While Claude Code does not enforce a directory name match, the name must be valid for registration.

**Verification:**

- [ ] `scripts/plugin-spec-e2e.test.ts` exists
- [ ] 3 discovery tests pass
- [ ] Plugin manifest is loaded and validated as the entry point

### Task 2: Add component auto-discovery simulation

**Goal:** Add tests that simulate Claude Code's component auto-discovery -- walking the `skills/`, `agents/`, and `hooks/` directories and validating that every discovered component meets spec requirements.

**File:** `scripts/plugin-spec-e2e.test.ts` (modify -- add new describe group)

**Steps:**

1. Add a `describe("Component Auto-Discovery")` block:

   a. **Test: all discovered skills are loadable.** Walk `dist/plugin/skills/`, for each subdirectory:
   - Assert `SKILL.md` exists
   - Read it and assert it starts with `---\n` (has frontmatter)
   - Extract frontmatter and assert `description` is present and non-empty
   - Assert the subdirectory name is kebab-case (KEBAB_CASE_REGEX)

   Collect any failures into an array and assert it is empty at the end. Report all failures at once for debugging.

   b. **Test: all discovered agents are loadable.** Walk `dist/plugin/agents/`, for each `.md` file:
   - Assert the file has non-trivial content (> 50 bytes)
   - Assert the file contains at least one markdown heading (`# ` or `## `)
   - Assert the filename (minus extension) is kebab-case

   Collect failures and assert empty.

   c. **Test: hooks configuration is loadable.** Parse `dist/plugin/hooks/hooks.json` and assert:
   - It is valid JSON
   - All top-level keys are recognized Claude Code event types
   - Every hook entry has `type`, `command`, and `timeout` fields
   - Every `command` path uses `${CLAUDE_PLUGIN_ROOT}/scripts/` prefix
   - Every referenced script file exists in `dist/plugin/scripts/`

   This is a comprehensive single-test that validates the entire hooks system end-to-end.

**Verification:**

- [ ] Failures are reported with specific file paths for debugging

### Task 4: Add the comprehensive "load readiness" summary test

**Goal:** Add a final summary test that compiles all validation results into a single pass/fail determination with a structured report. This is the definitive "would Claude Code load this?" test.

**File:** `scripts/plugin-spec-e2e.test.ts` (modify -- add final describe group)

**Steps:**

1. Add a `describe("Plugin Load Readiness")` block:

   a. **Test: plugin passes all spec-conformance checks.** This is a comprehensive test that runs ALL checks in sequence and reports a structured summary:

   ```typescript
   test("plugin is ready for Claude Code loading", () => {
     const issues: string[] = [];

     // 1. Manifest check
     const pluginJsonPath = path.join(
       PLUGIN_ROOT,
       ".claude-plugin",
       "plugin.json",
     );
     if (!existsSync(pluginJsonPath)) {
       issues.push("FATAL: .claude-plugin/plugin.json not found");
     } else {
       const manifest = JSON.parse(readFileSync(pluginJsonPath, "utf8"));
       const result = pluginManifestSchema.safeParse(manifest);
       if (!result.success) {
         issues.push(`plugin.json schema invalid: ${result.error.message}`);
       }
       // No component arrays
       for (const key of ["agents", "skills", "hooks"]) {
         if (key in manifest) {
           issues.push(`plugin.json has forbidden component array: ${key}`);
         }
       }
     }

     // 2. Required directories
     for (const dir of [
       ".claude-plugin",
       "agents",
       "skills",
       "hooks",
       "scripts",
     ]) {
       if (!existsSync(path.join(PLUGIN_ROOT, dir))) {
         issues.push(`Missing required directory: ${dir}/`);
       }
     }

     // 3. Skills have frontmatter with description
     const skillsDir = path.join(PLUGIN_ROOT, "skills");
     if (existsSync(skillsDir)) {
       for (const dir of readdirSync(skillsDir)) {
         const skillMd = path.join(skillsDir, dir, "SKILL.md");
         if (!existsSync(skillMd)) {
           issues.push(`Skill ${dir}/ missing SKILL.md`);
         } else {
           const content = readFileSync(skillMd, "utf8");
           const fm = extractFrontmatter(content);
           if (!fm || !fm.description) {
             issues.push(
               `Skill ${dir}/SKILL.md missing description frontmatter`,
             );
           }
         }
       }
     }

     // 4. Hooks use valid events and ${CLAUDE_PLUGIN_ROOT}
     const hooksJsonPath = path.join(PLUGIN_ROOT, "hooks", "hooks.json");
     if (existsSync(hooksJsonPath)) {
       const hooksJson = JSON.parse(readFileSync(hooksJsonPath, "utf8"));
       const validEvents = new Set([
         "PreToolUse",
         "PostToolUse",
         "Notification",
         "Stop",
         "SubagentTool",
         "SessionStart",
         "SessionEnd",
       ]);
       for (const event of Object.keys(hooksJson)) {
         if (!validEvents.has(event)) {
           issues.push(`Invalid hook event type: ${event}`);
         }
       }
     }

     // Report
     if (issues.length > 0) {
       console.error(
         "Plugin load readiness check FAILED:\n" +
           issues.map((i) => `  - ${i}`).join("\n"),
       );
     }
     expect(issues).toEqual([]);
   });
   ```

   b. **Test: plugin component summary matches expectations.** Count the actual number of skills, agents, and hook scripts, and assert each count is > 0. Log the counts for informational purposes:

   ```typescript
   test("plugin component summary", () => {
     const skillCount = readdirSync(path.join(PLUGIN_ROOT, "skills")).length;
     const agentCount = readdirSync(path.join(PLUGIN_ROOT, "agents")).filter(
       (f) => f.endsWith(".md"),
     ).length;
     const scriptCount = readdirSync(path.join(PLUGIN_ROOT, "scripts")).filter(
       (f) => f.endsWith(".sh"),
     ).length;

     console.log(
       `Plugin summary: ${skillCount} skills, ${agentCount} agents, ` +
         `${scriptCount} hook scripts`,
     );

     expect(skillCount).toBeGreaterThan(0);
     expect(agentCount).toBeGreaterThan(0);
     expect(scriptCount).toBeGreaterThan(0);
   });
   ```

**Verification:**

- [ ] 2 load readiness tests pass
- [ ] Comprehensive summary test validates all spec aspects in one pass
- [ ] Issues are reported with descriptive messages
- [ ] Component counts logged for visibility
