## Tasks

### Task 1: Add `sanitizeJsonParse()` to validation-utils.ts

**Goal**: Provide a safe JSON parse wrapper that strips prototype pollution keys (`__proto__`, `constructor`, `prototype`) recursively from parsed objects.

**File:** `src/shared/validation-utils.ts`

**Changes:**
1. Add a private `stripPrototypeKeys(obj: unknown): unknown` helper function that:
   - Returns primitives and null as-is
   - Recursively processes arrays via `.map()`
   - For objects, creates a new clean object skipping keys named `__proto__`, `constructor`, or `prototype`
   - Recursively processes remaining values

2. Add exported `sanitizeJsonParse(json: string): unknown` function that:
   - Calls `JSON.parse(json)` to get the raw value
   - Passes result through `stripPrototypeKeys()`
   - Returns the sanitized value

3. Add exported `safeSanitizeJsonParse(json: string): { success: boolean; data?: unknown; error?: string }` following the existing safe-validation pattern (try/catch wrapper).

**Pattern to follow** (from existing code):
```typescript
// Strict variant (throws)
export function sanitizeJsonParse(json: string): unknown {
  const parsed = JSON.parse(json);
  return stripPrototypeKeys(parsed);
}

// Safe variant (returns result)
export function safeSanitizeJsonParse(json: string): { success: boolean; data?: unknown; error?: string } {
  try {
    const data = sanitizeJsonParse(json);
    return { success: true, data };
  } catch (error) {
    return { success: false, error: error instanceof Error ? error.message : 'JSON parse failed' };
  }
}
```

### Task 2: Validate environment variable formats in Jira adapter `checkConfig()`

**Goal**: Upgrade `checkConfig()` in `jira-adapter.ts` from presence-only validation to format validation using Zod schemas. Validate that `JIRA_BASE_URL` is a valid HTTPS URL, `JIRA_API_TOKEN` is non-empty, and `JIRA_USER_EMAIL` has email shape.

**File:** `packages/luca-framework/src/adapters/jira-adapter.ts`

**Changes:**
1. Add `import { z } from 'zod'` at the top of the file (Zod is already a project dependency).

2. Add Zod schemas as module-level constants:
   ```typescript
   const jiraBaseUrlSchema = z.string().url().refine(
     (url) => url.startsWith('https://'),
     { message: 'JIRA_BASE_URL must use HTTPS' }
   );
   const jiraEmailSchema = z.string().email({ message: 'JIRA_USER_EMAIL must be a valid email' });
   const jiraTokenSchema = z.string().min(1, { message: 'JIRA_API_TOKEN must not be empty' });
   ```

3. Update `checkConfig()` to validate format after presence check:
   - After confirming all three values exist, validate each through its Zod schema
   - Collect validation errors into the `missing` array (rename to `errors` for clarity)
   - Return concatenated error messages if any fail
   - Keep the existing presence-check logic for the "Missing: X, Y, Z" message

**Important**: The existing test `'returns error listing only missing config vars'` passes a config with `baseUrl: 'https://test.atlassian.net'` which is a valid HTTPS URL, so it will still pass. However, any test that uses a non-HTTPS baseUrl or invalid email will now get a format validation error. Review all test fixtures in `jira-adapter.test.ts` to confirm they use valid values -- the existing `validConfig` already uses `https://` and `test@example.com`, so no test updates are needed for this task.
