# Plan 06-02: Shell Command Hardening

## Frontmatter
- **ID**: 06-02
- **Title**: Shell Command Hardening
- **Wave**: 2
- **Depends on**: none

## Objective

Eliminate shell injection vectors across the codebase by adding branch name validation to the GitHub adapter, inserting `--` end-of-options markers before user-provided arguments in execa calls, sanitizing subprocess error output, and migrating build scripts from `child_process.exec`/`execSync` to `Bun.spawn()`/`Bun.spawnSync()`. This wave can run in parallel with Wave 1.

## Context

- `packages/luca-framework/src/adapters/github-adapter.ts` -- uses `execa` array form (safe), but no input validation on `branchName` or `issueNumber`, no `--` markers, raw error propagation in `parseGhError()`
- `scripts/compile-all-to-cursor.ts` -- imports `child_process.exec`, generated build script uses `execSync` with shell
- `scripts/prepare-compilation.ts` -- imports `child_process.exec`, calls `execAsync('bun run build')` with shell, generates bash script
- `__tests__/packages/luca-framework/src/adapters/github-adapter.test.ts` -- existing tests for GitHub adapter (execa mocked)
- `06-RESEARCH.md` -- Wave 2 implementation notes, `validateBranchName()` spec, `Bun.spawn()` API reference

## Tasks

### Task 1: Add `validateBranchName()` utility

**Goal**: Create a reusable branch name validation function that rejects dangerous git branch name patterns.

**File:** `packages/luca-framework/src/adapters/github-adapter.ts` (add as module-level function)

**Changes:**
Add a `validateBranchName()` function before `createGitHubAdapter()`:

```typescript
/**
 * Validate a git branch name, rejecting patterns that are dangerous for
 * shell execution or git operations.
 */
function validateBranchName(name: string): { valid: boolean; error?: string } {
  if (!name || name.trim() === '') return { valid: false, error: 'Branch name is required' };
  if (name.startsWith('-')) return { valid: false, error: 'Branch name cannot start with -' };
  if (name.includes('..')) return { valid: false, error: 'Branch name cannot contain ..' };
  if (/[\s\0~^:\\]/.test(name)) return { valid: false, error: 'Branch name contains invalid characters' };
  if (name.endsWith('.lock')) return { valid: false, error: 'Branch name cannot end with .lock' };
  if (name.endsWith('.')) return { valid: false, error: 'Branch name cannot end with .' };
  if (name.includes('//')) return { valid: false, error: 'Branch name cannot contain //' };
  return { valid: true };
}
```

Also add an `issueNumber` validation function:

```typescript
function validateIssueNumber(num: string): { valid: boolean; error?: string } {
  if (!/^\d+$/.test(num)) return { valid: false, error: 'Issue number must be numeric' };
  return { valid: true };
}
```

**Verification:** New tests pass (see Task 4)

### Task 3: Migrate build scripts from child_process to Bun.spawn

**Goal**: Replace `child_process.exec`/`execSync` with `Bun.spawnSync()` in build scripts, eliminating the shell interpretation layer.

**File 1:** `scripts/compile-all-to-cursor.ts`

3. In `createBuildSystem()`, the generated build script string (lines 112-208) contains `execSync('npx tsc ...')`. Replace the generated script content to use `Bun.spawnSync()` instead:

### Task 6: Add Zod response schema for GitHub adapter

**Goal**: Add runtime validation of the `gh issue view` JSON output, replacing the TypeScript-only cast. This mirrors the Jira response schema approach in Plan 06-03.

**File:** `packages/luca-framework/src/adapters/github-adapter.ts`

2. Add a Zod schema for the GitHub issue response (~line 184 where `JSON.parse(stdout)` is called):
   ```typescript
   const githubIssueResponseSchema = z.object({
     number: z.number(),
     title: z.string(),
     body: z.string().nullable(),
     state: z.string(),
     labels: z.array(z.object({ name: z.string() })).optional(),
     assignees: z.array(z.object({ login: z.string() })).optional(),
     url: z.string().optional(),
   });
   ```

3. Replace the TypeScript cast with Zod validation:
   ```typescript
   // Before:

   // After:
   const rawData = JSON.parse(stdout);
   const parseResult = githubIssueResponseSchema.safeParse(rawData);
   if (!parseResult.success) {
     return { success: false, error: `GitHub API returned unexpected response format: ${parseResult.error.message}` };
   }
   const data = parseResult.data;
   ```

4. Derive the TypeScript type from the schema:
   ```typescript

   ```
