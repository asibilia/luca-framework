# Phase 126 Plan 03: Empty States

## Task Objective

Add missing empty states to observer dashboard pages to provide clear feedback when no data is available, following existing component patterns.

## Context

- Existing EmptyState component at `components/shared/empty-state.tsx`
- Current pattern: dashed border, monospace text, helpful message
- 3 specific gaps identified:
  1. Workflow page: no empty state for transition log (entries.length === 0)
  2. Harness page: null check missing before HarnessSummaryBanner
  3. Cost page: loading state needs standardization

## Files to Update

1. `app/workflow/page.tsx` - Add empty state for transition log
2. `app/harness/page.tsx` - Add null check for result before HarnessSummaryBanner
3. `app/cost/page.tsx` - Standardize loading state

## Execution Steps

1. **Workflow page - Transition Log:**
   - Check `entries.length === 0` condition
   - Render EmptyState component with message like "No transitions recorded yet"
   - Include helpful context about when transitions appear

2. **Harness page - Result Null Check:**
   - Add null check before rendering HarnessSummaryBanner
   - Show EmptyState if result is null/undefined
   - Message: "No harness results available" with context

3. **Cost page - Standardize Loading:**
   - Ensure consistent loading state using LoadingSkeleton from Wave 1
   - Add EmptyState for "no cost data available" scenario
   - Align with patterns from other pages

4. Follow existing EmptyState pattern:
   - Dashed border styling
   - Monospace text for technical feel
   - Helpful, actionable messages

## Verification

- [ ] Workflow page displays empty state when `entries.length === 0`
- [ ] Harness page handles null result gracefully with empty state
- [ ] Cost page has consistent loading and empty states
- [ ] All empty states use dashed border, monospace text styling
- [ ] Messages are helpful and actionable
- [ ] TypeScript compiles without errors
- [ ] Test suite passes

## Success Criteria

- Users receive clear feedback when no data is available
- No broken UI states from null/empty data
- Consistent empty state experience across observer dashboard
- Alignment with existing design patterns
