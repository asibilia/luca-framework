# Plan 41-01: Source File Rewire + Build Propagation

## Objective

Update all source files in the Luca framework to reference the new `packages/luca-state/src/bridge.ts` path instead of the old `src/state-machine/bridge.ts` path. Then run the build system to propagate these changes to all generated output directories (`.claude/`, `.cursor/`). This is the core rewire that shifts the framework's internal plumbing from the monolithic `src/state-machine/` directory to the extracted `packages/luca-state/` package.

This plan addresses **PKG-08**: Internal framework updated to consume from `packages/luca-state/` instead of `src/state-machine/`.

## Context

Read these files to understand the architecture:

- @packages/luca-state/package.json -- The extracted package with `bin.luca-state` entry and workspace configuration. Already contains the full bridge implementation.
- @packages/luca-state/src/bridge.ts -- The canonical bridge implementation that all CLI calls should now target.
- @packages/luca-state/bin/luca-state.js -- The bin entry point that routes subcommands to bridge handlers.
- @src/hooks/scripts/session-start.sh -- Example source hook referencing `src/state-machine/bridge.ts` via `STATE_MACHINE_BRIDGE` variable. Pattern: `STATE_MACHINE_BRIDGE="src/state-machine/bridge.ts"` then `bun run $STATE_MACHINE_BRIDGE <cmd>`.
- @src/skills/general/autopilot.skill.ts -- Example source skill with multiple inline `bun run src/state-machine/bridge.ts <cmd>` references in prompt template strings.
- @src/agents/general/lu-cognition.agent.ts -- Example source agent with bridge CLI references in agent prompt templates.
- @src/rules/general/state-machine-bridge.rule.ts -- The rule that documents bridge CLI usage for skills and agents. Must be updated to document the new path.
- @scripts/build-all.ts -- The build system that compiles source files to `.claude/` and `.cursor/` output directories.
- @scripts/check-drift.ts -- The drift checker that validates generated outputs match source files.

### Critical Architecture Note

This project has a **build system**: Source files in `src/` compile to `.claude/` and `.cursor/`. You MUST update SOURCE files only. Run `bun run build:all` to propagate changes. Do NOT manually edit generated output files in `.claude/` or `.cursor/`.

### CLI Path Change

| Before                                      | After                                             |
| ------------------------------------------- | ------------------------------------------------- |
| `bun run src/state-machine/bridge.ts <cmd>` | `bun run packages/luca-state/src/bridge.ts <cmd>` |

The replacement is a direct string substitution in all embedded CLI call strings. The bridge API (subcommands, flags, JSON output format) is identical -- only the file path changes.

## Tasks

### T1: Rewire source hook scripts

**Goal:** Update the 3 source hook scripts that are the canonical source for all hook outputs. These scripts define a `STATE_MACHINE_BRIDGE` variable and use it throughout. The change is a single variable assignment update per file.

**Files:**

- `src/hooks/scripts/session-start.sh`
- `src/hooks/scripts/snapshot-sync.sh`
- `src/hooks/scripts/pre-commit-gate.sh`

**Implementation:**

In each file, find the line:

```bash
STATE_MACHINE_BRIDGE="src/state-machine/bridge.ts"
```

Replace with:

```bash
STATE_MACHINE_BRIDGE="packages/luca-state/src/bridge.ts"
```

Also search for any direct inline references to `src/state-machine/bridge.ts` that do not use the variable and update those too.

**Verification:**

- `grep -r 'src/state-machine/bridge.ts' src/hooks/scripts/` returns zero matches
- `grep -r 'packages/luca-state/src/bridge.ts' src/hooks/scripts/` returns matches in all 3 files
- Each script is still syntactically valid bash (`bash -n <file>` exits 0)
