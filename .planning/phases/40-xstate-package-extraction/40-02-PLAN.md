# 40-02: Persistence Layer + CLI Entry Points

## Objective

Extract the persistence layer (`persistence.ts`), snapshot generator (`snapshot.ts`), and both CLI interfaces (`bridge.ts`, `cli.ts`) into the `packages/luca-state/` package. Create the `bin/luca-state.js` CLI binary entry point. After this plan, the package is functionally complete -- all 12 source files from `src/state-machine/` will be present in the package, and the `luca-state` CLI binary will be operational.

## Context

This plan handles the 4 files that have external imports beyond the intra-module scope:

| File             | External Import                            | Resolution                                                 |
| ---------------- | ------------------------------------------ | ---------------------------------------------------------- |
| `persistence.ts` | `../shared/types` (Result type)            | Import from local `./types` (Result was added in 40-01-T3) |
| `snapshot.ts`    | `../shared/cli-utils.ts` (escapeRegex)     | Import from local `./utils/cli-utils`                      |
| `bridge.ts`      | `../shared/cli-utils.ts` (getArg, hasFlag) | Import from local `./utils/cli-utils`                      |
| `cli.ts`         | `../shared/cli-utils.ts` (getArg, hasFlag) | Import from local `./utils/cli-utils`                      |

All 4 files also use Bun-specific APIs (`Bun.file`, `Bun.write`, `Bun.argv`, `import.meta.main`). This is acceptable per project conventions (Bun is the required runtime).

### Task 5: Create bin/luca-state.js CLI Entry Point (40-02-T5)

**Goal:** Create the thin CLI binary wrapper that the `bin` field in `package.json` points to. This delegates to the bridge module which has the high-level commands used by skills and agents.

**Files:**

- `packages/luca-state/bin/luca-state.js`

**Implementation:**

```javascript
#!/usr/bin/env bun
/**
 * CLI entry point for the luca-state package.
 *
 * Delegates to the bridge module for all subcommands.
 * This is the binary registered in package.json as "luca-state".
 *
 * Usage:
 *   luca-state read-status
 *   luca-state read-complexity
 *   luca-state transition --event=START
 *   luca-state ensure-init
 */
import "../src/bridge.ts";
```

Note: The entry point imports the source `.ts` file directly (not the built dist), since Bun natively handles TypeScript. For the `unbuild` distribution, the build.config.ts already includes `src/bridge` as an entry point, so the built version would use `../dist/bridge.mjs`.

For dual-mode support (development vs installed), use a conditional:

```javascript
#!/usr/bin/env bun
// In development: import source directly
// After build: import from dist
try {
  await import("../src/bridge.ts");
} catch {
  await import("../dist/bridge.mjs");
}
```

Or keep it simple with the source import since Bun is the required runtime.

### Task 7: Verify CLI Commands and Persistence Round-Trip (40-02-T7)

**Goal:** Verify that the package is functionally operational by testing CLI commands and persistence.

**Verification steps:**

1. **TypeScript compilation:** Run `bunx --bun tsc --noEmit --project packages/luca-state/tsconfig.json` and confirm zero errors.

2. **Zero framework imports:** Run `grep -r 'from "\.\.\/' packages/luca-state/src/ | grep -v node_modules` and confirm all results are intra-module (no `../shared/`, `../complexity/`, `../iteration/` etc.).

3. **CLI bridge responds:**

```bash
bun run packages/luca-state/src/bridge.ts read-status
# Expected: JSON with { initialized: false, state: "idle", ... }

bun run packages/luca-state/src/bridge.ts read-complexity
# Expected: JSON with { complexity: "TRIVIAL", initialized: false }
```

4. **Persistence round-trip:**

```bash
# Initialize
bun run packages/luca-state/src/bridge.ts ensure-init
# Expected: JSON with { initialized: true, ... }

# Read status
bun run packages/luca-state/src/bridge.ts read-status
# Expected: JSON with { initialized: true, state: "idle", ... }

# Send event
bun run packages/luca-state/src/bridge.ts transition --event=START
# Expected: Transition record JSON with previous_state: "idle", current_state: "preflight"

# Cleanup: remove test state file
rm -f .planning/state.json
```

5. **CLI binary entry point:**

```bash
bun run packages/luca-state/bin/luca-state.js read-status
# Expected: Same output as bridge.ts direct execution
```

6. **Low-level CLI responds:**

```bash
bun run packages/luca-state/src/cli.ts status
# Expected: JSON with { initialized: false } (if no state file)
```
