# 40-03: Test Suite Migration + Package Documentation

## Objective

Migrate all 11 test files from `src/state-machine/__tests__/` into the `packages/luca-state/` package, update their imports and path references, ensure they all pass, and create package documentation. After this plan, the `luca-state` package is complete with full test coverage and ready for use.

## Context

### Test File Classification

The 11 test files fall into three categories based on the import changes required:

**Category A: Framework import changes needed (3 files)**

These files import `DEFAULT_COMPLEXITY_MATRIX` from `../../complexity` which must change to the local `../defaults`:

| Test File             | Framework Import          | New Import           |
| --------------------- | ------------------------- | -------------------- |
| `machine.test.ts`     | `from "../../complexity"` | `from "../defaults"` |
| `guards.test.ts`      | `from "../../complexity"` | `from "../defaults"` |
| `persistence.test.ts` | `from "../../complexity"` | `from "../defaults"` |

**Category B: CLI path references in shell commands (4 files)**

These files use `Bun.$` to invoke CLI scripts via shell. The path strings must be updated:

| Test File                    | Old Path                      | New Path                            |
| ---------------------------- | ----------------------------- | ----------------------------------- |
| `bridge.test.ts`             | `src/state-machine/bridge.ts` | `packages/luca-state/src/bridge.ts` |
| `bridge-integration.test.ts` | `src/state-machine/bridge.ts` | `packages/luca-state/src/bridge.ts` |
| `cli.test.ts`                | `src/state-machine/cli.ts`    | `packages/luca-state/src/cli.ts`    |
| `hook-integration.test.ts`   | `src/state-machine/bridge.ts` | `packages/luca-state/src/bridge.ts` |

Also: `hook-integration.test.ts` references `src/hooks/scripts/snapshot-sync.sh` which is a framework hook script. This test may need to be adapted or marked as integration-only since it tests framework hook behavior, not the state machine package itself.

**Category C: No import changes needed (4 files)**

These files only use intra-module imports (`../types`, `../events`, `../snapshot`, `../actors/phase-actor`) which remain valid in the new package structure:

- `events.test.ts`
- `context.test.ts`
- `snapshot.test.ts`
- `phase-actor.test.ts`

### .planning/ Directory Setup/Teardown

Several test files (persistence, bridge, bridge-integration, cli, hook-integration) create and delete files in `.planning/` during test runs. Since tests run from the monorepo root (not from the package directory), the `.planning/` directory references remain valid and do not need to change. The setup/teardown helpers (`ensurePlanningDir`, `cleanupStateFile`, `cleanupStateFiles`) work with relative paths that resolve correctly when `bun test` runs from root.

// NEW:

**bridge-integration.test.ts:**

```typescript

// NEW:

```

**cli.test.ts:**

```typescript
// OLD:
const CLI = "src/state-machine/cli.ts";

// NEW:
const CLI = "packages/luca-state/src/cli.ts";
```

**hook-integration.test.ts:**

This file references both the bridge script and the snapshot-sync hook script:

```typescript
// OLD:
const BRIDGE = "src/state-machine/bridge.ts";
const SNAPSHOT_SYNC_SCRIPT = "src/hooks/scripts/snapshot-sync.sh";

// NEW:
const BRIDGE = "packages/luca-state/src/bridge.ts";
const SNAPSHOT_SYNC_SCRIPT = "src/hooks/scripts/snapshot-sync.sh";
```

The `SNAPSHOT_SYNC_SCRIPT` path remains unchanged because `snapshot-sync.sh` is a framework hook that lives in `src/hooks/`, not in the luca-state package. If the hook script is not accessible from the package test context, this test should be moved to a separate integration test file at the framework level, or the specific tests that depend on `snapshot-sync.sh` should be skipped with a `test.skip()` and a comment explaining why.

**Decision:** If `hook-integration.test.ts` tests are primarily about the framework's hook integration (not the state machine package), consider:

1. **Option A (preferred):** Keep the file but skip tests that depend on `src/hooks/scripts/snapshot-sync.sh` with a comment noting these are framework-level integration tests.
2. **Option B:** Remove `hook-integration.test.ts` from the package entirely and keep it only in the framework test suite.

Evaluate during Task 4 based on which tests pass and which fail.

### Task 4: Run Tests and Fix Failures (40-03-T4)

**Goal:** Execute the full test suite and resolve any remaining issues.

**Implementation:**

1. Run the full suite from the monorepo root:

```bash

```

2. Expected issues to fix:

   a. **Import path resolution:** If any test still references `../../complexity` or `../shared/`, update the import.

   b. **`.planning/` directory:** Tests that create/delete state files need the `.planning/` directory to exist. The `ensurePlanningDir()` helpers already handle this with `mkdirSync(".planning", { recursive: true })`.

   c. **Shell command paths:** If `Bun.$` commands fail because the path is wrong, verify the BRIDGE/CLI constants point to the correct package paths.

   d. **hook-integration.test.ts:** If tests fail because `src/hooks/scripts/snapshot-sync.sh` is not found or not relevant, skip those specific tests with `test.skip()`.

   e. **State file conflicts:** If tests interfere with each other (both framework and package tests writing to `.planning/state.json`), ensure the package tests run in isolation. The existing `beforeEach`/`afterEach` cleanup should handle this.

3. Iterate until all tests pass (or all non-skipped tests pass).
