**After (full replacement):**
```markdown
# Luca Framework — Coding Standards

> **Version:** 1.0.0
> **Last Updated:** 2026-02-10
> **Status:** Active

This document defines coding standards for the Luca Framework codebase.

## Runtime

- **Bun** is the primary runtime. Use Bun APIs over Node.js equivalents per `CLAUDE.md`.
- Use `bun test` for testing, `bun run` for scripts.

## Language

- **TypeScript** in strict mode.
- Prefer `unknown` over `any`. Use Zod for runtime validation.
- Use discriminated unions for result types (e.g., `{ success: true; data: T } | { success: false; error: string }`).

## File Organization

- `kebab-case` for file names.
- `camelCase` for variables and functions.
- `PascalCase` for classes and types.
- Colocate tests in `__tests__/` directories adjacent to source.

## Error Handling

- All user-facing errors must be actionable: state what failed, why, and what to do.
- Use `consola` logger (via `logger` utility) for all CLI output.
- Extract `.message` from Error instances; never interpolate raw error objects.

## Dependencies

- Minimize production dependencies.
- Prefer native Node.js/Bun APIs over third-party packages.
- Pin dependency versions.

## Templates

- Use EJS for template processing.
- JSON templates must escape backslashes in regex patterns (use `ticketPatternJson` helper).

## Testing

- Use `bun:test` (`describe`, `test`, `expect`).
- Mock external dependencies, not internal modules.
- Test error paths, not just happy paths.

## Reference

For Bun-specific conventions, see the `CLAUDE.md` file in the repository root.
```
