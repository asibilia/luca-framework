## Tasks

### Task 1: Fix regex escaping bug in config.json template
**Goal**: Ensure the config.json template produces valid JSON when `ticketPattern` contains backslash characters (e.g., `\d+`). Currently, EJS outputs raw `\d` into JSON, which is an invalid escape sequence that causes `JSON.parse()` to throw.
**Findings**: DX-009 (HIGH) — known UAT finding from Phase 8
**File:** `packages/luca-framework/src/utils/branding.ts` (context creation) and `packages/luca-framework/templates/base/.planning/config.json` (template)

**Root Cause:** `createBrandingContext()` passes `ticketPattern` as-is. When EJS interpolates `<%= branding.ticketPattern %>` into a JSON string value, backslashes are not doubled for JSON compatibility. `'[A-Z]+-\\d+'` in TypeScript is the string `[A-Z]+-\d+`, and `\d` is invalid JSON escape.

**Approach:** Add a `ticketPatternJson` helper to the branding context that properly escapes backslashes for JSON embedding. Update the template to use it.

**Changes in `packages/luca-framework/src/utils/branding.ts`** (inside `createBrandingContext`, around line 157-165):

**Before:**
```typescript
export function createBrandingContext(branding: BrandingConfig) {
  return {
    branding: {
      ...branding,
      // Computed helpers for templates
      commandSlash: `/${branding.commandPrefix}`,
      nameUppercase: branding.frameworkName.toUpperCase(),
      nameLowercase: branding.frameworkName.toLowerCase(),
    },
  };
}
```

**After:**
```typescript
export function createBrandingContext(branding: BrandingConfig) {
  return {
    branding: {
      ...branding,
      // Computed helpers for templates
      commandSlash: `/${branding.commandPrefix}`,
      nameUppercase: branding.frameworkName.toUpperCase(),
      nameLowercase: branding.frameworkName.toLowerCase(),
      // JSON-safe version of ticketPattern (backslashes doubled for JSON string embedding)
      ticketPatternJson: branding.ticketPattern.replace(/\\/g, '\\\\'),
    },
  };
}
```

**Changes in `packages/luca-framework/templates/base/.planning/config.json`** (line 8):

**Before:**
```json
    "ticketPattern": "<%= branding.ticketPattern %>",
```

**After:**
```json
    "ticketPattern": "<%= branding.ticketPatternJson %>",
```

**Verification:**
- Run `luca init` with default branding, then inspect `.planning/config.json` — the ticketPattern value should be `"[A-Z]+-\\d+"` (valid JSON with doubled backslash)
- Run `JSON.parse()` on the generated config.json — no SyntaxError
- Run `luca doctor` after init — config validation passes
- `bun test` passes

### Task 2: Fix wizard cancel handler to use process.exit(0)
**Goal**: Replace the `return null` in the `p.group()` `onCancel` handler with `process.exit(0)` for consistent cancel behavior. The current approach returns `null` from the callback, but `p.group()` may still return a partial result, making the null check on line 90 unreliable.
**Findings**: DX-012 (HIGH)
**File:** `packages/luca-framework/src/utils/wizard.ts`
**Changes:**
1. Change the `onCancel` handler to use `process.exit(0)` (consistent with the `p.isCancel()` handlers on lines 110-112 and 125-127).

**Before (lines 82-88):**
```typescript
  {
    onCancel: () => {
      p.cancel('Setup cancelled.');
      return null;
    },
  }
```

**After:**
```typescript
  {
    onCancel: () => {
      p.cancel('Setup cancelled.');
      process.exit(0);
    },
  }
```

Also remove the now-unnecessary null check on line 90:

**Before (line 90):**
```typescript
if (!branding) return null;
```

**After:**
```typescript
// onCancel calls process.exit(0), so if we reach here branding is always defined.
// Keep a defensive check for type safety.
if (!branding) return null;
```

Note: Keep the defensive null check for type safety since `p.group()` returns a potentially partial type, but it should never be reached in practice.

**Verification:**
- Pressing Ctrl+C or Escape during the branding group cleanly exits with code 0
- No partial state leaks after cancel
- `bun test` passes

### Task 3: Validate `--stack` argument against known templates
**Goal**: When `--stack` is passed via CLI args, validate it against known template values before proceeding. Invalid values currently silently fall through with no feedback.
**Findings**: DX-013 (MEDIUM)
**File:** `packages/luca-framework/src/utils/wizard.ts`
**Changes:**
1. Add validation of `args.stack` in `createConfigFromArgs()` (around line 193).
2. Define a `VALID_STACKS` constant.

**Before (lines 188-195):**
```typescript
return {
  branding: mergeBranding({
    frameworkName: args.name,
    commandPrefix: args.prefix,
  }),
  stack: args.stack || 'custom',
  workTracker: (args.tracker as 'jira' | 'github' | 'none') || 'none',
};
```

**After:**
```typescript
const VALID_STACKS = ['react-ts', 'custom'];
if (args.stack && !VALID_STACKS.includes(args.stack)) {
  throw new Error(
    `Invalid stack "${args.stack}". Valid options: ${VALID_STACKS.join(', ')}`
  );
}

const VALID_TRACKERS = ['jira', 'github', 'none'];
if (args.tracker && !VALID_TRACKERS.includes(args.tracker)) {
  throw new Error(
    `Invalid tracker "${args.tracker}". Valid options: ${VALID_TRACKERS.join(', ')}`
  );
}

return {
  branding: mergeBranding({
    frameworkName: args.name,
    commandPrefix: args.prefix,
  }),
  stack: args.stack || 'custom',
  workTracker: (args.tracker as 'jira' | 'github' | 'none') || 'none',
};
```

Note: This also addresses DX-014 (MEDIUM) — tracker validation — in the same change.

**Verification:**
- `npx luca init --stack=vue-ts` throws a clear error listing valid options
- `npx luca init --tracker=linear` throws a clear error listing valid options
- `npx luca init --stack=react-ts --tracker=github` works normally
- `npx luca init` (no args) works normally
- `bun test` passes
