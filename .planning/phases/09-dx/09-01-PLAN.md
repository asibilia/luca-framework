# Plan 09-01: CLI Error Messages — Actionable Errors for init, update, and version-check

## Frontmatter
- **ID**: 09-01
- **Title**: CLI Error Messages — Actionable Errors for init, update, and version-check
- **Wave**: 1
- **Depends on**: none

## Objective
Make all error messages in the `init` and `update` commands actionable. Users currently see raw errors, missing context, or misleading recovery guidance. After this plan, every error message tells the user (1) what failed, (2) why, and (3) what to do next.

## Context
- `packages/luca-framework/src/commands/init.ts` — Init command with non-actionable errors (lines 52-54, 66, 91)
- `packages/luca-framework/src/commands/update.ts` — Update command with non-actionable errors (lines 354-356, 477-486)
- `packages/luca-framework/src/utils/version-check.ts` — Update notifier with misleading message (line 55)
- `packages/luca-framework/src/utils/files.ts` — `generateFiles()` returns `{ success: false, error: string }` (line 231) — the error string is available but not used by init.ts

## Tasks

### Task 1: Fix non-actionable "Installation failed" error in init
**Goal**: When `generateFiles()` fails, show the actual error message from the result and provide actionable recovery guidance.
**Findings**: DX-001 (HIGH)
**File:** `packages/luca-framework/src/commands/init.ts`
**Changes:**
1. Extract the error from the `result` object (it's available as `result.error` when `result.success === false`).
2. Log the specific error and provide recovery guidance.

**Before (lines 88-93):**
```typescript
  const result = await generateFiles({ config });

  if (!result.success) {
    logger.error('Installation failed');
    process.exit(1);
  }
```

**After:**
```typescript
  const result = await generateFiles({ config });

  if (!result.success) {
    logger.error(`Installation failed: ${result.error}`);
    logger.info('Suggestions:');
    logger.info('  1. Check file permissions and available disk space');
    logger.info('  2. Run `npx luca doctor` to check your environment');
    logger.info('  3. If the problem persists, file a bug report');
    process.exit(1);
  }
```

**Verification:**
- The error from `generateFiles()` is propagated to the user
- Recovery guidance is shown after every installation failure
- `bun test` passes

### Task 2: Fix raw exception in config file error message
**Goal**: When `loadConfigFromFile()` throws, format the error properly instead of interpolating the raw object, and add guidance on expected config format.
**Findings**: DX-002 (MEDIUM)
**File:** `packages/luca-framework/src/commands/init.ts`
**Changes:**
1. Extract `.message` from Error instances to avoid `[object Object]` in output.
2. Add a hint about expected config file format.

**Before (lines 63-68):**
```typescript
    try {
      config = await loadConfigFromFile(args.config);
    } catch (error) {
      logger.error(`Failed to read config file: ${error}`);
      process.exit(1);
    }
```

**After:**
```typescript
    try {
      config = await loadConfigFromFile(args.config);
    } catch (error) {
      const message = error instanceof Error ? error.message : String(error);
      logger.error(`Failed to read config file: ${message}`);
      logger.info('Expected JSON format: { "branding": { "frameworkName": "..." }, "stack": "custom", "workTracker": "none" }');
      logger.info('See `npx luca init --help` for non-interactive configuration options.');
      process.exit(1);
    }
```

**Verification:**
- Error message shows the actual error string, never `[object Object]`
- User sees expected config file format
- `bun test` passes

### Task 3: Add `--force` flag hint to existing project error
**Goal**: When Luca is already installed, mention that re-initialization requires deleting `.planning/` first, since `--force` does not exist.
**Findings**: DX-003 (LOW) — bundled with init error improvements
**File:** `packages/luca-framework/src/commands/init.ts`
**Changes:**
1. Improve the existing project error message with clearer guidance.

**Before (lines 51-55):**
```typescript
  if (context.hasLuca) {
    logger.error('Luca is already installed in this project.');
    logger.info('Run `npx luca update` to update to the latest version.');
    process.exit(1);
  }
```

**After:**
```typescript

    logger.error('Luca is already installed in this project.');
    logger.info('To update: run `npx luca update`');

    process.exit(1);
  }
```

**Verification:**
- User sees two clear options: update or reinitialize
- No reference to non-existent `--force` flag
- `bun test` passes

### Task 5: Add recovery guidance to update failure error
**Goal**: When an update fails and backup is restored, provide actionable next steps instead of just showing the error.
**Findings**: DX-005 (MEDIUM)
**File:** `packages/luca-framework/src/commands/update.ts`
**Changes:**
1. Add recovery guidance after the backup restoration message.

**Before (lines 477-487):**
```typescript
  } catch (error) {
    spinner.stop('Update failed');

    // Restore backup on failure
    logger.error('Update failed, restoring backup...');
    await restoreBackup(backupDir, cwd);

    const errorMessage = error instanceof Error ? error.message : 'Unknown error';
    logger.error(`Error: ${errorMessage}`);
    process.exit(1);
  }
```

**After:**
```typescript
  } catch (error) {
    spinner.stop('Update failed');

    // Restore backup on failure
    logger.error('Update failed, restoring backup...');
    await restoreBackup(backupDir, cwd);

    const errorMessage = error instanceof Error ? error.message : 'Unknown error';
    logger.error(`Error: ${errorMessage}`);
    logger.info('');
    logger.info('Your project has been restored to its previous state.');
    logger.info('Next steps:');
    logger.info('  1. Run `npx luca doctor` to diagnose environment issues');
    logger.info('  2. Try again with `npx luca update --dry-run` to preview changes');
    logger.info('  3. If the problem persists, file a bug report');
    process.exit(1);
  }
```

**Verification:**
- Backup restoration is confirmed to the user
- Three actionable next steps are provided
- `bun test` passes

### Task 6: Fix misleading update notification message
**Goal**: The version check notifier says "Run: npx luca update" but `luca update` updates project files, not the npm package. Fix the message to tell users how to actually update the CLI.
**Findings**: DX-008 (LOW) — bundled with version-check file
**File:** `packages/luca-framework/src/utils/version-check.ts`
**Changes:**
1. Update the notification message to instruct users on how to update the npm package.

**Before (line 54-57):**
```typescript
  notifier.notify({
    message: `Update available: {currentVersion} → {latestVersion}\nRun: npx luca update`,
    defer: false,
  });
```

**After:**
```typescript
  notifier.notify({
    message: `Update available: {currentVersion} → {latestVersion}\nRun: bun add luca-framework@latest  # or: npm install luca-framework@latest\nThen: npx luca update  # to update project files`,
    defer: false,
  });
```

**Verification:**
- Users see correct instructions for updating both the package and project files
- The distinction between CLI update and project file update is clear
- `bun test` passes
