### 3. Create search-result-card component

**Type:** auto
**TDD:** false
**Depends on:** 2

Create `packages/luca-observer/components/semantic-search/search-result-card.tsx`.

**Props:**

```typescript
interface SearchResultCardProps {
  result: SemanticSearchResult;
  onExplain: (engramId: string) => void;
  explainLoading: boolean;
}
```

**Layout:**

Each result card shows:

- **Concept** (bold, `text-sm font-semibold`)
- **Content preview** (2-3 lines, truncated with `line-clamp-3` if longer)
- **Relevance score** as a horizontal bar + numeric value (e.g., "0.85")
- **Memory type badge** (if present) -- small pill with `bg-muted text-xs rounded-full px-2 py-0.5`
- **Tags** as small pills below content (if present) -- `bg-accent/10 text-accent text-xs rounded-full px-2 py-0.5`
- **Action links row:**
  - "Explain" button -- toggles the inline ScoreBreakdown section. Shows "Loading..." while explain is fetching. Only shown after clicking; re-clicking collapses it.
  - "Traverse" link -- `<a href={/knowledge-graph?entity=${encodeURIComponent(result.concept)}}>Traverse</a>` (navigates to knowledge graph page with entity context)
  - "View" link -- `<a href={/memory?entity=${encodeURIComponent(result.concept)}}>View</a>` (navigates to memory page filtered by entity)

**Explain expand/collapse:**

- Track `expanded` boolean in local state
- When "Explain" is clicked and `result.explain` is undefined, call `onExplain(result.id)` and show loading
- When `result.explain` is populated, render `<ScoreBreakdown explain={result.explain} />`
- Re-clicking "Explain" collapses the section (no re-fetch needed since explain data is cached in the result)

**Styling:**

- Card uses `border border-border rounded-lg p-4 bg-card` pattern
- `font-mono` for score values
- Action links use `text-xs text-accent hover:underline` pattern

### 5. Create Semantic Search page

**Type:** auto
**TDD:** false
**Depends on:** 1, 4

Create `packages/luca-observer/app/semantic-search/page.tsx`.

Follow the decisions page pattern exactly:

```typescript
"use client";

import { PageContainer } from "~/components/layout/page-container";
import { ErrorBoundary } from "~/components/shared/error-boundary";
import { LoadingSkeleton } from "~/components/shared/loading-skeleton";
import { EmptyState } from "~/components/shared/empty-state";
import { useSemanticSearch } from "~/hooks/use-semantic-search";
import { SearchBar } from "~/components/semantic-search/search-bar";
import { SearchResults } from "~/components/semantic-search/search-results";
import { relativeTime } from "~/lib/format";
```

**Page structure:**

```
PageContainer
  title="Semantic Search"
  subtitle="MuninnDB Knowledge Search"
  actions={lastUpdated + Refresh button}

  SearchBar (always visible at top)

  {loading ? LoadingSkeleton :
   !configured ? EmptyState("MuninnDB not configured") :
   error ? error display :
   results.length === 0 && lastQuery === null ? EmptyState("Enter a search query to explore your knowledge base") :
   SearchResults}
```

**Key behaviors:**

- SearchBar is always visible (even during loading or error states)
- Before any search: show a friendly prompt EmptyState
- During search: show LoadingSkeleton (variant="card", 3 instances)
- After search with results: show SearchResults
- After search with no results: SearchResults handles empty state internally
- Not configured: show EmptyState with MuninnDB message
- Track `explainLoadingId` in page state to pass down to SearchResults
