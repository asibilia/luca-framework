# Phase 175 Plan 2: Core Library Functions

## Objective

Implement the three core library modules -- backup manager, settings merger, and deploy manifest writer -- as modular, reusable functions in `packages/luca-framework/src/utils/`. These functions encapsulate all merge, backup, and manifest logic so that both `deploy-global.ts` and `luca init` can consume them via simple function calls.

### 1. Implement backup manager

**Type:** auto
**TDD:** false
**Depends on:** none (uses Plan 1 schemas only for types, not runtime)

Create `packages/luca-framework/src/utils/backup-manager.ts` with these functions. Use `Bun.file()` and `Bun.write()` for file I/O (matching the `manifest.ts` pattern), not `node:fs`.

**`backupSettings(settingsPath: string, backupsDir: string): Promise<string | null>`**

- If settings file exists (check via `Bun.file(settingsPath).exists()`), read its content and write to `{backupsDir}/settings-{timestamp}.json` where timestamp is ISO format with colons/periods replaced by dashes
- Create backups directory if it does not exist (`mkdir` via Bun shell or `node:fs.mkdirSync` for directory creation)
- Return the backup file path, or null if no settings file existed
- Use `Bun.file()` for reading and `Bun.write()` for writing (consistent with manifest.ts)

**`rotateBackups(backupsDir: string, maxKeep: number): void`**

- Read the backups directory
- Filter for files matching `settings-*.json`
- Sort by filename lexically using `lodash/orderBy` (ISO timestamps sort correctly)
- Delete the oldest files exceeding `maxKeep`
- Best-effort cleanup: swallow individual file deletion errors

**`listBackups(backupsDir: string): string[]`**

- Return sorted list of backup file paths (newest first)
- Used by `luca reinit` and status display

Include comprehensive JSDoc documentation on all exports.

### 2. Implement settings merger (three-tier merge)

**Type:** auto
**TDD:** false
**Depends on:** none (uses Plan 1 schemas for types)

Create `packages/luca-framework/src/utils/settings-merger.ts` with the core merge algorithm.

**`buildSlotKey(event: string, matcher?: string): string`**

- Returns `"{Event}:{matcher}"` or `"{Event}:"` for no-matcher hooks
- Used to create composite keys for hook identification

**`parseExistingHooks(settings: Record<string, unknown>): Map<string, HookSlot[]>`**

- Parse the `hooks` section of an existing settings.json
- Returns a map of event name to array of slot groups (each group has optional matcher + hooks array)

**`extractLucaScriptName(command: string): string | null`**

- Extract the base script filename from a command string
- Handles quoted paths: `"\"~/.claude/hooks/session-start.sh\""` -> `"session-start.sh"`
- Handles `$CLAUDE_PROJECT_DIR` paths: `"$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh"` -> `"session-start.sh"`
- Handles plain paths: `"~/.claude/hooks/session-start.sh"` -> `"session-start.sh"`
- Returns null if no `.sh` extension found

**`isLucaHook(command: string, knownScripts: Set<string>): boolean`**

- Returns true if `extractLucaScriptName(command)` is in `knownScripts`
- `knownScripts` should be derived from the canonical hook registry

**`computeMergeActions(existingSettings: Record<string, unknown>, proposedHooks: Record<string, unknown>, knownLucaScripts: Set<string>): MergeAction[]`**

- For each proposed hook slot (event + matcher):
  - If slot does not exist in existing settings: `auto-merge`
  - If slot exists and contains a hook with identical command: `auto-skip`
  - If slot exists with a different non-Luca hook at the same command pattern: `conflict`
  - If slot exists with only Luca hooks (identified by `isLucaHook`): auto-replace (silent update)
- Uses `cloneDeep` from lodash before any mutation

**`applyMerge(existingSettings: Record<string, unknown>, proposedHooks: Record<string, unknown>, resolutions: Map<string, ConflictResolution>, knownLucaScripts: Set<string>): Record<string, unknown>`**

- Applies the merge based on computed actions and user resolutions
- Returns the new settings object (deep-cloned, never mutates input)
- For each event:
  - Preserves all non-Luca hooks untouched
  - Replaces/adds Luca hooks per the resolution
  - For "keep-both" resolution, adds both hooks to the slot

**`getKnownLucaScripts(): Set<string>`**

- Returns a Set of all Luca hook script filenames (`.sh` extension) derived from the canonical hook registry
- Single source of truth, no hardcoded list

Include comprehensive JSDoc documentation.

**Files to create:**

- `packages/luca-framework/src/utils/settings-merger.ts`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- `getKnownLucaScripts()` returns 14 entries (matches canonical hook registry count)
- No hardcoded script name lists (unlike current deploy-global.ts which has `lucaScripts` array repeated 3 times)

### 3. Implement deploy manifest writer

**Type:** auto
**TDD:** false
**Depends on:** none (uses Plan 1 DeployManifestSchema)

Create `packages/luca-framework/src/utils/deploy-manifest-writer.ts` with functions for managing the deploy manifest at `~/.luca/manifests/deploy-manifest.json`.

**`createDeployManifest(options: { sourcePath: string, deployedFiles: Array<{ relativePath: string, absolutePath: string, sourceType: string }>, settingsBackupPath?: string }): Promise<DeployManifest>`**

- Hash each deployed file using `hashFile()` from `manifest.ts`
- Build the `artifacts` record with relative paths as keys
- Include `package_version` from `LUCA_VERSION`
- Include `deployed_at` as ISO timestamp
- Set `mode` to `"copy"`

**`writeDeployManifest(manifest: DeployManifest, manifestDir: string): Promise<void>`**

- Write to `{manifestDir}/deploy-manifest.json`
- Create directory if needed
- Pretty-print JSON

**`readDeployManifest(manifestDir: string): Promise<DeployManifest | null>`**

- Read and parse the deploy manifest
- Return null if not found or unparseable
- Validate with `DeployManifestSchema.safeParse()`

Include JSDoc documentation.
