# Phase 180 Plan 2: Consumer Updates & Shared Deploy Module

## Objective

Create the shared deploy-helpers module and update consumers that depend on Wave 1 extractions. This wave creates `deploy-helpers.ts` (shared by init.ts and deploy-global.ts), delegates vault-setup's health check to the existing `checkMuninndbService()`, and extends `getLucaHomePaths()` with a `claudeGlobal` field to eliminate direct `homedir()` calls.

### 1. Extract shared deploy utilities: copyDirForDeploy, rewriteHookPaths (DRY-4)

**Type:** auto
**TDD:** false
**Depends on:** none (Wave 1 only needs to be complete for consumer updates; the shared module itself has no Wave 1 dependencies)

Two functions are duplicated between `init.ts` and `deploy-global.ts`:

- `copyDirForDeploy` / `copyDirRecursive`: recursive directory copy with SEC-008 symlink traversal guard
- `rewriteWrapperPathsForInit` / `rewriteWrapperPaths`: regex path rewriting for shell wrappers

Extract both into a new shared file.

**What to do:**

1. Read `packages/luca-framework/src/commands/init.ts` to find `copyDirForDeploy` (~lines 346-401) and `rewriteWrapperPathsForInit` (~lines 409-421).

   - `copyDirForDeploy` accepts `deployedFiles` as an explicit parameter (matching init.ts's design, not deploy-global.ts's module-level array).
   - `rewriteHookPaths` does NOT include a `dryRun` guard -- callers handle that.
   - Preserve the SEC-008 symlink traversal guard (lstatSync + realpathSync check).
   - Import `DeploySourceType` from `./deploy-manifest.schemas`.
   - Use `node:fs` for `lstatSync`, `mkdirSync`, `readdirSync`, `readFileSync`, `realpathSync`, `writeFileSync` (Bun migration of this file is not in scope for this phase).
4. Update `init.ts`:
   - Remove inline `copyDirForDeploy` function.
   - Remove inline `rewriteWrapperPathsForInit` function.
   - Add import: `import { copyDirForDeploy, rewriteHookPaths } from "../utils/deploy-helpers"`.
   - Update call sites to use the imported functions. Verify the parameter signatures match.
5. Update `scripts/deploy-global.ts`:
   - Remove inline `copyDirRecursive` function.
   - Remove inline `rewriteWrapperPaths` function.
   - Add import: `import { copyDirForDeploy, rewriteHookPaths } from "../packages/luca-framework/src/utils/deploy-helpers"`.
   - Update `deployDir()` to pass `deployedFiles` array and `GLOBAL_DIR` to the shared function.
   - **CRITICAL:** Keep the `dryRun` guard at the call site for `rewriteHookPaths`: `if (!dryRun) rewriteHookPaths(targetPath, projectRoot);`. The shared function must NOT include dryRun logic.
6. Run `bunx --bun tsc --noEmit` to verify.

### 3. Replace direct homedir() calls with getLucaHomePaths() (ANTI-PATTERN-1)

**Type:** auto
**TDD:** false
**Depends on:** none

Multiple files construct `~/.claude/` paths via `homedir()` + `join(home, ".claude")` instead of using the centralized `getLucaHomePaths()` utility. However, `getLucaHomePaths()` currently only covers `~/.luca/` paths -- it does not include `~/.claude/`.

**CRITICAL DISTINCTION (from research):** Most `homedir()` calls construct `~/.claude/` (Claude Code global config dir), NOT `~/.luca/` (Luca home dir). The fix requires extending `getLucaHomePaths()`.

**What to do:**

1. Read `packages/luca-framework/src/utils/luca-home.ts` to understand `LucaHomePathsSchema` and `getLucaHomePaths()`.
2. Extend `LucaHomePathsSchema` to include a `claudeGlobal` field:

```typescript
// Add to LucaHomePathsSchema
claudeGlobal: z.string(), // ~/.claude/ -- Claude Code global config directory
```

3. Update `getLucaHomePaths()` to include: `claudeGlobal: join(home, ".claude")`.
4. Update consumers that construct `~/.claude/` manually:
   - `init.ts` (~line 92): Replace `const home = homedir(); const globalDir = join(home, ".claude");` with `const { claudeGlobal: globalDir } = getLucaHomePaths();`.
   - `reinit.ts` (~line 58): Same replacement pattern.
   - `global-update.ts` (~lines 164, 337): Same replacement pattern. May already import `getLucaHomePaths` -- extend usage.
   - `doctor/checks/global-artifacts.ts` (~line 59): Same replacement pattern.
5. Remove now-unused `import { homedir } from "node:os"` from files that no longer need it directly (verify no other homedir() calls remain in the file first).
6. Run `bunx --bun tsc --noEmit` to verify.

**NOTE:** `luca-home.ts` itself and `runtime-context.ts` use `homedir()` correctly as the source of truth -- do NOT change those.

**Files to create/edit:**

- `packages/luca-framework/src/utils/luca-home.ts` (extend schema and function)
- `packages/luca-framework/src/commands/init.ts` (replace homedir pattern)
- `packages/luca-framework/src/commands/reinit.ts` (replace homedir pattern)
- `packages/luca-framework/src/utils/global-update.ts` (replace homedir pattern)
- `packages/luca-framework/src/utils/doctor/checks/global-artifacts.ts` (replace homedir pattern)

**Verification:**

- `bunx --bun tsc --noEmit` passes
- `LucaHomePathsSchema` includes `claudeGlobal` field
- No direct `join(home, ".claude")` or `join(homedir(), ".claude")` patterns remain in the updated files
- `luca-home.ts` and `runtime-context.ts` are the only files that still call `homedir()` directly
