## Tasks

### 1. Migrate init.ts from node:fs to Bun.file/Bun.write (DRY-5)

**Type:** auto
**TDD:** false
**Depends on:** Plan 2 Task 1 (deploy-helpers extraction must be complete so we know which fs calls remain in init.ts)

Per CONTEXT.md, only `readFileSync` and `writeFileSync` calls are migrated. All other fs operations (`existsSync`, `mkdirSync`, `chmodSync`, `readdirSync`, `lstatSync`, `realpathSync`) stay as-is because Bun has no cleaner alternatives for them.

**CRITICAL (from PREMORTEM Risk 2):** Every `Bun.file()` and `Bun.write()` call MUST have `await`. The containing function (`runDeployStep`) is already `async`, so this is safe. Verify no synchronous callers exist.

**What to do:**

1. Read `packages/luca-framework/src/commands/init.ts` to identify all remaining `readFileSync` and `writeFileSync` calls (after Plan 2 moved some into `deploy-helpers.ts`).
2. Based on the research, the following calls should remain in init.ts and need migration:
   - Agent deploy loop (~line 140): `writeFileSync(target, readFileSync(...))` -> `await Bun.write(target, await Bun.file(sourcePath).arrayBuffer())`
   - Hook deploy loop (~line 196): Same pattern
   - Settings read (~line 277): `readFileSync(settingsPath, "utf-8")` -> `await Bun.file(settingsPath).text()`
   - Settings write (~line 323): `writeFileSync(settingsPath, ...)` -> `await Bun.write(settingsPath, ...)`
3. For each migration:
   - Add `await` to every `Bun.file()` and `Bun.write()` call
   - Use `.arrayBuffer()` for binary file copies, `.text()` for text reads
   - Preserve error handling (try/catch blocks around I/O)
4. Update the import statement: remove `readFileSync` and `writeFileSync` from the `node:fs` import. Keep all other fs imports.
5. Run `bunx --bun tsc --noEmit` to verify -- TypeScript will catch any missing `await` (Promise<string> where string is expected).

**NOTE:** `deploy-helpers.ts` (created in Plan 2) still uses `node:fs` -- that file's Bun migration is out of scope for this phase.

**Files to create/edit:**

- `packages/luca-framework/src/commands/init.ts` (replace readFileSync/writeFileSync with Bun APIs)

**Verification:**

- `bunx --bun tsc --noEmit` passes
- No `readFileSync` or `writeFileSync` calls remain in `init.ts`
- All `Bun.file()` and `Bun.write()` calls have `await`
- The `node:fs` import still includes `existsSync`, `mkdirSync`, `chmodSync`, `readdirSync` etc.
- No `Promise<string>` type errors (would indicate missing `await`)

### 2. Emit build-time hook registry JSON artifact (COMPLEXITY-1)

**Type:** auto
**TDD:** false
**Depends on:** none

Create a build-time generator that reads the canonical hook registry and emits `dist/hooks-registry.json`. Update `init.ts` to try reading this artifact with a fallback to the existing hardcoded map.

**CRITICAL CONSTRAINT (from MEMORY.md):** `bun run build:all` CRASHES Claude Code sessions. The generator code will be written and wired into the build pipeline, but it CANNOT be executed during this session. The user must run `bun run build:all` manually afterward. init.ts must retain its fallback map.

**What to do:**

1. Read `src/hooks/__helpers/hook-registry.ts` to understand `canonicalHookRegistry` and `resolveCanonicalRegistry()`.
2. Read `scripts/build-all.ts` to find where to add the new generator step.
3. Create `scripts/generate-hooks-registry-json.ts`:

````typescript
/**
 * Generate dist/hooks-registry.json from the canonical hook registry.
 *
 * Called during `bun run build:all` to produce a runtime-readable artifact
 * that init.ts can consume instead of maintaining a hardcoded hook map.
 *
 * @example
 * ```bash
 * bun scripts/generate-hooks-registry-json.ts
 * ```
 */
````

- Import `resolveCanonicalRegistry` from `../src/hooks/__helpers/hook-registry`.
- Call `resolveCanonicalRegistry()` to get the full registry map.
- Serialize to JSON with the shape: `Record<string, { event, tool_filter?, command_filter?, timeout, async, status_message }>`.
- Write to `dist/hooks-registry.json` using `Bun.write()`.
- Log the number of hooks written.

4. Wire into `scripts/build-all.ts`: Add a call or import after the existing `generateAllOutputs()` step. This can be a simple dynamic import or direct function call.

5. Update `init.ts` to try reading the JSON artifact:
   - Rename the existing hardcoded `scriptEventMap` to `FALLBACK_HOOK_MAP` and add a sync version comment.
   - Before the hook deploy section, try loading `dist/hooks-registry.json`:

```typescript
const registryPath = join(sourceRoot, "dist/hooks-registry.json");
let hookRegistry: Record<string, unknown> | null = null;
try {
  const file = Bun.file(registryPath);
  if (await file.exists()) {
    hookRegistry = sanitizeJsonParse(await file.text());
  }
} catch {
  /* fallback to hardcoded map */
}
if (!hookRegistry) {
  hookRegistry = FALLBACK_HOOK_MAP;
}
```

6. Run `bunx --bun tsc --noEmit` to verify the generator and init.ts changes compile.

**Files to create/edit:**

- `scripts/generate-hooks-registry-json.ts` (new file)
- `scripts/build-all.ts` (add generator step)
- `packages/luca-framework/src/commands/init.ts` (add JSON artifact reader with fallback)

**Verification:**

### 3. Refactor executeGlobalUpdate() into composable helpers (COMPLEXITY-2)

**Type:** auto
**TDD:** false
**Depends on:** Plan 1 Task 2 (resolveMonorepoRoot), Plan 2 Task 1 (deploy-helpers)

`executeGlobalUpdate()` in `global-update.ts` is ~190 lines of orchestration logic. After Wave 1 extracted `resolveMonorepoRoot()` and `inferSourceType()`, the function can be further decomposed.

**What to do:**

1. Read `packages/luca-framework/src/utils/global-update.ts` to understand the current structure of `executeGlobalUpdate()` (~lines 244-433).
2. Identify the deploy loop (~lines 337-405) which iterates over diff entries and applies file operations. Extract this into a helper:

```typescript
/**
 * Apply artifact updates from a computed diff to the global directory.
 *
 * Processes added, modified, and removed files based on the diff result.
 * Returns the list of deployed file metadata for manifest generation.
 *
 * @param diff - The computed artifact diff from computeGlobalDiff().
 * @param sourceClaudeDir - Source .claude directory path.
 * @param globalDir - Target ~/.claude directory path.
 * @param options - Execution options (dryRun, verbose).
 * @returns Array of deployed file metadata.
 */
function applyArtifactUpdates(
  diff: GlobalDiffResult,
  sourceClaudeDir: string,
  globalDir: string,
  options: { dryRun: boolean; verbose: boolean },
): Array<{
  relativePath: string;
  absolutePath: string;
  sourceType: DeploySourceType;
}>;
```

3. The summary display section (~lines 283-333) can remain inline since it is UI logic tightly coupled to the orchestrator.
4. After extraction, `executeGlobalUpdate()` should be a thin orchestrator:

   - Read manifest

   - Display summary
   - Call `applyArtifactUpdates()`

   - Write manifest
5. The helper can be defined in the same file (private helper, not exported) or in `deploy-helpers.ts` if it is generic enough. Prefer same-file since it is tightly coupled to the global-update workflow.
6. Run `bunx --bun tsc --noEmit` to verify.
