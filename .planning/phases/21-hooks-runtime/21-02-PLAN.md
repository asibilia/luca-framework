# Plan 21-02: Hook Script Runtime Detection

## Objective

Add runtime detection to `pre-commit-gate.sh`, `post-edit-format.sh`, and `post-edit-typecheck.sh` so they use the correct commands based on whether `bun` or `node` is the configured runtime. Currently these scripts hardcode `bun test`, `bunx --bun tsc`, and `bunx --bun prettier`. Plugin users who do not have bun installed will get silent failures. After this plan, each script reads a `runtime` field from `.planning/config.json` (written by SessionStart in Plan 21-03) and falls back to direct `command -v` detection if the config is unavailable.

## Context

@src/hooks/scripts/pre-commit-gate.sh — Pre-commit quality gate. Hardcodes `bun test` (line 53) and `bunx --bun tsc --noEmit` (line 73). Needs runtime-conditional commands.

@src/hooks/scripts/post-edit-format.sh — Auto-formatter hook. Hardcodes `bunx --bun prettier --write` at lines 45, 49, 53, 57, 61, 65. Needs runtime-conditional formatter command.

@src/hooks/scripts/post-edit-typecheck.sh — Async type-checker hook. Hardcodes `bunx --bun tsc --noEmit` at line 56. Needs runtime-conditional tsc command.

@.planning/phases/21-hooks-runtime/21-RESEARCH.md — Section 5 (Pre-Commit Gate Runtime Detection) details the runtime detection approach, command mapping table, and fallback chain.

## Tasks

### Task 1: Define the `read_runtime()` shell function pattern

**Goal:** Establish a standard `read_runtime()` function that all three hook scripts will use. This function reads the runtime from `.planning/config.json`, falling back to direct `command -v` detection.

**Design:**

The function must handle four scenarios:

1. config.json exists with `"runtime"` field -- use that value
2. config.json exists but no `"runtime"` field -- fall back to detection
3. config.json does not exist -- fall back to detection
4. Neither bun nor node available -- default to `bun` (existing behavior, will fail with clear error)

The function uses `bun -e` to read JSON if bun is available, or `node -e` if only node is available. If neither is available, defaults to `bun`.

```bash
# Detect runtime: reads .planning/config.json, falls back to command detection
read_runtime() {
  local config="${CLAUDE_PROJECT_DIR:-.}/.planning/config.json"

  # Try reading from config.json
  if [ -f "$config" ]; then
    local rt=""
    set +e
    if command -v bun &>/dev/null; then
      rt=$(HOOK_CFG="$config" bun -e "
        try {
          const cfg = JSON.parse(await Bun.file(process.env.HOOK_CFG).text());
          process.stdout.write(cfg.runtime || '');
        } catch { /* empty */ }
      " 2>/dev/null)
    elif command -v node &>/dev/null; then
      rt=$(HOOK_CFG="$config" node -e "
        try {
          const fs = require('fs');
          const cfg = JSON.parse(fs.readFileSync(process.env.HOOK_CFG, 'utf-8'));
          process.stdout.write(cfg.runtime || '');
        } catch { /* empty */ }
      " 2>/dev/null)
    fi
    set -e

    if [ -n "$rt" ]; then
      echo "$rt"
      return
    fi
  fi

  # Fallback: detect from PATH
  if command -v bun &>/dev/null; then
    echo "bun"
  elif command -v node &>/dev/null; then
    echo "node"
  else
    echo "bun"
  fi
}
```

**Command mapping:**

| Check      | bun runtime                   | node runtime           |
| ---------- | ----------------------------- | ---------------------- |
| Tests      | `bun test`                    | `npm test`             |
| TypeScript | `bunx --bun tsc --noEmit`     | `npx tsc --noEmit`     |
| Formatter  | `bunx --bun prettier --write` | `npx prettier --write` |

**Note:** This function is duplicated in each script rather than sourced from a shared file, because hook scripts must be self-contained (plugin context has no `source` dependencies). The duplication is intentional and acceptable for 3 scripts.

**Verification:**

- [ ] The function pattern is documented and consistent across all three scripts
