## Objective

Implement two high-value hooks that enforce code quality automatically: (1) an async post-edit type-checker that reports TypeScript errors after `.ts`/`.tsx` file edits without blocking, and (2) a synchronous pre-commit quality gate that blocks `git commit` commands when tests fail or type errors exist. Together, these hooks replace advisory "remember to check" skills with deterministic "always check" enforcement.

## Context

- `src/hooks/index.ts` -- Hook registry created in 11-01. Must be extended with two new entries (`post-edit-typecheck` and `pre-commit-gate`).
- `src/hooks/scripts/post-edit-format.sh` -- The formatter hook from 11-01. The type-checker follows a similar pattern (read stdin JSON, extract file path, run tool) but uses `async: true`.
- `.claude/settings.json` -- Generated by the build pipeline (11-01). Will automatically include the new hooks once they are added to the registry.
- `scripts/build-claude.ts` -- Already copies hook scripts and generates settings.json (from 11-01). No changes needed to the build scripts for this plan -- the registry-driven approach handles new hooks automatically.
- `.planning/phases/11-hooks/RESEARCH.md` -- Section 3.3 details the type-checker approach (async, `bunx tsc --noEmit`, file extension filtering). Section 3.4 details the pre-commit gate (match Bash commands, fast exit for non-commit, run checks, deny with `permissionDecision`). Section 4.1-4.2 cover performance risks and mitigations.

### Key API Details (from Research)

**Async hooks**: Set `"async": true` in the hook config. The hook runs in the background; results are delivered on the next turn as a `systemMessage`. This is critical for the type-checker because `tsc --noEmit` takes 2-10 seconds.

**PreToolUse decision control**: For `PreToolUse` events, the hook can block the action by outputting JSON on stdout:
```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Tests failed. Fix the following before committing:\n..."
  }
}
```

**PreToolUse matcher**: The matcher `Bash` matches ALL Bash tool calls. The script must quickly detect non-commit commands and exit 0 (no-op). Only commit-related commands trigger the full quality gate.

**PostToolUse async feedback**: Async PostToolUse hooks deliver feedback via stdout. The format is either a plain string (appended to tool response) or JSON with `systemMessage` field.

## Tasks

### Task 1: Create the post-edit type-checker hook script

**Goal**: Create a shell script that runs `bunx tsc --noEmit` after TypeScript file edits. The script runs asynchronously so it does not block editing. It reports type errors as a system message that Claude receives on the next turn.

**File**: Create `src/hooks/scripts/post-edit-typecheck.sh`

**Details**:

```bash
#!/usr/bin/env bash
# post-edit-typecheck.sh — Async type-check after TypeScript file edits
#
# Hook event: PostToolUse (matcher: Edit|Write)
# Type: Command hook (async: true)
# Timeout: 30 seconds
#
# Reads the edited file path from stdin JSON, checks if it is a TypeScript
# file, and runs tsc --noEmit if so. Since this hook is async, results are
# delivered on the next turn. Non-TypeScript files are skipped immediately.
#
# Uses `bun -e` for JSON parsing instead of jq (project convention).

set -euo pipefail

# Read stdin JSON
INPUT=$(cat)

# Extract file path using bun -e
FILE_PATH=$(printf '%s' "$INPUT" | bun -e "
  const data = JSON.parse(await Bun.stdin.text());
  const filePath = data.tool_input?.file_path;
  if (filePath) process.stdout.write(filePath);
")

# Exit early if no file path
if [ -z "$FILE_PATH" ]; then
  exit 0
fi

# Exit early if file doesn't exist
if [ ! -f "$FILE_PATH" ]; then
  exit 0
fi

# Only type-check TypeScript files
case "$FILE_PATH" in
  *.ts|*.tsx)
    # Continue to type-check
    ;;
  *)
    # Not a TypeScript file — skip
    exit 0
    ;;
esac

# Check if tsconfig.json exists in project root
PROJECT_DIR="${CLAUDE_PROJECT_DIR:-.}"
if [ ! -f "$PROJECT_DIR/tsconfig.json" ]; then
  exit 0
fi

# Run type-checker (project-wide, since types are interconnected)
set +e
TSC_OUTPUT=$(cd "$PROJECT_DIR" && bunx --bun tsc --noEmit 2>&1)
TSC_EXIT=$?
set -e

if [ $TSC_EXIT -ne 0 ] && [ -n "$TSC_OUTPUT" ]; then
  # Truncate output to avoid flooding the context
  TRUNCATED=$(echo "$TSC_OUTPUT" | head -20)
  LINE_COUNT=$(echo "$TSC_OUTPUT" | wc -l | tr -d ' ')

  if [ "$LINE_COUNT" -gt 20 ]; then
    TRUNCATED="$TRUNCATED
... ($LINE_COUNT total lines, showing first 20)"
  fi

  # Output as JSON systemMessage for async delivery
  # Using bun -e to safely JSON-encode the error output
  HOOK_FILE_PATH="$FILE_PATH" printf '%s' "$TRUNCATED" | bun -e "
    const errors = await Bun.stdin.text();
    const filePath = process.env.HOOK_FILE_PATH;
    const msg = {
      systemMessage: 'TypeScript type errors found after editing ' + filePath + ':\n' + errors.trim()
    };
    process.stdout.write(JSON.stringify(msg));
  "
fi

exit 0
```

**Key decisions**:
- **Async execution**: This hook MUST have `async: true` in the registry. Synchronous tsc would block every edit for 2-10 seconds, which is unacceptable UX.
- **Project-wide type-check**: Uses `tsc --noEmit` (not per-file) because TypeScript types are interconnected. A change in one file can cause errors in others.
- **Output truncation**: Limits to 20 lines to avoid flooding context. Shows total line count if truncated.
- **JSON systemMessage**: Async hooks deliver feedback via `systemMessage` in JSON output. Claude sees this on the next turn.
- **tsconfig.json guard**: Skips type-checking if no tsconfig.json exists (project may not use TypeScript compilation).
- **Non-TypeScript skip**: Files not ending in `.ts`/`.tsx` exit immediately (0 overhead).

**Verification**:
- Script is valid bash: `bash -n src/hooks/scripts/post-edit-typecheck.sh`
- Manual test with TypeScript file: `echo '{"tool_input":{"file_path":"src/hooks/index.ts"}}' | bash src/hooks/scripts/post-edit-typecheck.sh`
- Manual test with non-TypeScript file: `echo '{"tool_input":{"file_path":"README.md"}}' | bash src/hooks/scripts/post-edit-typecheck.sh` exits silently

### Task 2: Create the pre-commit quality gate hook script

**Goal**: Create a shell script that intercepts Bash tool calls, detects commit commands, and blocks them when tests fail or type errors exist. Non-commit commands pass through instantly (< 1ms overhead).

**File**: Create `src/hooks/scripts/pre-commit-gate.sh`

**Details**:

```bash
#!/usr/bin/env bash
# pre-commit-gate.sh — Block commits when quality checks fail
#
# Hook event: PreToolUse (matcher: Bash)
# Type: Command hook (synchronous)
# Timeout: 120 seconds
#
# Intercepts all Bash tool calls. For non-commit commands, exits 0 immediately
# (near-zero overhead). For commit commands, runs quality checks (tests + tsc)
# and blocks the commit if any fail.
#
# Exit codes:
#   0 = allow (command proceeds)
#   2 = block (commit denied, stderr fed to Claude)
#
# JSON decision output for PreToolUse:
#   { "hookSpecificOutput": { "permissionDecision": "deny", "permissionDecisionReason": "..." } }
#
# Uses `bun -e` for JSON parsing instead of jq (project convention).

set -euo pipefail

# Read stdin JSON
INPUT=$(cat)

# Extract the Bash command being executed
COMMAND=$(printf '%s' "$INPUT" | bun -e "
  const data = JSON.parse(await Bun.stdin.text());
  const cmd = data.tool_input?.command || '';
  process.stdout.write(cmd);
")

# Fast exit: Not a commit command? Allow immediately.
# This check must be near-instant since it runs on EVERY Bash call.
case "$COMMAND" in
  *"git commit"*|*"git merge"*|*"bun run commit"*|*"bunx commit"*|*"bunx --bun commit"*)
    # Potentially a commit command — continue to quality checks
    ;;
  *)
    # Not a commit command — allow immediately
    exit 0
    ;;
esac

PROJECT_DIR="${CLAUDE_PROJECT_DIR:-.}"
ERRORS=""
HAS_ERRORS=0

# Quality Check 1: Run tests
echo "Running tests before commit..." >&2
set +e
TEST_OUTPUT=$(cd "$PROJECT_DIR" && bun test 2>&1)
TEST_EXIT=$?
set -e

if [ $TEST_EXIT -ne 0 ]; then
  HAS_ERRORS=1
  # Truncate test output to last 30 lines (most relevant)
  TEST_SUMMARY=$(echo "$TEST_OUTPUT" | tail -30)
  ERRORS="${ERRORS}
## Test Failures
\`\`\`
${TEST_SUMMARY}
\`\`\`
"
fi

# Quality Check 2: Type-check (if tsconfig.json exists)
if [ -f "$PROJECT_DIR/tsconfig.json" ]; then
  echo "Running type-checker before commit..." >&2
  TSC_OUTPUT=$(cd "$PROJECT_DIR" && bunx --bun tsc --noEmit 2>&1) || true
  TSC_EXIT=$?

  if [ $TSC_EXIT -ne 0 ] && [ -n "$TSC_OUTPUT" ]; then
    HAS_ERRORS=1
    TSC_SUMMARY=$(echo "$TSC_OUTPUT" | head -20)
    TSC_LINES=$(echo "$TSC_OUTPUT" | wc -l | tr -d ' ')
    if [ "$TSC_LINES" -gt 20 ]; then
      TSC_SUMMARY="$TSC_SUMMARY
... ($TSC_LINES total type errors, showing first 20)"
    fi
    ERRORS="${ERRORS}
## Type Errors
\`\`\`
${TSC_SUMMARY}
\`\`\`
"
  fi
fi

# If any checks failed, block the commit
if [ $HAS_ERRORS -ne 0 ]; then
  REASON="Commit blocked by pre-commit quality gate. Fix the following issues before committing:
${ERRORS}"

  # Output JSON decision to stdout for PreToolUse
  printf '%s' "$REASON" | bun -e "
    const reason = await Bun.stdin.text();
    const output = {
      hookSpecificOutput: {
        permissionDecision: 'deny',
        permissionDecisionReason: reason.trim()
      }
    };
    process.stdout.write(JSON.stringify(output));
  "

  # Exit 2 = block
  exit 2
fi

# All checks passed — allow the commit
exit 0
```

**Key decisions**:
- **Fast path for non-commits**: The `case` statement pattern-matches the command string. Non-commit commands exit 0 with near-zero overhead. This is critical because the hook fires on EVERY Bash tool call.
- **Commit detection patterns**: Matches `git commit`, `git merge`, `bun run commit`, and `bunx commit`. These cover the common commit commands in this project.
- **Two quality checks**: Tests (`bun test`) and type-checking (`bunx tsc --noEmit`). Lint is omitted because the post-edit formatter (HOOK-02) already handles formatting automatically.
- **JSON decision output**: Uses `hookSpecificOutput.permissionDecision: "deny"` for PreToolUse events, which is the documented API for blocking actions.
- **Exit code 2**: Signals "block" to Claude Code. The stderr output and JSON decision reason are both fed to Claude, who will see the error details and fix them.
- **Sequential checks**: Tests and type-check run sequentially (not parallel) for simpler error aggregation. Total time is typically 10-30 seconds, well within the 120-second timeout.
- **Truncated output**: Test output shows last 30 lines (most relevant failures), type errors show first 20 lines.

**Verification**:
- Script is valid bash: `bash -n src/hooks/scripts/pre-commit-gate.sh`
- Non-commit fast path: `echo '{"tool_input":{"command":"ls -la"}}' | bash src/hooks/scripts/pre-commit-gate.sh; echo $?` exits 0 instantly
- Non-commit with git: `echo '{"tool_input":{"command":"git status"}}' | bash src/hooks/scripts/pre-commit-gate.sh; echo $?` exits 0 instantly
- Commit detection: `echo '{"tool_input":{"command":"git commit -m test"}}' | bash src/hooks/scripts/pre-commit-gate.sh` runs quality checks (exit 0 if passing, exit 2 if failing)

```json

      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/post-edit-format.sh",
            "timeout": 10,
            "statusMessage": "Formatting..."
          },
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/post-edit-typecheck.sh",
            "timeout": 30,
            "async": true,
            "statusMessage": "Type-checking..."
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/pre-commit-gate.sh",
            "timeout": 120,
            "statusMessage": "Running pre-commit checks..."
```
