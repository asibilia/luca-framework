# Plan 32-02: Auto-Discuss Flag + Phase-Discuss Integration with User Override

## Objective

Add `--auto` flag support to the phase-discuss skill and its workflow. When invoked as `/phase-discuss <phase> --auto`, the skill bypasses the interactive multi-select and deep-dive loop. Instead, it: (1) auto-selects all identified gray areas, (2) spawns `lu-discuss-researcher` (from Plan 32-01) per gray area question to research each autonomously, (3) collects all recommendations with citations into a summary, (4) presents the summary to the user for review and override before writing CONTEXT.md, (5) writes CONTEXT.md with researched decisions. This maintains the user-override guardrail even in autonomous mode.

## Context

@src/skills/general/phase-discuss.skill.ts -- The phase-discuss skill definition. Currently has a single `main` section with the skill's arguments, process steps, and gray area identification logic. The `--auto` flag must be added to the arguments documentation, and the process section must document the auto mode execution path alongside the existing interactive path.

@.cursor/luca/workflows/discuss-phase.md -- The discuss-phase workflow used by the skill. Contains the step-by-step process: validate_phase, check_existing, analyze_phase, present_gray_areas, discuss_areas, write_context, confirm_creation, git_commit. The auto mode must add new steps (auto_select, auto_research, present_summary, user_override) that replace the interactive steps (present_gray_areas multi-select and discuss_areas loop) when `--auto` is active.

@src/agents/general/lu-discuss-researcher.agent.ts -- The lu-discuss-researcher agent created in Plan 32-01. Spawned per gray area question. Expects input: gray area question, phase context, tech stack. Returns: recommendation, confidence, sources, alternatives.

@.planning/BRAIN.md -- Project identity file. The auto mode reads the `## Stack` section to pass tech stack context to each lu-discuss-researcher spawn.

@.cursor/luca/templates/context.md -- Template for CONTEXT.md output. The auto mode produces the same output format but with research-backed decisions instead of user-provided answers.

@CLAUDE.md -- Project conventions (Bun-first, bun:test for testing).

## Tasks

### Task 1: Update phase-discuss skill with --auto flag documentation

**Goal:** Modify `src/skills/general/phase-discuss.skill.ts` to document the `--auto` flag in the skill's main section. The skill uses `disable-model-invocation: true` -- it is a prompt-only skill -- so changes are to the natural language content, not functional code.

**Files:** `src/skills/general/phase-discuss.skill.ts` (modify)

**Steps:**

1. In the `main` section content, update the **Arguments** line from:

   ```
   **Arguments:** `<phase>`
   ```

   to:

   ```
   **Arguments:** `<phase> [--auto]`
   ```

2. After the "How It Works" numbered list, add a new subsection for auto mode:

   ```markdown
   ## Auto Mode (`--auto`)

   When invoked with `--auto`, the discussion runs autonomously:

   1. Analyze the phase to identify gray areas (same as interactive)
   2. Auto-select ALL gray areas (no multi-select prompt)
   3. Spawn `lu-discuss-researcher` agent per gray area question
   4. Each researcher uses WebSearch/WebFetch scoped to project tech stack (from BRAIN.md)
   5. Collect all recommendations with citations into a summary
   6. Present summary to user for review and override
   7. Write CONTEXT.md with researched decisions (user-approved)

   **Key difference:** Auto mode replaces user Q&A with web research. The user still approves before CONTEXT.md is written.

   **When to use auto mode:**

   - Standard domain where best practices are well-documented
   - User wants to skip interactive discussion and review research instead
   - Kickstarting context for phases where user has no strong preferences

   **When NOT to use auto mode:**

   - User has specific vision or preferences (use interactive mode)
   - Domain is niche or novel (research may not find good answers)
   - Phase is TRIVIAL or SIMPLE (discussion is skipped entirely regardless)
   ```

3. In the "Process" section, add a conditional branch after step 4 ("Present gray areas"):

   ```markdown
   ### Auto Mode Branch

   If `--auto` flag is present, after step 3 (Analyze phase):

   4a. **Auto-select all gray areas** — Skip multi-select, research all identified areas
   5a. **Spawn lu-discuss-researcher per question** — Read BRAIN.md Stack section, spawn Task() per gray area
   6a. **Present research summary** — Show all recommendations with citations before writing
   7a. **User override** — User can accept, modify, or reject any recommendation
   8a. **Write CONTEXT.md** — Same format as interactive mode, decisions sourced from research + overrides
   ```

4. In the "Next Steps" table, add a note that auto mode follows the same next steps as interactive mode.

- [ ] Auto mode section references `lu-discuss-researcher` agent
- [ ] Auto mode section references BRAIN.md for tech stack scoping
- [ ] User override step is explicitly documented (even in auto mode)

### Task 2: Update discuss-phase workflow with auto mode steps

**Goal:** Modify `.cursor/luca/workflows/discuss-phase.md` to add auto mode steps that replace the interactive discussion loop when `--auto` is active.

**Files:** `.cursor/luca/workflows/discuss-phase.md` (modify)

   ```markdown
   Proceed to `auto_select` → `auto_research` → `present_summary` → `user_override` → `write_context`.

   </step>
   ```

   Luca ► AUTO-DISCUSS MODE

   ✓ {Gray area 4}

   ```

   Proceed to `auto_research`.
   </step>
   ```

3. Add the `auto_research` step:

   ````markdown
   <step name="auto_research">
   For each gray area, spawn a `lu-discuss-researcher` agent via Task().

   **Step 1: Read BRAIN.md**

   ```bash
   cat .planning/BRAIN.md
   ```
   ````

   Extract the `## Stack` section content to pass as tech stack context.

   **Step 2: Formulate questions**

   For each gray area, generate 1-2 specific research questions that would resolve the ambiguity. These should be concrete technical questions, not vague "what should we do" questions.

   Example:
   - Gray area: "Loading behavior"
   - Questions: "What is the recommended pagination pattern for TypeScript + Bun APIs?" and "Infinite scroll vs pagination performance tradeoffs for list views?"

   **Step 3: Spawn researchers**

   For each gray area question, spawn lu-discuss-researcher:

   ```
   Task(
     prompt="""
   <research_context>
   **Gray Area:** {gray_area_name}
   **Question:** {specific_question}

   **Phase Context:**
   - Phase: {phase_number} - {phase_name}
   - Description: {phase_description}
   - Goal: {phase_goal_from_roadmap}

   **Tech Stack (from BRAIN.md):**
   {stack_section_content}
   </research_context>

   Research this question and return a cited recommendation. Follow your research_protocol and output_format sections.
   """,
     subagent_type="lu-discuss-researcher",
     description="Research: {gray_area_name}"
   )
   ```

   **Step 4: Collect results**

   Wait for all Task() spawns to complete. Collect each researcher's output (recommendation, confidence, sources, alternatives).

   If any researcher returns `researchable: false`, note that gray area needs interactive discussion with the user.

   Proceed to `present_summary`.
   </step>

   ```

   ```

5. Add the `user_override` step:

   ```markdown
   <step name="user_override">
   Give the user the opportunity to override any recommendation before writing CONTEXT.md.

   Use AskQuestion:

   - header: "Review Research"
   - question: "Review the recommendations above. What would you like to do?"
   - options:
     - "Accept all" — Use all recommendations as-is for CONTEXT.md
     - "Override some" — Let me change specific recommendations
     - "Discuss instead" — Switch to interactive mode for remaining areas

   **If "Accept all":**
   Proceed to `write_context` with all research-backed decisions.

   **If "Override some":**
   For each gray area, ask:

   - header: "{Gray Area Name}"
   - question: "Research recommends: {recommendation}. Keep this or change?"
   - options:
     - "Keep" — Use the researched recommendation
     - "Change" — {user provides their preference}

   Collect overrides. Proceed to `write_context` with mixed decisions (research + overrides).

   **If "Discuss instead":**
   Fall back to the interactive `discuss_areas` step for ALL gray areas. Discard research results.

   Proceed to `write_context`.
   </step>
   ```

6. Update the existing `write_context` step to handle auto mode decisions. Add a note at the top of the step:

   ````markdown
   ```markdown

   ```
   ````

   For user-overridden decisions:

   ```markdown
   ### {Category}

   - {Decision} _(user override — research suggested {original recommendation})_
   ```

   ```

   ```
