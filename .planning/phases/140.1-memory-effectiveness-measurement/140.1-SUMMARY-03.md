# Phase 140.1 Plan 3 Summary: Surfacing -- Progress Skill Memory Health and Milestone-Complete Pruning

## Objective

Surface memory effectiveness data to the developer via the progress skill, and add stale memory detection and pruning to milestone-complete so memory stays clean across milestones.

## What Was Done

### Task 1: Memory Health Section in Progress Skill

Added a new "Memory Health" section to `src/skills/general/progress.skill.ts` Step 5 (Present Rich Status Report), inserted between "Key Decisions Made" and "Blockers/Concerns".

The section:

- Recalls recent memory metrics from MuninnDB (recall precision, hit rate)
- Conditionally renders -- only displayed when metric data exists, skipped entirely when no data
- Shows an ASCII banner with: recall precision %, hit rate %, token cost, stale engram count
- Computes health status: `healthy` (precision >= 0.5 AND stale <= 3), `degraded` (precision < 0.5 OR stale > 3), `no_data` (no metrics)
- Suggests `/milestone-complete` when degraded

### Task 2: Stale Memory Pruning in Milestone-Complete

Added Step 0.5 (Stale Memory Detection and Pruning) to `src/skills/general/milestone-complete.skill.ts`, inserted between Step 0 (Final Learning Extraction) and Step 1 (Archive Milestone Memory).

Step 0.5:

1. Recalls all memory metrics for the milestone
2. Identifies stale engrams (recalled 3+ times with net-negative feedback, or never recalled at all)
3. Applies pruning actions: forget (old + unused), evolve (low usefulness), consolidate (similar low-utility)
4. Stores pruning report as a MuninnDB metric engram (`metric:memory-pruning-{version}`)

Also updated Step 1 (Archive Milestone Memory) to include "Memory effectiveness summary" in the archive contents.
