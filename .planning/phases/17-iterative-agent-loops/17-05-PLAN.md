# Plan 17-05: Orchestrator Loop Protocol & Skill Update

## Objective

Replace the existing Step 6.6 (Failure-to-Fix Loop) in `lu-execute-phase/SKILL.md` with the new unified loop protocol, and add the Loop B (Verify Loop) after Step 7 (verifier). The orchestrator skill is the loop controller -- it calls the `src/iteration/` CLI utilities for convergence detection, error classification, checkpoint management, and budget tracking to make iteration decisions. This plan delivers the core ITER-01 requirement: decision-support utilities in src/iteration/, skill orchestrates the loop. It also delivers ITER-07 (HITL/AFK mode integration) at the skill level.

## Context

- **Current skill:** `.claude/skills/lu-execute-phase/SKILL.md` (Steps 6.5, 6.6, 7 are the relevant sections)
- **Current Step 6.6:** Simple failure-to-fix loop. Reads harnessFixIterations from complexity. Spawns lu-executor with errors. Re-runs harness. Aborts if errors unchanged 2x consecutive. ~80 lines.
- **Current Step 7:** Spawns lu-verifier. Routes by status: passed/human_needed/gaps_found. No re-execution of plans.
- **Iteration utilities (Plan 17-02):** convergence.ts (createFingerprint, assessConvergence), classifier.ts (classifyErrors, partitionByClass)
- **Checkpoint utilities (Plan 17-03):** checkpoint.ts (createCheckpoint, rollbackToCheckpoint, getArtifactDelta, getCurrentCommitHash, prunePhaseCheckpoints), budget.ts (createBudgetState, shouldStartIteration, advanceBudget)
- **ComplexityGate updates (Plan 17-04):** verifyFixIterations field, iteration config section, source_plan in verifier gaps
- **Locked decisions:** 17-CONTEXT.md Decision 1 (two loop points, orchestrator-only control, Step 6.6 replaced)
- **Locked decisions:** 17-CONTEXT.md Decision 3 (AFK default, HITL pause with 4 options)
- **Locked decisions:** 17-CONTEXT.md Decision 4 (convergence detection, classification, permanent error handling)
- **Ralph Wiggum principle:** The skill IS the loop controller. src/iteration/ provides decision-support. No standalone loop program.

## Design Decisions Applied

1. **Skill IS the loop controller**: The lu-execute-phase SKILL.md describes the loop protocol in natural language. Claude follows these instructions, calling CLI utilities for intelligence. No TypeScript loop orchestrator program.
2. **Two loop points**: Loop A (Step 6.6 replacement) after harness, Loop B (new Step 7.5) after verifier. Both use the same loop protocol with different configuration.
3. **Unified loop protocol**: Both loops follow the same pre-check/execute/evaluate/classify/converge/checkpoint cycle. Only the trigger (harness errors vs verifier gaps) and limits (harnessFixIterations vs verifyFixIterations) differ.
4. **HITL/AFK integration**: Mode read from config.json iteration.default_mode, overridable with --mode flag. AFK runs autonomously; HITL pauses with 4-choice menu after each iteration.
5. **Per-plan re-execution in Loop B**: Verifier identifies which plans have gaps (via source_plan). Loop B re-executes only those plans with gap-targeted instructions.
