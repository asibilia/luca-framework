# Plan 22-03: Build Pipeline Consolidation

## Objective

Consolidate all plugin generation logic from `scripts/build-plugin.ts` into `scripts/build-all.ts`, creating a single unified build script that generates all three targets (.claude/, .cursor/, dist/plugin/) in one pass. Remove the standalone `build-plugin.ts` file and the `build:plugin` script from package.json. After this plan, `bun run build:all` is the only way to build, and the build summary reports stats for all three targets. This plan depends on 22-01 (marketplace.json) and 22-02 (README) because it consolidates the logic those plans added to build-plugin.ts.

## Context

@scripts/build-all.ts -- Unified build script (414 lines). Currently generates .claude/ and .cursor/ output inline (lines 47-358), then calls `import { buildPlugin } from "./build-plugin"` at line 44 and `await buildPlugin()` at line 363. After consolidation, the buildPlugin() call is replaced with inline plugin generation.

@scripts/build-plugin.ts -- Plugin build script (553 lines). Contains all plugin generation logic that will be moved inline into build-all.ts. Key sections to move:

- `COMMAND_EXCLUDED_SKILLS` (lines 74-81)
- `PLUGIN_EXCLUDED_HOOKS` (lines 90-92)
- `generatePluginHooksConfig()` (lines 105-143)
- `generateCommandMarkdown()` (lines 157-162)
- `readVersion()` (lines 172-203)
- `SKILL_CATEGORIES`, `AGENT_CATEGORIES`, `generateReadme()` (added by Plan 22-02)
- Plugin directory setup, compilation, command generation, hook copying, manifest generation, marketplace generation, README generation (lines 228-525)

@scripts/build-utils.ts -- Shared build utilities (`cleanDirectory`, `cleanSkillsDirectory`, `ensureDir`). Already imported by both build-all.ts and build-plugin.ts. No changes needed.

@src/compilers/plugin.compiler.ts -- PluginCompiler class. Currently imported by build-plugin.ts. After consolidation, build-all.ts will import it directly.

@src/compilers/plugin.types.ts -- `generatePluginManifest()` function. Currently imported by build-plugin.ts. After consolidation, build-all.ts will import it directly.

@package.json -- Contains `"build:plugin": "bun ./scripts/build-plugin.ts"` which will be removed.

@.planning/phases/22-distribution/22-RESEARCH.md -- Section 2 covers the build pipeline analysis. Section 2.2 details the consolidation approach. Section 2.3 describes the enhanced build summary. Section 2.4 covers package.json script changes. Section 6.6 warns about import side effects.

## Tasks

### Task 1: Extract shared constants to build-shared.ts, then move plugin logic inline into build-all.ts

**Goal:** First, extract shared constants and helper functions into a new `scripts/build-shared.ts` module so they can be imported by both `build-all.ts` and (later in Plan 22-04) `check-drift.ts` and `check-drift.test.ts`. Then replace the `buildPlugin()` call in `build-all.ts` with inline plugin generation logic that imports from `build-shared.ts`.

**Files:** `scripts/build-shared.ts` (create), `scripts/build-all.ts` (modify)

**Steps:**

1. Read both `scripts/build-all.ts` and `scripts/build-plugin.ts` in full.

2. **Create `scripts/build-shared.ts`** with the following shared exports extracted from `build-plugin.ts`:
   - `COMMAND_EXCLUDED_SKILLS` set (from build-plugin.ts lines 74-81)
   - `PLUGIN_EXCLUDED_HOOKS` set (from build-plugin.ts lines 90-92)
   - `SKILL_CATEGORIES` map (added by Plan 22-02)
   - `AGENT_CATEGORIES` map (added by Plan 22-02)
   - `generatePluginHooksConfig()` function (from build-plugin.ts lines 105-143)
   - `generateCommandMarkdown()` function (from build-plugin.ts lines 157-162)
   - `readVersion()` function (from build-plugin.ts lines 172-203)
   - `generateReadme()` function (added by Plan 22-02)

   This module is the single source of truth for these constants and functions. Both `build-all.ts` and `check-drift.ts` (Plan 22-04) will import from it, eliminating code duplication across all three files.

3. **Update imports** in `build-all.ts`:
   - Remove: `import { buildPlugin } from "./build-plugin";` (line 44)
   - Add: `import { PluginCompiler } from "../src/compilers/plugin.compiler";`
   - Add: `import { generatePluginManifest } from "../src/compilers/plugin.types";`
   - Add: `import type { HookDefinition } from "../src/hooks/index";` (already partially imported via hookRegistry)
   - Add: `import { COMMAND_EXCLUDED_SKILLS, PLUGIN_EXCLUDED_HOOKS, SKILL_CATEGORIES, AGENT_CATEGORIES, generatePluginHooksConfig, generateCommandMarkdown, readVersion, generateReadme } from "./build-shared";`

4. **Do NOT define constants or helper functions inline** in `build-all.ts`. All shared constants and functions come from `build-shared.ts` imports.

5. **Replace the plugin build section** in `main()`. Remove the existing plugin section (lines 361-372):

   ```typescript
   // --- Plugin ---
   console.log("\n--- Plugin ---");
   const pluginSummary = await buildPlugin();
   // ...
   ```

   Replace with the full inline plugin generation logic from `buildPlugin()` (build-plugin.ts lines 228-525), adapted to:
   - Use the same `failures` array already defined in `main()` scope
   - Track plugin-specific counts (`pluginAgentCount`, `pluginSkillCount`, `pluginCommandCount`, `pluginHookCount`) to avoid name collisions with the existing `.claude/.cursor` counters
   - Track plugin-specific name arrays (`pluginAgentNames`, `pluginSkillNames`, `pluginCommandNames`, `pluginHookNames`) for manifest and README generation
   - Include marketplace.json generation (from Plan 22-01)
   - Include README.md generation (from Plan 22-02)

6. Key adaptation notes:
   - The `.claude/.cursor` section already compiles agents/skills/rules with `cursorCompiler` and `claudeCompiler`. The plugin section compiles the same registries with `pluginCompiler` -- this is NOT duplication; the PluginCompiler produces different output.
   - Luca-specific agents/skills (lu-executor, lu-planner, lu skill) must be compiled for the plugin just as they are for .claude/.cursor.
   - The `readVersion()` function call must happen in the plugin section (it reads package.json for the version field).

### Task 3: End-to-end verification with concrete before/after comparison

2. **After consolidation** (after applying Task 1 and Task 2 changes):

   - If any differences appear, investigate and fix before proceeding

4. Run `bun test` -- all 877+ tests should pass.
