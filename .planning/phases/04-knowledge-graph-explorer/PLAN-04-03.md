## Tasks

### 1. Create TimeRangeSlider component

**Type:** auto
**TDD:** false
**Depends on:** none

Create `packages/luca-observer/components/knowledge-graph/time-range-slider.tsx` — a dual-handle date range slider with histogram overlay.

**Layout:**

- Positioned at bottom of graph area (absolute, full width, height ~80px)
- Semi-transparent dark background with blur backdrop
- Two range handles (start/end) over a date axis
- Small histogram bar chart behind the slider showing node creation density

**Implementation:**

- Use two native `<input type="range">` elements overlaid on each other
- Both share the same min/max (timeExtent[0] to timeExtent[1] as Unix timestamps)
- Style the track as transparent; only style the thumbs
- Left handle controls start of range; right handle controls end
- Prevent handles from crossing (left handle max = right handle value, and vice versa)
- Display formatted dates below each handle (use month/day format for compactness)
- Histogram: render as a row of thin CSS bar divs behind the slider (pure CSS, no Canvas)
  - Divide time range into ~40 buckets
  - Height of each bar = proportional to node count in that bucket
  - Color: white at 20% opacity

**Props:**

- `timeExtent: [number, number]` — overall min/max timestamps
- `timeRange: [number, number] | null` — current selected range (null = full range)
- `histogram: number[]` — array of bucket counts
- `onRangeChange: (range: [number, number] | null) => void` — callback when range changes
- `onReset: () => void` — reset to full range

**Interaction:**

- Dragging handles updates the range in real-time (with throttle at ~100ms for performance)
- Double-click on track resets to full range
- Show "Reset" text button when range is filtered

**Files to create:**

- `packages/luca-observer/components/knowledge-graph/time-range-slider.tsx`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- Two handles render and are draggable

### 2. Improve cluster expand/collapse behavior

**Type:** auto
**TDD:** false
**Depends on:** none

Refine the cluster expand/collapse in the hook and canvas to handle Pitfall 3 (position loss on expand).

**Improvements to `useKnowledgeGraph` hook:**

- When expanding a cluster type via `toggleCluster`:
  1. Record the x/y position of the cluster supernode before expansion
  2. Position all newly visible child nodes near that x/y (random offset within radius 30)
  3. Set initial `fx`/`fy` (fixed position) on child nodes, then release after 500ms
  - This prevents the "scatter" effect where all nodes fly to random positions
- When collapsing a cluster type:
  1. Calculate centroid of the child nodes being collapsed
  2. Position the new cluster supernode at that centroid

**Improvements to `GraphCanvas`:**

- After expanding: set `cooldownTicks={50}` temporarily (gentle re-layout, not full restart)
- After collapsing: set `cooldownTicks={30}` (even less movement needed)
- Call `graphRef.current.d3ReheatSimulation()` after data change for smooth transition

**Files to edit:**

- `packages/luca-observer/hooks/use-knowledge-graph.ts`
- `packages/luca-observer/components/knowledge-graph/graph-canvas.tsx`

**Verification:**

- Expanding a cluster positions child nodes near the former cluster location
- Collapsing keeps the new cluster near where the children were
- No "scatter to random positions" effect on expand

### 3. Add connection highlighting on hover

**Type:** auto
**TDD:** false
**Depends on:** none

When hovering over a node, highlight its direct connections (connected nodes + their links).

**Implementation in `graph-canvas.tsx`:**

- Track `hoveredNodeId` and compute `highlightedNodeIds` (Set of directly connected node IDs)
- Compute highlighted set from graphData.links: for each link where source or target matches hoveredNodeId, add the other endpoint to the set
- In `nodeCanvasObject`: nodes NOT in highlightedNodeIds get dimmed (alpha 0.2) when a hover is active
- In `linkCanvasObject` or `linkColor`: links NOT connected to hovered node get dimmed when hover active
- When hover clears (hoveredNodeId = null), restore all nodes/links to full opacity

**Performance:**

- Pre-compute a `nodeNeighbors` Map<nodeId, Set<nodeId>> from links once per graphData change (useMemo)
- Use this for O(1) lookup of connected nodes during rendering

**Files to edit:**

- `packages/luca-observer/components/knowledge-graph/graph-canvas.tsx`

**Verification:**

- Hovering a node dims unconnected nodes and links
- Connected nodes and links remain bright
- Removing hover restores all to normal
- Performance remains smooth
