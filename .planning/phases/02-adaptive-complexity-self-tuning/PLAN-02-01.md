### 3. Create reassessment.ts module with shouldPromoteComplexity() and buildCalibrationEngram()

**Type:** auto
**TDD:** false
**Depends on:** 1, 2

Create `src/complexity/__helpers/reassessment.ts` with two functions:

**3a. `shouldPromoteComplexity(signals, alreadyPromoted)`**

Logic (threshold-based OR -- any single signal exceeding threshold triggers promotion):

1. If `currentLevel === "CRITICAL"` or `alreadyPromoted === true`, return no-promote with reason.
2. Look up `REASSESSMENT_THRESHOLDS[currentLevel]`.
3. Check each signal against its threshold. Collect trigger descriptions for signals that exceed.
4. If no triggers, return no-promote.
5. If triggers exist, compute next level: `COMPLEXITY_LEVELS[COMPLEXITY_ORDER[currentLevel] + 1]`.
6. Return `should_promote: true` with `promoted_to`, `triggered_by`, and `reason`.

**3b. `buildCalibrationEngram(params)`**

Parameters:

- `phase`: number
- `milestone`: string
- `predicted`: ComplexityLevel (initial lu-router classification)
- `actual`: ComplexityLevel (final observed, post-promotion if any)
- `promoted_mid_execution`: boolean
- `promotion_trigger`: string (or empty string if no promotion)
- `files_touched`: number
- `harness_iterations`: number

Returns an object with:

- `concept`: `"decision:complexity-calibration-{milestone}-phase-{phase}"` -- includes milestone for uniqueness per research pitfall #5
- `content`: JSON-stringified calibration data with all params plus an ISO 8601 timestamp

Import from:

- `COMPLEXITY_LEVELS`, `COMPLEXITY_ORDER`, `type ComplexityLevel` from `../schemas/complexity.schemas`
- `REASSESSMENT_THRESHOLDS` from `./defaults`
- `ReassessmentSignals`, `ReassessmentResult`, `ReassessmentSignalsSchema`, `ReassessmentResultSchema` from `../__schemas/complexity.schemas`

Follow existing patterns from `self-tuning.ts` for JSDoc comments and function structure.
