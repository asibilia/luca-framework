# Plan 16-02: Schema Integration & Compiler Extension

## Objective

Integrate the context module types (from Plan 16-01) into the existing agent schema system and compiler pipeline. This plan adds the `context` field to `agentFrontmatterSchema`, extends `ComplexityGate` with `contextPromotions`, and updates `ClaudeCompiler` to emit context config in YAML frontmatter alongside cognition config. After this plan, agents can declare context configuration and the build pipeline will propagate it to compiled `.md` files.

## Context

- **Context module (from 16-01):** `src/context/types.ts` (contextConfigSchema, contextTierSchema, isolationModeSchema)
- **Agent schemas:** `src/agents/types/agent.schemas.ts` (agentFrontmatterSchema, cognitionConfigSchema)
- **Agent types:** `src/agents/types/agent.types.ts` (AgentFrontmatter interface with `[key: string]: unknown` index signature)
- **Complexity types:** `src/complexity/types.ts` (ComplexityGate with `cognitionPromotions`)
- **Complexity defaults:** `src/complexity/defaults.ts` (DEFAULT_COMPLEXITY_MATRIX)
- **ClaudeCompiler:** `src/compilers/claude.compiler.ts` (lines 18-38: compileAgent with cognition frontmatter emission)
- **Cognition resolve-tier:** `src/agents/cognition/resolve-tier.ts` (imports from complexity, pattern to follow)
- **Shared utils:** `src/shared/utils.ts` (formatFrontmatter used by compiler)

## Design Decisions Applied

1. **Agent frontmatter has `[key: string]: unknown`** (from research): Safe to add `context` alongside `cognition` without breaking existing code
2. **Independent promotion tracks** (Decision 2): `contextPromotions` is a separate field from `cognitionPromotions` in ComplexityGate
3. **Clean separation** (Decision 8): Agent declares context config (WHAT to load), orchestrator uses it to assemble context

**Changes to `src/complexity/types.ts`:**

Add import of `ContextTier` type:


Add `contextPromotions` field to `ComplexityGate` interface:

```typescript
export interface ComplexityGate {
  // ... existing fields ...

  /** Optional cognition tier promotions at this complexity level. */
  cognitionPromotions?: Partial<Record<CognitionTier, CognitionTier>>;

  /** Optional context tier promotions at this complexity level.
   *  Context promotes more aggressively than cognition (starts at MODERATE).
   *  Maps a default tier to a promoted tier (e.g., T0 -> T1 at MODERATE). */
  contextPromotions?: Partial<Record<ContextTier, ContextTier>>;
}
```

### Task 3: Extend ClaudeCompiler to emit context frontmatter

**Goal:** Update the ClaudeCompiler to include context configuration in the YAML frontmatter block of compiled agent `.md` files, following the existing cognition emission pattern.

**File to modify:** `src/compilers/claude.compiler.ts`

**Current pattern (lines 22-34):**

```typescript
const cognition = agent.config.frontmatter.cognition;
if (cognition) {
  const frontmatterData: Record<string, unknown> = {
    name: agent.name,
    cognition: { ... },
  };
  const yamlBlock = formatFrontmatter(frontmatterData);
  return `${yamlBlock}\n\n${markdown}`;
}
```

**New pattern:** Emit frontmatter when EITHER cognition OR context is present. Include both if both exist:

```typescript
compileAgent(agent: BaseAgent, format: SupportedFormat): string {
  this.validateFormat(format);
  const markdown = agent.toClaudeFormat();

  const cognition = agent.config.frontmatter.cognition;
  const context = agent.config.frontmatter.context;

  // Emit YAML frontmatter if cognition OR context config is present
  if (cognition || context) {
    const frontmatterData: Record<string, unknown> = {
      name: agent.name,
    };

    if (cognition) {
      frontmatterData.cognition = {
        default_tier: cognition.default_tier,
        promotable_to: cognition.promotable_to,
        memory_tags: cognition.memory_tags,
      };
    }

    if (context) {
      frontmatterData.context = {
        default_tier: context.default_tier,
        promotable_to: context.promotable_to,
        isolation: context.isolation,
      };
    }

    const yamlBlock = formatFrontmatter(frontmatterData);
    return `${yamlBlock}\n\n${markdown}`;
  }

  return markdown;
}
```

**Verification:**

- [ ] Agents with BOTH cognition and context get both blocks in YAML frontmatter
- [ ] Agents with ONLY cognition still compile correctly (no regression)
- [ ] Agents with ONLY context get context block in YAML frontmatter
- [ ] Agents with NEITHER still compile as plain markdown (no frontmatter)
- [ ] The compiled `.md` output is valid YAML frontmatter (parseable by yaml.load)
- [ ] `bunx --bun tsc --noEmit` passes

### Task 4: Update resolve-context-tier to use ComplexityGate

**Goal:** Now that `contextPromotions` lives in the complexity matrix (Task 2), update the context tier resolution function to read from the matrix instead of its own defaults.

**File to modify:** `src/context/resolve-context-tier.ts`

Update `resolveEffectiveContextTier` to accept promotions from the complexity matrix. The function signature already supports this (it takes `contextPromotions` as a parameter). Add a convenience overload that reads from the matrix:

```typescript
import { DEFAULT_COMPLEXITY_MATRIX } from "../complexity/defaults";

/**
 * Resolves the effective context tier for a sub-agent using the complexity matrix.
 * This is the primary entry point -- reads contextPromotions from the matrix.
 */
export function resolveContextTierFromMatrix(
  defaultTier: ContextTier,
  promotableTo: ContextTier,
  complexityLevel: ComplexityLevel,
): ContextTier {
  const gate = DEFAULT_COMPLEXITY_MATRIX[complexityLevel];
  return resolveEffectiveContextTier(
    defaultTier,
    promotableTo,
    complexityLevel,
    gate.contextPromotions,
  );
}
```

Update `src/context/index.ts` to also export `resolveContextTierFromMatrix`.

**Verification:**

- [ ] `resolveContextTierFromMatrix('T0', 'T1', 'MODERATE')` returns `'T1'` (uses matrix)
- [ ] `resolveContextTierFromMatrix('T0', 'T0', 'MODERATE')` returns `'T0'` (ceiling)
- [ ] `resolveContextTierFromMatrix('T2', 'T3', 'COMPLEX')` returns `'T3'` (uses matrix)

- [ ] Both functions exported from `src/context/index.ts`
