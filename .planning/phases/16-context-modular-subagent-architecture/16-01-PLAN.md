# Plan 16-01: Context Module Foundation & Result Envelope

## Objective

Create the `src/context/` module with the foundational type system for context-modular sub-agent architecture: context tier definitions, context profile schemas, budget allocation types, isolation modes, and the universal result envelope. This plan establishes the type vocabulary that all subsequent plans import -- no existing files are modified, only new files are created.

## Context

- **Module pattern precedent:** `src/complexity/` (types.ts + defaults.ts + index.ts)
- **Harness pattern precedent:** `src/harness/` (types.ts + runner.ts + parsers/ + index.ts)
- **Existing cognition tiers:** `src/agents/types/agent.types.ts` (CognitionTier = T0-T3)
- **Existing complexity types:** `src/complexity/types.ts` (ComplexityLevel, ComplexityGate)
- **Phase 16 decisions:** `.planning/phases/16-context-modular-subagent-architecture/16-CONTEXT.md` (8 key decisions)
- **Phase 16 research:** `.planning/phases/16-context-modular-subagent-architecture/16-RESEARCH.md` (module structure, tier assignments)

## Design Decisions Applied

1. **Additive tier-mapped profiles** (Decision 1): Context tiers are T0-T3, mapped to document sets that grow additively
2. **Output reservation is advisory** (Decision 3): Budget fields are documented guidance, not enforced constraints
3. **Universal result envelope as Zod schema** (Decision 4): `{ status, summary, artifacts[], issues[], metadata }` with fallback-to-raw
4. **Conflict resolution: keep all, tag with source** (Decision 5): Issues array includes `source_agent` field
5. **Clean separation: agents = HOW, orchestrator = WHAT** (Decision 8): Context config describes WHAT to load, not HOW the agent works

### Task 1: Create src/context/types.ts — Core Type Definitions

**Goal:** Define the foundational types for context-modular sub-agent architecture using Zod schemas with `z.infer` for type derivation (no separate interfaces that could drift).

**File:** `src/context/types.ts` (new)

Define the following types:

**Context Tiers (parallels cognition tiers):**

```typescript
/** Context tiers control how much project context a sub-agent receives.
 * T0 = plan only, T1 = + BRAIN.md summary, T2 = + STATE.md + selective MEMORY + WORKING.md,
 * T3 = + full BRAIN + full MEMORY + agent summaries */
export const CONTEXT_TIERS = ["T0", "T1", "T2", "T3"] as const;
export type ContextTier = (typeof CONTEXT_TIERS)[number];
```

**Numeric order for tier comparison** (same pattern as `TIER_ORDER` in `resolve-tier.ts`):

```typescript
export const CONTEXT_TIER_ORDER: Record<ContextTier, number> = {
  T0: 0,
  T1: 1,
  T2: 2,
  T3: 3,
};
```

**Isolation mode** (from Decision 6 — writer/reviewer separation):

```typescript
export const ISOLATION_MODES = ["none", "cold", "warm"] as const;
export type IsolationMode = (typeof ISOLATION_MODES)[number];
```

- `none`: No isolation restrictions, receives full context per tier
- `cold`: Receives only diff + BRAIN.md (code reviewers)
- `warm`: Receives plans + summaries, NO WORKING.md (verifier)

**Context profile Zod schema** (per-agent context configuration):

```typescript
export const contextConfigSchema = z.object({
  /** Default context tier for this agent */
  default_tier: contextTierSchema.default("T0"),
  /** Maximum context tier this agent can be promoted to */
  promotable_to: contextTierSchema.default("T0"),
  /** Isolation mode for writer/reviewer separation */
  isolation: isolationModeSchema.default("none"),
});
```

**Budget allocation types** (advisory, not enforced per Decision 3):

```typescript
export const budgetAllocationSchema = z.object({
  /** Total token budget allocated to this sub-agent invocation */
  total_tokens: z.number().int().positive(),
  /** Recommended output reservation (25-50% of total) */
  output_reservation_pct: z.number().min(0.25).max(0.5).default(0.3),
  /** Whether this budget is advisory (true) or hard-enforced (false) */
  advisory: z.boolean().default(true),
});
```

**Context document set** (what the orchestrator assembles for a given tier):

```typescript
export const contextDocumentSetSchema = z.object({
  /** Plan content (always included, T0+) */
  plan_content: z.string().optional(),
  /** BRAIN.md summary (T1+) */
  brain_summary: z.string().optional(),
  /** STATE.md content (T2+) */
  state_content: z.string().optional(),
  /** Selective MEMORY.md entries filtered by agent's memory_tags (T2+) */
  memory_entries: z.string().optional(),
  /** WORKING.md content (T2+ when isolation != warm) */
  working_content: z.string().optional(),
  /** Full BRAIN.md content (T3 only, replaces brain_summary) */
  brain_full: z.string().optional(),
  /** Full MEMORY.md content (T3 only, replaces memory_entries) */
  memory_full: z.string().optional(),
  /** Other agent summaries from current phase (T3 only) */
  agent_summaries: z.string().optional(),
  /** Git diff content (cold isolation only) */
  git_diff: z.string().optional(),
  /** Plan summaries (warm isolation only) */
  plan_summaries: z.string().optional(),
});
```

**Utility functions:**

```typescript

  tier: ContextTier,
```

**Issue severity (reuse from code review pattern):**

```typescript

  "critical",
  "high",
  "medium",
  "low",
  "info",
] as const;
```

**Artifact schema** (files created/modified by sub-agent):

```typescript

  path: z.string(),
  action: z.enum(["created", "modified", "deleted"]),
  description: z.string().optional(),
});
```

**Issue schema** (problems found, tagged with source agent per Decision 5):

```typescript
export const resultIssueSchema = z.object({
  severity: issueSeveritySchema,
  message: z.string(),
  file: z.string().optional(),
  line: z.number().optional(),
  source_agent: z.string(),
  suggestion: z.string().optional(),
});
```

**The universal result envelope:**

```typescript
export const resultEnvelopeSchema = z.object({
  status: resultStatusSchema,
  summary: z.string(),
  artifacts: z.array(resultArtifactSchema).default([]),
  issues: z.array(resultIssueSchema).default([]),
  metadata: z.object({
    agent_name: z.string(),
    duration_ms: z.number().optional(),
    context_tier: contextTierSchema,
    isolation_mode: isolationModeSchema.optional(),
  }),
});
```

**Safe parsing utility** (fallback-to-raw per Decision 4):

```typescript
/**
 * Attempts to parse a sub-agent result string as a ResultEnvelope.
 * If parsing fails, wraps the raw string in a minimal envelope with
 * status='partial' and the raw text as the summary.
 */
export function parseResultEnvelope(
  raw: string,
  agentName: string,
): ResultEnvelope;
```

Implementation: Try JSON.parse, then `resultEnvelopeSchema.safeParse()`. On failure, return `{ status: 'partial', summary: raw.slice(0, 2000), artifacts: [], issues: [], metadata: { agent_name: agentName, context_tier: 'T0' } }`.

**Verification:**

- [ ] ResultEnvelope schema validates correct data
- [ ] ResultEnvelope schema provides defaults for optional arrays
- [ ] `parseResultEnvelope()` handles valid JSON correctly
- [ ] `parseResultEnvelope()` wraps non-JSON strings gracefully
- [ ] `parseResultEnvelope()` wraps invalid-schema JSON gracefully

### Task 4: Create src/context/resolve-context-tier.ts — Context Tier Resolution

**Goal:** Create the context tier resolution function, parallel to `src/agents/cognition/resolve-tier.ts` but for context tiers with independent promotion tracks (Decision 2).

**File:** `src/context/resolve-context-tier.ts` (new)

Define:

```typescript
/**
 * Resolves the effective context tier for a sub-agent.
 *
 * Context tiers promote one level more aggressively than cognition:
 * - MODERATE: context promotes (T0->T1, T1->T2), cognition does not
 * - COMPLEX: both context and cognition promote
 * - CRITICAL: both promote (context reaches ceiling faster)
 *
 * @param defaultTier - Agent's default context tier from frontmatter
 * @param promotableTo - Maximum context tier this agent can reach
 * @param complexityLevel - Current task complexity level
 * @param contextPromotions - Per-level promotion map (from complexity gate)
 * @returns The effective context tier for this invocation
 */
export function resolveEffectiveContextTier(
  defaultTier: ContextTier,
  promotableTo: ContextTier,
  complexityLevel: ComplexityLevel,
  contextPromotions?: Partial<Record<ContextTier, ContextTier>>,
): ContextTier;
```

**Default context promotion maps** (to be used until complexity matrix integration in Plan 16-02):

```typescript
export const DEFAULT_CONTEXT_PROMOTIONS: Record<
  ComplexityLevel,
  Partial<Record<ContextTier, ContextTier>> | undefined
> = {
  TRIVIAL: undefined,
  SIMPLE: undefined,
  MODERATE: { T0: "T1", T1: "T2" }, // Context promotes at MODERATE (cognition does NOT)
  COMPLEX: { T0: "T1", T1: "T2", T2: "T3" }, // Both promote at COMPLEX
  CRITICAL: { T0: "T1", T1: "T2", T2: "T3" }, // Both promote at CRITICAL
};
```

Logic: Look up promotions for the complexity level. If the default tier has a promotion, apply it. Cap at `promotableTo` ceiling.

**Verification:**

- [ ] `resolveEffectiveContextTier('T0', 'T1', 'MODERATE')` returns `'T1'`
- [ ] `resolveEffectiveContextTier('T0', 'T0', 'MODERATE')` returns `'T0'` (ceiling blocks)
- [ ] `resolveEffectiveContextTier('T2', 'T3', 'COMPLEX')` returns `'T3'`
- [ ] `resolveEffectiveContextTier('T1', 'T1', 'TRIVIAL')` returns `'T1'` (no promotion)
- [ ] `resolveEffectiveContextTier('T0', 'T1', 'CRITICAL')` returns `'T1'` (capped at ceiling)
- [ ] Imports `ContextTier`, `CONTEXT_TIER_ORDER` from `./types.ts`
