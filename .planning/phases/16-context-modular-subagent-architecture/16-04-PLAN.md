# Plan 16-04: Agent Context Wiring

## Objective

Wire context metadata into all 27 agent `.agent.ts` registry files, adding `context` configuration to each agent's frontmatter object. Also add `<context_isolation>` instruction sections to agents that operate under cold or warm isolation, so the compiled agent `.md` files document their context boundaries. This is the batch-update plan (parallel to Phase 15 Plan 15-04) that applies the context infrastructure from Plans 16-01 and 16-02 to the full agent roster.

## Context

- **Context module types (from 16-01):** `src/context/types.ts` (ContextConfig, contextConfigSchema)
- **Schema integration (from 16-02):** `src/agents/types/agent.schemas.ts` (context field on agentFrontmatterSchema)
- **Compiler (from 16-02):** `src/compilers/claude.compiler.ts` (emits context in YAML frontmatter)
- **Agent files (luca):** `src/agents/luca/lu-executor.agent.ts`, `src/agents/luca/lu-planner.agent.ts`
- **Agent files (general):** `src/agents/general/*.agent.ts` (25 files)
- **Compiled output (generated, do NOT edit directly):** `.claude/agents/*.md`, `.cursor/agents/*.md`
- **Phase 15 precedent:** `.planning/phases/15-cognition-per-agent-audit/15-04-PLAN.md` (batch wiring pattern)
- **16-RESEARCH.md agent tier table:** Default context tiers, promotable_to, and isolation modes for all agents

## Design Constraints

- **All 27 `.agent.ts` files need `context` metadata** in their `frontmatter` object
- **7 agents need `<context_isolation>` sections** (cold: 5 reviewers, warm: 1 verifier, plus code-developer)
- **Batch efficiency:** Group changes by isolation mode (all cold agents together, warm, then none)
- **No breaking changes:** The `context` field is optional with defaults per Plan 16-02
- **Edit source files ONLY:** Never edit compiled `.claude/agents/*.md` or `.cursor/agents/*.md`

For each file, add the `context` field to the frontmatter object, alongside the existing `cognition` field:

```typescript
frontmatter: {
  name: 'agent-name',
  description: `...`,
  color: '...',
  cognition: {
    default_tier: 'T2',
    promotable_to: 'T3',
    memory_tags: ['coding', 'patterns', 'pitfalls', 'conventions'],
  },
  context: {
    default_tier: 'T2',
    promotable_to: 'T3',
    isolation: 'none',
  },
},
```

**Important:** Note that context tiers and cognition tiers may differ for the same agent. The context tier controls what DOCUMENTS the agent receives. The cognition tier controls what MEMORY FEATURES the agent uses. They are independently tracked and independently promoted by complexity gating.

### Task 2: Add Context Isolation Sections to Cold-Isolation Agent Source Files

**Goal:** Add `<context_isolation>` sections to the 5 cold-isolation agent `.agent.ts` source files that explain their context boundaries in the compiled output.

**Files:** 5 agent files: `dx-advocate.agent.ts`, `code-simplifier.agent.ts`, `code-architect.agent.ts`, `security-auditor.agent.ts`, `performance-auditor.agent.ts`

For each file, insert a `<context_isolation>` section into the `sections[0].content` template literal. Insert AFTER the `<role>` section (or opening section) and BEFORE the first operational instruction.

**Template for cold isolation agents:**

```xml
<context_isolation>
## Context Isolation: COLD

You operate in **cold isolation** to prevent bias from executor session context.

**You receive:**
- Git diff of changed files
- BRAIN.md summary (project conventions)

**You do NOT receive:**
- STATE.md (project state)
- WORKING.md (executor session notes)
- MEMORY.md (historical patterns/decisions)
- Agent summaries from other sub-agents

**Why:** Fresh perspective produces better reviews. Your judgment should be based solely on the code diff and project conventions, not influenced by the executor's reasoning or session history.
</context_isolation>
```

### Task 3: Add Context Isolation Section to Warm-Isolation Agent (lu-verifier)

**Goal:** Add `<context_isolation>` section to lu-verifier that documents warm isolation.

**File:** `src/agents/general/lu-verifier.agent.ts`

Insert a `<context_isolation>` section into the `sections[0].content` template literal, after the existing `<cognition_integration>` section:

```xml
<context_isolation>
## Context Isolation: WARM

You operate in **warm isolation** to separate verification from execution bias.

**You receive:**
- Plan contents and plan summaries
- BRAIN.md summary (project conventions)
- STATE.md (project state)
- Selective MEMORY.md entries (at T2+, filtered by your memory_tags)

**You do NOT receive:**
- WORKING.md (executor session notes)
- Full MEMORY.md (at T1, only selective entries at T2)

**Why:** You verify whether the PLAN GOALS were achieved, not whether the executor's APPROACH was good. Receiving WORKING.md would bias you toward confirming the executor's narrative rather than independently verifying outcomes.
</context_isolation>
```
