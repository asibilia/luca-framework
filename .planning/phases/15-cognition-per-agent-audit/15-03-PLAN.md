# Plan 15-03: Cognition Agent & Tag System

## Objective

Update lu-cognition's selective recall algorithm to support tier-aware filtering and tag-based MEMORY.md recall. Update lu-learner's extraction template to include domain tags on new entries. Define the formal tag vocabulary. These changes implement the runtime cognition behavior that uses the schema infrastructure from Plan 15-02.

## Design Decisions

- **Decision 4 (from 15-CONTEXT.md):** Tag-based filtering with semi-fixed vocabulary. lu-learner can add new tags.
- **Backward compatibility:** Entries without `Tags:` field are included in ALL agent recalls (legacy treatment)
- **Tag vocabulary is coarse-grained:** 14 domain tags, not fine-grained keywords. Keyword scoring handles specificity.
- **Context budget per tier:** T1: 3-5 entries, T2: 5-7 entries, T3: 7-10 entries

## Tasks

### Task 1: Define Tag Vocabulary Document

**Goal:** Create a formal reference document defining all 14 domain tags with descriptions, examples, and usage guidelines.
**Output:** `.planning/phases/15-cognition-per-agent-audit/TAG-VOCABULARY.md`

Define these 14 tags:

| Tag            | Domain                                   | Matches Entries About                                        |
| -------------- | ---------------------------------------- | ------------------------------------------------------------ |
| `coding`       | Code patterns, implementation approaches | Implementation techniques, code structure, refactoring       |
| `patterns`     | Validated development patterns           | Proven approaches, architectural patterns, design patterns   |
| `pitfalls`     | Known issues and gotchas                 | Bugs encountered, failure modes, things that break           |
| `conventions`  | Project conventions                      | Naming, formatting, API conventions, coding standards        |
| `architecture` | System design and structure              | Component design, layering, module boundaries                |
| `planning`     | Plan structure and validation            | Wave structure, plan-checker findings, dependency management |
| `verification` | Testing and verification                 | Verification pipeline, signal tiers, quality gates           |
| `testing`      | Test patterns and tooling                | Test frameworks, test strategies, bun test patterns          |
| `debugging`    | Bug investigation patterns               | Debug strategies, root cause analysis, hypothesis testing    |
| `stack`        | Technology choices                       | Bun, TypeScript, framework decisions, library selection      |
| `security`     | Security patterns and concerns           | Input validation, credential handling, injection prevention  |
| `performance`  | Performance optimization                 | Startup time, bundle size, lazy loading, caching             |
| `decisions`    | Architectural decisions                  | Past choices with rationale, trade-off analysis              |
| `complexity`   | Complexity gating system                 | Tier mapping, gating rules, agent scaling                    |

Include guidelines for lu-learner:

- Assign 1-3 tags per entry (prefer fewer, more relevant tags)
- Use existing vocabulary first; only propose new tags when no existing tag fits
- Tags describe the DOMAIN of the knowledge, not the specific content
- Entries can belong to multiple domains (e.g., a security pattern gets `[security, patterns]`)

### Task 2: Update lu-cognition Selective Recall Algorithm

**Goal:** Modify lu-cognition's selective recall step to support tier-aware gating and tag-based filtering.
**File:** `src/agents/general/lu-cognition.agent.ts` (modify the `sections[0].content` template literal)

**IMPORTANT:** Edit the TypeScript source file, NOT the compiled `.claude/agents/lu-cognition.md`. After completing changes, run `bun run build:all` to regenerate the compiled output.

Add a new step BEFORE the existing `selective_recall` step:

**New Step: `resolve_cognition_tier`**

```
1. Read target agent's compiled .md file from .claude/agents/
2. Parse YAML frontmatter for cognition config
   - If no frontmatter or no cognition field: treat as T0 (default behavior)
3. Extract: default_tier, promotable_to, memory_tags
4. Read current complexity from STATE.md "Task Complexity:" field
   - If not set, default to MODERATE
5. Apply complexity-driven promotion:
   - Look up cognitionPromotions for current complexity level
   - Promote default_tier if mapping exists
   - Cap at promotable_to ceiling
6. Store effective_tier for use in selective_recall
```

**Modify existing `selective_recall` step:**

```
IF effective_tier == T0:
    SKIP recall entirely
    Output minimal report: "Agent [name] is T0 (stateless) — no memory recall"
    RETURN

# Tag-based pre-filtering (NEW)
agent_memory_tags = agent.cognition.memory_tags
IF agent_memory_tags is empty OR agent_memory_tags contains "*":
    candidate_entries = all_entries  # No filtering (wildcard or no tags)
ELSE:
    candidate_entries = entries.filter(entry =>
        entry has Tags field AND entry.tags intersects agent_memory_tags
        OR entry has NO Tags field  # Legacy backward compatibility
    )

# Existing keyword + agent scoring (UNCHANGED, but operates on filtered set)
scored = score_entries(candidate_entries, task_keywords, target_agent)

# Tier-scaled entry limits (NEW)
IF effective_tier == T1: select top 3-5 entries
IF effective_tier == T2: select top 5-7 entries
IF effective_tier == T3: select top 7-10 entries
```

**Key constraints:**

- Do NOT remove or renumber existing steps
- Insert the new step using the established pattern (new section, clear numbering)
- Maintain backward compatibility: agents without frontmatter default to T0 (which matches current behavior where most agents get no memory recall)

### Task 3: Update lu-learner Extraction Template

**Goal:** Add `Tags:` field to lu-learner's extraction template so new MEMORY.md entries are tagged at write time.
**File:** `src/agents/general/lu-learner.agent.ts` (modify the `sections[0].content` template literal)

**IMPORTANT:** Edit the TypeScript source file, NOT the compiled `.claude/agents/lu-learner.md`. After completing changes, run `bun run build:all` to regenerate the compiled output.

Modify the extraction template (in the `extract_*` steps) to include:

```markdown
#### [Entry Title]

- **Pattern/Decision/Pitfall**: [Description]
- **When to use**: [Context]
- **Agent**: [agent name]
- **Relevant to**: [list of agents]
- **Tags**: [domain tags from vocabulary]
- **Confidence**: [High/Medium/Low]
```

Add instructions for lu-learner on tag assignment:

- Reference the TAG-VOCABULARY.md for valid tags

- Tags describe the knowledge domain, not the specific content
- If no existing tag fits, propose a new tag with justification (lu-learner can extend vocabulary)
- Always include the most specific matching tag

### Task 4: Update lu-cognition WORKING.md Tier-Aware Output

**Goal:** Update lu-cognition's cognitive report output format to include tier information.
**File:** `src/agents/general/lu-cognition.agent.ts` (modify the `sections[0].content` template literal)

**IMPORTANT:** Edit the TypeScript source file, NOT the compiled `.claude/agents/lu-cognition.md`. After completing changes, run `bun run build:all` to regenerate the compiled output.

Modify the cognitive report output (the document lu-cognition produces for the target agent) to include:

1. **Tier resolution section** at the top of the report:

   ```
   ## Cognition Profile
   - Agent: [name]
   - Default Tier: [T0-T3]
   - Effective Tier: [T0-T3] (after complexity promotion)
   - Complexity Level: [TRIVIAL-CRITICAL]
   - Memory Tags: [list]
   - Entries Recalled: [count]
   ```

2. **Tier-specific content sections:**
   - T1: Include `### Relevant Context` with recalled patterns/decisions/pitfalls
   - T2: Everything from T1 PLUS `### Session Tracking` instructions (write to WORKING.md)
   - T3: Everything from T2 PLUS `### Project Identity` (BRAIN.md summary) and `### Learning Instructions` (write candidate entries)

3. **WORKING.md integration instructions for T2+ agents:**
   ```
   ### Session Tracking (T2+)
   During execution, append findings to WORKING.md:
   - Code observations and unexpected behaviors
   - Decisions made during implementation
   - Candidate patterns/pitfalls for MEMORY.md
   ```
