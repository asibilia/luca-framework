# Plan 07-03: Error Handling Standardization

## Frontmatter
- **ID**: 07-03
- **Title**: Error Handling Standardization
- **Wave**: 2
- **Depends on**: 07-01

## Objective

Standardize error handling across the codebase by adopting the `AdapterResult<T>` discriminated union pattern as the canonical result type. Currently, `src/shared/validation-utils.ts` returns `{ success: boolean; data?: T; error?: string }` which prevents TypeScript from narrowing the type -- both `data` and `error` remain optional in both branches. Additionally, `packages/luca-framework/src/utils/files.ts` uses `{ success: true, manifest }` instead of the standard `{ success: true, data: manifest }`. This plan introduces a shared `Result<T>` type and migrates all result-returning functions to use it.

## Context

- `packages/luca-framework/src/contracts/work-tracker.ts` -- canonical `AdapterResult<T>` definition (lines 64-66): `{ success: true; data: T } | { success: false; error: string }`
- `src/shared/validation-utils.ts` -- 4 functions with weak `{ success: boolean }` return types (lines 88, 110, 119, 128)
- `packages/luca-framework/src/utils/files.ts` -- `generateFiles()` returns `{ success: boolean; manifest?: LucaManifest; error?: string }` (line 122), and line 219 returns `{ success: true, manifest }` instead of `{ success: true, data: manifest }`
- `packages/luca-framework/src/utils/sanitize.ts` -- `safeSanitizeJsonParse()` returns `{ success: boolean; data?: unknown; error?: string }` (line 55)
- `packages/luca-framework/src/commands/init.ts` -- potential call site for `generateFiles()` that may destructure `manifest`
- `.planning/phases/07-architecture/07-RESEARCH.md` -- Finding #5 (MEDIUM severity), Error Handling Patterns section

## Tasks

### Task 1: Define a shared `Result<T>` type in `src/shared/`

**Goal**: Create a reusable discriminated union result type that follows the `AdapterResult<T>` pattern established in the adapter layer. This type will be used by all result-returning functions in the `src/` domain.

**File:** `src/shared/types.ts` (new file)

**Changes:**
1. Create `src/shared/types.ts` with the following content:
```typescript
/**
 * Discriminated union for operation results.
 *
 * Follows the AdapterResult<T> pattern from packages/luca-framework/src/contracts/work-tracker.ts.
 * Use this type for any function that can succeed with data or fail with an error message.
 *
 * @example
 * ```typescript
 * function parseConfig(input: string): Result<Config> {
 *   try {
 *     const data = JSON.parse(input);
 *     return { success: true, data };
 *   } catch (error) {
 *     return { success: false, error: error.message };
 *   }
 * }
 *
 * const result = parseConfig(rawInput);
 * if (result.success) {
 *   // TypeScript narrows: result.data is Config
 *   console.log(result.data);
 * } else {
 *   // TypeScript narrows: result.error is string
 *   console.error(result.error);
 * }
 * ```
 */
export type Result<T> =
  | { success: true; data: T }
  | { success: false; error: string }
```

2. Export from root `index.ts` -- this will be handled in Plan 07-04 (Public API Surface Cleanup). For now, the type is importable directly from `src/shared/types.ts`.

**Verification:**
- File exists at `src/shared/types.ts`
- The type matches the `AdapterResult<T>` shape from `packages/luca-framework/src/contracts/work-tracker.ts`
- `bunx tsc --noEmit` passes
