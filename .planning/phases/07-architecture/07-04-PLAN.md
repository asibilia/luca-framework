# Plan 07-04: Public API Surface Cleanup

## Frontmatter
- **ID**: 07-04
- **Title**: Public API Surface Cleanup
- **Wave**: 2
- **Depends on**: 07-01, 07-03

## Objective

Replace `export *` in the root `index.ts` with explicit named exports to establish an intentional public API surface. Currently, `export *` re-exports everything from every referenced module, including Zod schema type re-exports (`AgentFrontmatterSchema`, `AgentSectionSchema`, etc.), internal formatting utilities (`formatFrontmatter`), and internal helpers (`stripPrototypeKeys` is private but `sanitizeJsonParse` is not clearly public-facing). This makes the public API boundary undefined -- consumers may depend on any export, making internal changes risky. Also clean up the `export *` in the doctor checks index.

### Task 1: Replace `export *` with explicit named exports in root `index.ts`

**Goal**: Define an intentional public API by listing every exported symbol explicitly. This prevents accidental exposure of internal implementation details (Zod schema types, `formatFrontmatter`, etc.) and makes the public contract clear. Consumers should only depend on the explicitly listed exports.

**File:** `index.ts` (project root)

**Changes:**
Replace the entire file contents with explicit named exports organized by category:

```typescript

 * Main entry point for the Luca Framework compiler system

 * This file defines the intentional public API surface.
 * Only symbols listed here are part of the public contract.
 */
```

### Task 3: Verify imports resolve across the codebase

**Goal**: Ensure that all internal code that imports from the root `index.ts` (or from the modules it re-exports) still resolves correctly after switching to explicit exports. The main concern is any code that imports Zod schema types or `formatFrontmatter` via the root barrel -- these imports would now break and need to be updated to import directly from the source module.

**File:** N/A (verification and fixup task)

**Changes:**
1. Run `bunx tsc --noEmit` to detect any broken imports
2. Search for imports of the now-excluded symbols from the root:
   - `grep -r "from '.*index'" src/ scripts/ __tests__/` to find all barrel imports
   - `grep -r "AgentFrontmatterSchema\|AgentSectionSchema\|AgentConfigSchema" src/ scripts/ __tests__/` to find Zod schema type usage
   - `grep -r "SkillFrontmatterSchema\|SkillSectionSchema\|SkillConfigSchema" src/ scripts/ __tests__/`
   - `grep -r "RuleFrontmatterSchema\|RuleSectionSchema\|RuleConfigSchema" src/ scripts/ __tests__/`
   - `grep -r "formatFrontmatter" src/ scripts/ __tests__/` to find internal utility usage
3. For any broken import found:
   - If the import was from the root index (`from '../..'` or `from 'luca-framework'`), update it to import directly from the source module (e.g., `from '../agents/types/agent.schemas'` or `from '../../shared/utils'`)
   - If the import was already direct (not through the barrel), no change needed

**Important note:** Internal code within `src/` already imports directly from source modules (e.g., `base-agent.ts` imports from `../types/agent.types`), so most internal code should be unaffected. The main risk is in test files or scripts that might import from the root.
