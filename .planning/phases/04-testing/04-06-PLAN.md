# Plan 04-06: Doctor Subsystem Tests

## Frontmatter
- **ID**: 04-06

- **Wave**: 3

## Objective

Write unit tests for the doctor subsystem: the `executeDoctor()` executor function and its three individual checks (`nodeVersionCheck`, `cursorIdeCheck`, `configValidationCheck`). Each check depends on different system state (Node version, filesystem paths, process.platform), so tests require careful mocking of process globals and filesystem access.

## Context

- `packages/luca-framework/src/utils/doctor/index.ts` -- `executeDoctor()` runs all checks in parallel, formats output, returns exit code (0 or 1)
- `packages/luca-framework/src/utils/doctor/types.ts` -- `CheckResult` (`{ name, status, message, fixCommand, details }`), `DoctorCheck` (`{ name, run() }`)
- `packages/luca-framework/src/utils/doctor/checks/node-version.ts` -- `nodeVersionCheck` reads `process.version`, checks `>= 18`
- `packages/luca-framework/src/utils/doctor/checks/cursor-ide.ts` -- `cursorIdeCheck` checks `existsSync` at platform-specific paths, reads `process.platform` and `process.env.HOME`
- `packages/luca-framework/src/utils/doctor/checks/config-validation.ts` -- `configValidationCheck` reads `.planning/config.json` and `.planning/manifest.json` via `existsSync` and `readFile`
- `packages/luca-framework/src/utils/logger.ts` -- used by executor (mock to silence output)
- `__tests__/utils/temp-dir.ts` -- for config-validation check filesystem tests (from 04-01)
- `__tests__/utils/fixtures.ts` -- `validPlanningConfig` (from 04-01)

## Tasks

### Task 1: Node Version Check Tests
**Goal**: Test `nodeVersionCheck` with various Node.js version strings.
**Files**: Create `__tests__/packages/luca-framework/src/utils/doctor/checks/node-version.test.ts`
**Details**:

The node version check reads `process.version`. To test different versions, we need to temporarily override `process.version`. Since `process.version` is read-only in modern Node/Bun, use `Object.defineProperty` to override it in tests:

```typescript
import { describe, test, expect, beforeEach, afterEach } from 'bun:test';

let originalVersion: string;

beforeEach(() => {
  originalVersion = process.version;
});

afterEach(() => {
  Object.defineProperty(process, 'version', {
    value: originalVersion,
    writable: true,
    configurable: true,
  });
});

function setNodeVersion(version: string) {
  Object.defineProperty(process, 'version', {
    value: version,
    writable: true,
    configurable: true,
  });
}
```

Since `nodeVersionCheck` references `this.name` internally, import and call it correctly:

```typescript
import { nodeVersionCheck } from '../../../../../../../packages/luca-framework/src/utils/doctor/checks/node-version';
```

**Test cases:**

1. **Node 22 (pass)**: Set `'v22.0.0'`. Call `nodeVersionCheck.run()`. Assert:
   - `result.status === 'pass'`
   - `result.message` contains `'v22.0.0'`
   - `result.fixCommand === null`

2. **Node 20 (pass)**: Set `'v20.11.0'`. Assert `status === 'pass'`.

3. **Node 18 (pass -- boundary)**: Set `'v18.0.0'`. Assert `status === 'pass'`.

4. **Node 16 (fail)**: Set `'v16.20.2'`. Assert:
   - `result.status === 'fail'`
   - `result.message` contains `'v16.20.2'`
   - `result.fixCommand` is a string (contains install instructions)
   - `result.details` contains `'18 or later'`

5. **Node 14 (fail)**: Set `'v14.0.0'`. Assert `status === 'fail'`.

6. **Result name**: Assert `result.name === 'Node.js Version'`.

**Verification**: `bun test __tests__/packages/luca-framework/src/utils/doctor/checks/node-version.test.ts` -- all tests pass.

### Task 2: Cursor IDE Check Tests
**Goal**: Test `cursorIdeCheck` across different platforms and installation states.
**Files**: Create `__tests__/packages/luca-framework/src/utils/doctor/checks/cursor-ide.test.ts`
**Details**:

This check reads `process.platform`, `process.env.HOME`, and calls `existsSync`. Since `process.platform` is read-only, use `Object.defineProperty`. For `existsSync`, use `mock.module('fs', ...)` to control which paths "exist".

```typescript
import { describe, test, expect, mock, beforeEach, afterEach } from 'bun:test';
```

For each test, mock `fs` module's `existsSync` and override `process.platform`:

```typescript
let originalPlatform: string;
let originalHome: string | undefined;

beforeEach(() => {
  originalPlatform = process.platform;
  originalHome = process.env.HOME;
});

afterEach(() => {
  Object.defineProperty(process, 'platform', { value: originalPlatform, configurable: true });
  process.env.HOME = originalHome;
});

function setPlatform(platform: string) {
  Object.defineProperty(process, 'platform', { value: platform, configurable: true });
}
```

**Test cases:**

1. **macOS with Cursor installed in /Applications**: Set platform to `'darwin'`. Mock `existsSync('/Applications/Cursor.app')` to return `true`. Assert:
   - `result.status === 'pass'`
   - `result.message` contains `'detected'`
   - `result.details` contains `'Found Cursor.app'`

2. **macOS with Cursor in ~/Applications**: Set `process.env.HOME = '/Users/test'`. Mock `existsSync('/Users/test/Applications/Cursor.app')` returns true, `/Applications/Cursor.app` returns false. Assert `status === 'pass'`.

3. **macOS without Cursor**: Mock both macOS paths return false. Assert:
   - `result.status === 'warning'` (not fail -- Cursor is recommended, not required)
   - `result.fixCommand` contains `'cursor.sh'`

4. **Windows with Cursor installed**: Set platform to `'win32'`, set `process.env.LOCALAPPDATA = 'C:\\Users\\test\\AppData\\Local'`. Mock `existsSync` for Windows path returns true. Assert `status === 'pass'`.

5. **Windows without Cursor**: Mock returns false. Assert `status === 'warning'`.

6. **Linux with Cursor in /usr/bin**: Set platform to `'linux'`. Mock `/usr/bin/cursor` returns true. Assert `status === 'pass'`.

7. **Linux without Cursor**: Mock both Linux paths return false. Assert `status === 'warning'`.

8. **Result name**: Assert `result.name === 'Cursor IDE'`.

**Verification**: `bun test __tests__/packages/luca-framework/src/utils/doctor/checks/cursor-ide.test.ts` -- all tests pass.

### Task 3: Config Validation Check Tests
**Goal**: Test `configValidationCheck` with various filesystem states. Use real temp directories.
**Files**: Create `__tests__/packages/luca-framework/src/utils/doctor/checks/config-validation.test.ts`
**Details**:

The config validation check reads `process.cwd()` to find `.planning/config.json` and `.planning/manifest.json`. Override `process.cwd` to point to a temp directory:

```typescript
import { describe, test, expect, beforeEach, afterEach, spyOn } from 'bun:test';
import { setupTempProject, cleanupTempDir } from '../../../../../../utils/temp-dir';
import { validPlanningConfig } from '../../../../../../utils/fixtures';
```

```typescript
let tempDir: string;
let cwdSpy: ReturnType<typeof spyOn>;

beforeEach(async () => {
  tempDir = await createTempDir();
  cwdSpy = spyOn(process, 'cwd').mockReturnValue(tempDir);
});

afterEach(async () => {
  cwdSpy.mockRestore();
  await cleanupTempDir(tempDir);
});
```

**Test cases:**

1. **config.json missing**: Empty temp dir (no `.planning/`). Assert:
   - `result.status === 'fail'`
   - `result.message` contains `'missing'`
   - `result.fixCommand` contains `'npx luca init'`

2. **config.json invalid JSON**: Create `.planning/config.json` with `'not-json'`. Assert:
   - `result.status === 'fail'`
   - `result.message` contains `'unreadable'`

3. **config.json missing required fields**: Create with `{ "stack": "react-ts" }` (missing `branding` and `workTracker`). Assert:
   - `result.status === 'fail'`
   - `result.message` contains `'invalid'`
   - `result.details` contains `'branding'` and `'workTracker'`

4. **Valid config but missing manifest**: Create `.planning/config.json` with `validPlanningConfig` but no manifest.json. Assert:
   - `result.status === 'warning'`
   - `result.message` contains `'manifest.json missing'`
   - `result.fixCommand` contains `'--repair'`

5. **All valid (config + manifest)**: Create both `.planning/config.json` and `.planning/manifest.json`. Assert:
   - `result.status === 'pass'`
   - `result.message` contains `'valid'`
   - `result.details` contains `'react-ts'` and `'github'` (from validPlanningConfig)

6. **Result name**: Assert `result.name === 'Config Validation'`.

**Verification**: `bun test __tests__/packages/luca-framework/src/utils/doctor/checks/config-validation.test.ts` -- all tests pass.

### Task 4: Doctor Executor Tests
**Goal**: Test `executeDoctor()` -- the orchestrator that runs all checks and computes exit codes.
**Files**: Create `__tests__/packages/luca-framework/src/utils/doctor/executor.test.ts`
**Details**:

The executor dynamically imports its checks. Rather than trying to mock the dynamic imports (which is fragile with `mock.module()` path resolution), use a more robust approach: mock the **underlying system dependencies** that the checks use, then let the real checks run with controlled inputs. This mirrors the approach used in Tasks 1-3 and avoids dynamic import interception issues.

```typescript
import { describe, test, expect, mock, beforeEach, afterEach } from 'bun:test';
```

**Mocking approach**: Mock the system-level dependencies that the individual checks rely on:
- `process.version` for the Node version check
- `fs.existsSync` for the Cursor IDE and config validation checks
- `process.cwd()` for config validation (point to a temp dir)
- `process.platform` for Cursor IDE check
- Logger to silence output

```typescript
// Save originals
const originalVersion = process.version;
const originalPlatform = process.platform;
const originalCwd = process.cwd;

// Mock logger to silence output
mock.module('../../../../../../packages/luca-framework/src/utils/logger', () => ({
  logger: { info: () => {}, success: () => {}, error: () => {}, warn: () => {}, box: () => {} },
}));

// Import temp dir helper for config validation tests
import { setupTempProject, cleanupTempDir } from '../../utils/temp-dir';
```

For "all checks pass" scenarios: set `process.version` to a valid version, create a temp dir with valid config.json and manifest, and ensure Cursor IDE detection passes (mock `existsSync` for the Cursor app path).

For "failure" scenarios: set `process.version` to `'v16.0.0'` (Node check fails), or point `process.cwd()` to an empty temp dir (config check fails).

Then dynamically import the executor AFTER setting up mocks:
```typescript
const { executeDoctor } = await import('../../../../../../packages/luca-framework/src/utils/doctor/index');
```

**Important**: Restore all original values in `afterEach` to prevent test pollution.

**Test cases:**

1. **All checks pass**: All three mocked to return `status: 'pass'`. Assert `exitCode === 0`.

2. **One check fails**: Node version returns `'fail'`, others pass. Assert `exitCode === 1`.

3. **Warnings only (no failures)**: All return `'warning'`. Assert `exitCode === 0` (warnings don't cause failure).

4. **Mixed results (fail + warning + pass)**: Assert `exitCode === 1` (any failure causes exit 1).

5. **All checks fail**: Assert `exitCode === 1`.

6. **Fix suggestions shown for failed checks**: Mock a check with `fixCommand: 'run this'`. Verify the executor doesn't throw (output verification is secondary -- the key behavior is the return code).

**Verification**: `bun test __tests__/packages/luca-framework/src/utils/doctor/executor.test.ts` -- all tests pass.
