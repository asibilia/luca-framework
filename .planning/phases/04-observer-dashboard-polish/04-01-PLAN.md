# Phase 4 Plan 01: Standardize Loading States with LoadingSkeleton

## Objective

Replace the remaining inline loading patterns with the reusable `LoadingSkeleton` component so every page has consistent, accessible loading UI. The `LoadingSkeleton` component already exists with 4 variants (card, table, chart, text) and proper `role="status"` / `aria-busy` accessibility attributes.

## Context

@packages/luca-observer/components/shared/loading-skeleton.tsx
@packages/luca-observer/app/workflow/page.tsx
@packages/luca-observer/app/memory/page.tsx
@packages/luca-observer/app/tribunal/page.tsx
@packages/luca-observer/app/cost/page.tsx

## Current State Assessment

After code review, the situation is better than initially described:

1. **All 8 loading.tsx files** (agents, harness, iterations, memory, notes, planning, tribunal, workflow) already import and use `LoadingSkeleton`. No inline `animate-pulse` divs in loading.tsx files.
2. **workflow/page.tsx line 40**: Uses inline `<p className="... animate-pulse">Loading state...</p>` for the state diagram loading state instead of `LoadingSkeleton`.
3. **memory/page.tsx line 22**: Uses `<EmptyState message="Loading memory files..." />` as a loading indicator instead of `LoadingSkeleton`.
4. **tribunal/page.tsx line 28**: Uses `<EmptyState message="Loading tribunal data..." />` as a loading indicator instead of `LoadingSkeleton`.
5. **cost/page.tsx**: Already uses `LoadingSkeleton` correctly for its loading state.

The scope is narrow: 3 files need their client-side loading states updated from `EmptyState`/inline to `LoadingSkeleton`.
