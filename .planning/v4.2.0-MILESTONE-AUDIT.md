### Security (security-auditor)

| Finding                                                                | Severity | Fix                                                                     |
| ---------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------- |
| No vault name validation in init-vault `--vault` argument              | MEDIUM   | Add regex guard `/^[a-z0-9][a-z0-9_-]{0,63}$/` before writing to config |
| No MUNINN_DB_URL validation — potential SSRF during connectivity check | MEDIUM   | Validate URL protocol is http/https before fetch                        |
| API key leaks to untrusted host if MUNINN_DB_URL is misconfigured      | LOW      | Validate target URL before attaching Authorization header               |
| Fragile grep-based config.json parsing in vault resolution             | LOW      | Consider `bun -e` JSON parsing for robustness                           |
| Silent config.json overwrite on corruption                             | LOW      | Log warning before defaulting to empty config                           |

**Positive security findings:** API keys stored in .env (gitignored), sanitizeJsonParse strips prototype pollution, set-field uses allowlist, vault name is URL-encoded in API calls, no secrets in config.json.
