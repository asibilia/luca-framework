## Context

The eval reporter transforms EvalReport objects into human-readable and machine-readable output formats: JSON files, markdown summaries, and colorized console output.

**Implementation details for `writeJsonReport`:**

1. Compute dir: `.planning/evals/${report.component}/`
2. Create directory if it doesn't exist: `await Bun.write(dirPath + ".gitkeep", "")` then mkdir via `import { mkdir } from "node:fs/promises"`.
3. Write JSON: `await Bun.write(filePath, JSON.stringify(report, null, 2))`
4. Update `latest.json`: Write the same content to `${dirPath}/latest.json` (not a symlink -- just a copy, since symlinks can cause issues on Windows and in git).

**Implementation details for `formatMarkdownReport`:**

1. Group results by `case_id`.
2. For each case, compute per-case pass@1 (any trial passed) and average score.
3. Build the markdown tables as shown in the JSDoc.
4. In the "Failures" section, only include cases where pass@1 is false.

**Implementation details for `printConsoleReport`:**

- ANSI codes: `\x1b[32m` (green), `\x1b[31m` (red), `\x1b[33m` (yellow), `\x1b[1m` (bold), `\x1b[0m` (reset).
- Use `console.log` for output.
- Group results by case_id, show summary line per case.
- When `verbose` is false, only show failing cases after the summary metrics.

**Implementation details for `loadLatestReport` and `loadReport`:**

- Use `Bun.file(path).exists()` to check existence.
- Use `Bun.file(path).json()` to read and parse.
- Wrap in try/catch, return null on any error.

## Notes

- The `.planning/evals/` directory is NOT gitignored by default. The implementing agent should add `.planning/evals/` to `.gitignore` if it is not already there.
- Reports use `Bun.write` and `Bun.file` per project conventions (prefer Bun APIs over node:fs).
- The `latest.json` is a file copy, not a symlink. This avoids cross-platform symlink issues.
