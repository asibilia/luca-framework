# Todo Gap Analysis: Brainstorm vs Pending Todos

Generated by lu-implementation-researcher for the studio-cleanup team.

## Executive Summary

The brainstorm documents (0-9) describe a comprehensive plan to merge Luca Observer and the planned Luca Studio into a single Next.js 15 app called **Luca Studio**. The existing pending todos (runtime-d01 through runtime-d11) describe building a **standalone Bun.serve() vanilla HTML/CSS/JS package** — a fundamentally different architecture that was explicitly rejected in the brainstorm.

**Critical finding:** All 11 D-series todos target the wrong architecture. They must be either retired or rewritten to target the Next.js absorption approach. Beyond this architectural mismatch, there are **27 distinct work items** from the brainstorm that have no corresponding pending todo.

### Gap 1.1: D-Series Todos Target Wrong Architecture

**What the brainstorm decided (0.overview.md):**

- **Overlap:** The D-series FEATURES (agent browser, DAG viz, state inspector, eval viewer, SSE, file watcher) are still needed — but implemented in React/Next.js, not vanilla JS.

### Gap 4.1: SSE Event Stream Route

**Source:** 4.technical-architecture.md, 6.research-architecture.md (R1, R4)

## Category 5: State Management

### Gap 5.1: Three-Layer Jotai Atom Model

**Source:** 4.technical-architecture.md, 9.research-frontend-tech.md (R12)
**Description:** Implement the three-layer atom architecture:

- **Layer 1 (Server State):** `configAtom`, `agentRegistryAtom`, `routingTableAtom`, `stateAtom` — read-only mirrors of disk state
- **Layer 2 (Draft State):** `configDraftAtom`, `agentDraftAtom(name)` via `atomFamily`, `routingDraftAtom` — writable copies for editing
- **Layer 3 (Dirty Tracking):** `dirtySetAtom` (Set<string>), `canSaveAtom` (derived), `validationErrorsAtom` (Map<string, ZodError[]>)

Uses `atomFamily` for per-entity independent atom trees. Concurrent multi-entity editing works naturally.
**Priority:** P1 — Required for any editing functionality.
**Size:** M (4-6 hours)
**Dependencies:** Gap 2.2 (jotai-history for undo/redo)
**Existing todo overlap:** None. Existing Observer uses Jotai (vault.ts) but for read-only state only.

### Gap 5.2: Undo/Redo with jotai-history

**Source:** 2.ux-design.md, 4.technical-architecture.md, 9.research-frontend-tech.md (R12)
**Description:** Per-entity undo/redo using `withHistory(targetAtom, 50)` from `jotai-history`. Exports UNDO, REDO, RESET action constants and `canUndo`/`canRedo` derived atoms. Max 50 entries per entity.
**Priority:** P2 — Enhancement to editing, not blocking for initial launch.

## Category 8: Editing Infrastructure

### Gap 8.1: ETag-Based Optimistic Locking

**Source:** 4.technical-architecture.md
**Description:** Concurrency control for all write routes:

- Every GET response includes `ETag: sha256(file_contents).substring(0, 16)`
- Every PUT/PATCH includes `If-Match: <etag>`
- API reads current file, computes hash, rejects with `409 Conflict` if diverged
- On 409, UI shows diff of external change via DiffPreview component
  **Priority:** P2 — Important for correctness but can ship without initially.
  **Size:** S (3-4 hours, middleware pattern reusable across routes)
  **Dependencies:** Gap 7.2 (DiffPreview component for conflict UI)
  **Existing todo overlap:** None

### Gap 8.2: Validation Pipeline

**Source:** 4.technical-architecture.md
**Description:** Three-step validation for every write:

1. Schema parse: `safeParse()` against Zod schema, reject 422 with structured errors
2. Semantic validation: DAG cycle detection, nonexistent agent references, disabled parser references, required gates, model routing coverage
3. Atomic write: Write to `.tmp` sibling, then `rename()` into place
   **Priority:** P1 — Required for safe writes.
   **Size:** M (4-6 hours)
   **Dependencies:** Existing Zod schemas in `src/` domains
   **Existing todo overlap:** None

### Gap 8.3: Pre-Write Type Check

**Source:** 4.technical-architecture.md
**Description:** After writing TypeScript entity file, sidecar runs `bunx --bun tsc --noEmit <filepath>`. If fails, API returns TypeScript errors in response body. File still written (user can iterate) but compilation blocked until errors resolved.
**Priority:** P2 — Quality guard for entity editing.
**Size:** S (2-3 hours)
**Dependencies:** Gap 2.3 (compilation sidecar)
**Existing todo overlap:** None

### Gap 8.4: Git Rollback (Batch-Commit-on-Publish)

**Source:** 4.technical-architecture.md, 9.research-frontend-tech.md (R13)
**Description:**

- Batch commit on **publish** (not every save) with `[studio-edit]` prefix
- "Config History" view: `git log --grep="[studio-edit]"` for listing
- "Revert to version": `git checkout <sha> -- <file>` for per-file rollback
- Uses `Bun.$` shell commands — no new dependencies
  **Priority:** P3 — Nice-to-have, not required for initial editing.
  **Size:** M (4-6 hours)
  **Dependencies:** None
