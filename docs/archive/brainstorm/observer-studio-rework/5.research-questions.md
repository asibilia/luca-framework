# Research Questions: Luca Studio

Open questions for the research team to investigate before finalizing the implementation plan.

## Architecture

### R1: Next.js SSE Viability

- Can Next.js App Router API routes reliably maintain long-lived SSE connections?
- What are the known limitations (connection timeouts, proxy behavior, serverless deployment)?
- Should we use a custom Next.js server or a sidecar for SSE?
- How does this behave in `next dev` vs `next start` (standalone)?

### R2: Compilation Sidecar Design

- What's the best IPC mechanism between Next.js API routes and the Bun sidecar? (HTTP, Unix socket, stdio)
- How should the sidecar process be managed? (Spawned by `next dev`, separate process, process manager)
- Can the sidecar share the Bun module cache with the main monorepo to avoid cold-start latency?
- What happens when the sidecar crashes? Auto-restart strategy?

### R3: TypeScript Round-Trip Fidelity

- Do ALL existing agent/skill/rule files conform to the canonical template, or are there variations?
- What edge cases exist in section content serialization? (nested template literals, regex patterns, escaped characters)
- Should we build a round-trip test suite that runs against every entity file in `src/`?
- Is there a simpler serialization format we could migrate entity files to (e.g., frontmatter YAML + markdown body)?

### R4: fs.watch Reliability on macOS

- What are the known issues with `fs.watch` on macOS (kqueue/FSEvents)?
- Should we use `chokidar`, `Bun.file().watch()`, or native `fs.watch`?
- What debounce strategy works best for IDE-triggered save events (which can fire multiple times)?

## Product

### R5: Existing Observer Page Usage

- Which of the current 11 pages actually get used? Can we get any usage data?
- Which pages populate with real data in a typical Luca workflow? Which remain empty?
- Are there pages that users have explicitly said are useful or useless?

### R6: Competitive Analysis

- What do similar tools look like? (Stately Studio for state machines, n8n/Retool for workflow editing, Vercel dashboard for observability)
- What editing patterns do they use? (Inline, modal, full-page, visual)
- What can we learn from their UX for agent/workflow configuration?

### R7: Agent Editing Complexity

- How many agents exist currently? How complex are their prompts?
- What's the distribution of agent prompt lengths? (Short config-like vs. long detailed instructions)
- Do consumers actually need to create new agents, or is configuring existing ones sufficient?
- Could we start with config-only editing (Tier 1) and defer prompt authoring (Tier 2)?

## UX

### R8: Navigation Validation

- Is the proposed 3-group / 11-item navigation optimal?
- Should Memory be a standalone page or a section within Home?
- Is the Decisions page distinct enough from Sessions to warrant its own nav item?
- Do Complexity and Gates deserve their own pages, or could they be tabs within a unified Config page?

### R9: Monaco Editor Trade-offs

- What's the bundle size impact of adding Monaco to the app?
- Are there lighter alternatives (CodeMirror 6, Shiki for read-only, plain textarea for prompts)?
- Does Monaco support custom markdown token providers for template variables?
- How does Monaco perform on mobile/tablet (if relevant)?

### R10: Draft/Publish vs Direct Save

- Is the two-stage draft/publish model worth the complexity for config.json edits?
- Should config.json edits take effect immediately (save = live) while entity edits use draft/compile?
- What's the right UX for "your change is saved but not compiled yet"?

## Technical

### R11: React Flow v12 Interactive Editing

- What's needed to evolve the existing read-only React Flow canvas to support drag-to-reorder?
- How do we handle edge reconnection when a node is moved?
- Can React Flow support the "drop indicator" (glowing line between nodes) during drag?
- What are the performance implications with 15+ nodes and complex edges?

### R12: Jotai Patterns for Editing State

- What's the best Jotai pattern for per-entity draft atoms? (atom family, derived atoms, atom-with-storage)
- How do we handle concurrent edits to multiple entities? (Multiple tabs editing different agents)
- What's the best pattern for undo/redo with Jotai?

### R13: Git Auto-Commit for Rollback

- Should every Studio edit create a git commit, or should commits be batched?
- How do we avoid polluting git history with dozens of micro-commits?
- Should we use a separate git branch for Studio edits? (e.g., `studio/config-edits`)
- How does this interact with the user's normal git workflow?

### R14: Package Rename

- What's involved in renaming `packages/luca-observer` to `packages/luca-studio`?
- What references need updating? (package.json, tsconfig paths, import aliases, scripts, CI/CD)
- Should we rename incrementally or all at once?
- Is `@luca/studio` the right package name?
