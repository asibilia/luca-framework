# UI Architecture: Luca Studio

## Tech Stack (Retained from Observer)

- Next.js 15 (App Router)
- React 19
- shadcn/ui (Radix primitives)
- Tailwind CSS v4
- React Flow v12 (graph visualization)
- Tremor (charts)
- Jotai (state management)
- Lucide icons

## Layout Patterns

### Three-Zone Shell

The app uses a three-zone layout that adapts based on context:

**Zone A — Navigation Rail (left)**: 48px collapsed, 240px expanded. Icon-first, hover/pin to expand. Auto-collapses during editing to reclaim horizontal space.

**Zone B — Primary Content (center)**: Main workspace. Dashboards render at max-w-7xl centered. Editors expand to full width.

**Zone C — Detail Panel (right)**: 400-600px slide-over, resizable. Three states: closed, floating (overlay), docked (pushes content).

### Layout Adaptation by Context

| Context               | Rail            | Content                      | Detail Panel            |
| --------------------- | --------------- | ---------------------------- | ----------------------- |
| Dashboard (observing) | Expanded, 240px | max-w-7xl, centered          | Closed                  |
| Workflow editor       | Collapsed, 48px | Full bleed canvas            | Docked, 480px           |
| Agent editor          | Collapsed, 48px | Split: tree (280px) + editor | Docked, 400px (preview) |
| Rule manager          | Expanded, 240px | Table/list view              | Floating overlay        |

### Implementation

- `LayoutShell` component with CSS Grid: `grid-template-columns: auto 1fr auto`
- Detail panel animates with `transform: translateX()` and `data-state` attribute
- Panel state persisted in Jotai across navigation
- Keyboard shortcuts: `Cmd+\` toggles rail, `Cmd+.` toggles detail panel

## Workflow Editor UI

### Canvas Architecture (Three Levels of Detail)

**Level 1 — Pipeline Overview**: All steps visible as compact nodes in horizontal DAG. Each shows: step name, icon, status badge (enabled/disabled/error), agent count.

**Level 2 — Step Focus**: Selected step highlighted, others dimmed. Detail panel opens on right with full configuration. Canvas smoothly centers selected node.

**Level 3 — Agent Drill-Down**: From step detail panel, clicking agent name navigates to agent editor. Breadcrumb: Pipeline > Step Name > Agent Name.

### Node Design

```
+------------------------------------------+
|  [icon]  Step Name              [handle]  |
|  ---------------------------------------- |
|  Model tier: balanced    Agents: 3        |
|  Budget: 2 iterations                     |
|  ---------------------------------------- |
|  [status pill: enabled]   [overflow menu] |
+------------------------------------------+
```

- Width: fixed 280px
- Height: variable, capped ~120px
- Left border accent (2px) colored by domain: blue=planning, green=execution, amber=verification, purple=learning
- Selected node: `ring-2 ring-primary`
- Drag to reorder: drop indicator (glowing line between nodes)

### Interactive Capabilities

1. **Drag**: `nodesDraggable: true`, `onNodeDragStop` persists positions
2. **Add step**: Floating action button or canvas toolbar, opens command palette
3. **Remove step**: Right-click context menu or delete in detail panel (confirmation dialog)
4. **Reorder**: Drag node to new position, edges update in real-time
5. **Connect/disconnect**: Draw edges for conditional flows, validate acyclic

### Step Configuration Panel

Collapsible sections in the right detail panel:

1. **Identity**: Name, description, step type badge, enabled toggle
2. **Model Routing**: Complexity x tier grid (same as agent routing)
3. **Loop Budgets**: Numeric sliders (min 1, max 5) for iteration caps
4. **Agents**: List of assigned agents with links to agent editor, "Add Agent" dropdown
5. **Gates**: Toggle switches for applicable gates

### Canvas Toolbar

```
[Zoom In] [Zoom Out] [Fit View] [Minimap] | [Undo] [Redo] | [Add Step] | [Layout: H/V]
```

## Agent Editor UI

### Three-Column Layout

**Column 1 — Agent Tree (280px, collapsible)**: Tree view grouped by directory. Search/filter at top. Grouping by: directory (default), model tier, or complexity level. Right-click: New, Duplicate, Delete. Dirty indicator (dot) on unsaved entries.

**Column 2 — Editor (flexible)**: Tab bar at top:

- **Configure**: Structured form with all properties
- **Prompt**: Full-height code/text editor
- **Source**: Read-only TypeScript source
- **Compiled**: Read-only compiled markdown

**Column 3 — Preview (400px, togglable)**: Live compiled output. Updates with 300ms debounce.

### Prompt Editing

> **Updated after research (R9):** Monaco Editor (2+ MB gzipped) is overkill for markdown prompt editing. CodeMirror 6 (~300 KB) provides the same features at 1/10th the bundle cost. Shiki (~200 KB) handles read-only syntax highlighting for source/compiled preview.

Use **CodeMirror 6** (`@codemirror/view`, `@codemirror/lang-markdown`) for editable surfaces:

- Custom theme matching app CSS variables
- Markdown language mode with syntax highlighting
- Word wrap on by default
- JetBrains Mono font
- Toolbar: Format (bold/italic/code), Insert Template Variable, character/token count

Use **Shiki** for read-only code preview (Source and Compiled tabs):

- TypeScript and Markdown highlighting
- Matches app theme
- Zero interactivity overhead — pure static rendering

### ModelRoutingGrid Component (Shared)

Compact editable grid used in both workflow steps and agent editors:

```
              TRIVIAL  SIMPLE  MODERATE  COMPLEX  CRITICAL
Model tier:   [fast]   [fast]  [balanced] [capable] [capable]
```

Each cell is a small dropdown. Color-coded by tier. Shows preset name if matching a known preset.

## Visual Language: Edit vs. Observe

### Mode Indicators (Contextual, Not Global)

**View mode (default):**

- Standard background (`bg-background`)
- No save bar
- Fields rendered as text/badges, not inputs
- Detail panel header shows "Details" or entity name

**Edit mode (entered explicitly):**

- Thin accent bar (2px, `bg-primary`) at top of editing surface
- Detail panel header: "Editing: {entity name}" (editable inline)
- Fields transform from text to inputs (subtle animation, border appears)
- `SaveBar` slides up from bottom
- Background shifts slightly (`bg-background` → `bg-card`)

**Transition:**

- Observe → Edit: Click "Edit" button (pencil icon). URL updates to include `/edit`
- Edit → Observe: Click "Done" (after save) or "Discard". Dirty check dialog if unsaved.

### Unsaved Changes Indicators (5 redundant signals)

1. **DirtyIndicator dot**: 6px amber circle next to entity name in tree, tab, and page title
2. **SaveBar**: Persistent bottom bar with change count and action buttons
3. **Browser tab title**: Prepend bullet: "\* Agent: lu-router — Luca Studio"
4. **Navigation guard**: Dialog on nav with dirty state: "You have unsaved changes."
5. **Breadcrumb suffix**: "(edited)" in muted amber text

### Color Language

| Signal           | Color                        | Usage                                       |
| ---------------- | ---------------------------- | ------------------------------------------- |
| Edit mode accent | `hsl(var(--primary))` (blue) | Top bar, focused field borders, save button |
| Unsaved/dirty    | `amber-500`                  | Dots, badges, breadcrumb suffix             |
| Error/invalid    | `destructive` (red)          | Field borders, validation messages          |
| Success/saved    | `green-500`                  | Brief flash on save, success toasts         |
| View mode        | No accent                    | Standard background                         |

## Interaction Patterns

### Command Palette (Cmd+K)

Universal across all pages:

- "Go to agent: lu-router"
- "Go to workflow step: code review"
- "Create new agent"
- "Toggle edit mode"
- "Save current changes"
- "Search rules for 'complexity'"

Use shadcn's `CommandDialog` (wraps cmdk).

### Drag and Drop

Two contexts:

1. **Workflow canvas**: Reorder steps by dragging nodes
2. **Agent tree**: Reorder within groups

Same visual language: picked item gets drop shadow + 5% scale. Drop targets show blue highlight line.

### Optimistic Updates

All saves are optimistic — UI updates immediately, reverts on error. SaveBar shows "Saving..." briefly, then "Saved" on success, or reverts and shows error toast on failure.
