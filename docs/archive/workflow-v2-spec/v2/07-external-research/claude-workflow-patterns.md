# Common Workflow Patterns for AI Agents

## Source

- **URL**: https://claude.com/blog/common-workflow-patterns-for-ai-agents-and-when-to-use-them
- **Fetched**: 2026-03-22
- **Relevance**: HIGH

## Summary

This post defines three core workflow patterns for AI agents: Sequential, Parallel, and Evaluator-Optimizer. Each pattern is described with clear use cases, tradeoffs, and anti-patterns. The fundamental decision framework is: try a single agent call first; if it meets the quality bar, stop. Only add workflow complexity when you can identify where the single-agent approach falls short.

The Sequential pattern handles tasks with clear dependencies where outputs flow linearly through stages. The Parallel pattern distributes independent subtasks across concurrent agents, enabling multiple perspectives on the same problem (voting patterns, sectioned concerns). The Evaluator-Optimizer pattern pairs a generator with an evaluator in an iterative loop -- the generator produces content, the evaluator assesses against criteria, and the generator refines based on feedback.

A critical guardrail emphasized throughout: set clear stopping criteria before iterating. Define maximum iteration counts and specific quality thresholds. The post warns against "endless minor refinements" and emphasizes measuring baselines with single agents before introducing workflow complexity.

## Key Patterns Relevant to Luca v2

### Evaluator-Optimizer Pattern (Review Loops)

- **What**: Iterative cycle pairing a generator agent with an evaluator. Generator produces content, evaluator assesses against criteria, generator refines. Requires clear, measurable quality criteria and defined stopping conditions.
- **How it applies to v2**: This is the formal pattern for Luca v2's review loops. Research output is generated by research agents, evaluated by review agents against quality criteria (grounded sources, completeness, actionability), and refined until convergence. Plan output follows the same pattern.
- **Confidence**: HIGH

### Parallel Pattern for Multi-Perspective Analysis

- **What**: Multiple agents examine the same problem simultaneously from different angles, then results are aggregated. Key insight: "Agents don't hand off work to each other -- they operate autonomously and produce results that contribute to the overall task."
- **How it applies to v2**: Multi-agent parallel research is exactly this pattern. Multiple research agents investigate different aspects (API docs, implementation examples, performance characteristics) in parallel, then findings are aggregated into a unified research output.
- **Confidence**: HIGH

### Sequential Pattern for Phase Dependencies

- **What**: Tasks execute in predetermined order with outputs flowing linearly. Each step can leverage agent reasoning, but orchestration follows a defined path.
- **How it applies to v2**: Luca's phase pipeline (research -> discuss -> plan -> execute -> verify) is inherently sequential. Within each phase, parallel patterns can be used (parallel research agents, parallel reviewers), but phases themselves are sequential.
- **Confidence**: HIGH

### Pattern Composition

- **What**: Patterns are composable. Evaluator-optimizer can use parallel evaluation; sequential workflows can incorporate parallel processing at bottleneck stages.
- **How it applies to v2**: Luca v2 should compose all three: sequential phases, parallel agents within phases, and evaluator-optimizer loops for quality convergence. The research phase uses parallel + evaluator-optimizer; execution uses sequential + evaluator-optimizer.
- **Confidence**: HIGH

### Single-Agent Baseline

- **What**: Always establish a baseline with a single agent before adding workflow complexity. Only add patterns when measurable improvement justifies the token/latency cost.
- **How it applies to v2**: TRIVIAL/SIMPLE tasks should use single-agent research and single-pass review. Only MODERATE+ should trigger multi-agent research. Only COMPLEX+ should trigger multi-pass review loops. Complexity gating prevents over-engineering simple tasks.
- **Confidence**: HIGH

## Specific Techniques to Adopt

- **Clear stopping criteria before iterating**: Define max iteration count AND quality threshold for every review loop. Luca v2 should enforce both: `max_review_iterations` (from config) and quality score threshold
- **Measure quality improvement**: Track whether review loops actually improve output quality. If review iteration N produces the same score as iteration N-1, stop early
- **Aggregation strategy before parallel dispatch**: Define how parallel results will be merged BEFORE spawning agents. For research, this means defining the output schema; for reviews, defining how conflicting findings are resolved
- **Diagnostic questions for pattern selection**: Formalize the decision: "Can one agent handle this effectively?" -> no workflow. "Can subtasks process independently?" -> parallel. "Does quality improve with iteration?" -> evaluator-optimizer
- **Failure handling and retry logic per step**: Each workflow step should define fallback behavior. Research agent fails? Use cached/prior research. Review agent fails? Skip review for this iteration

## Specific Techniques to Avoid

- **Forcing sequential when parallel is possible**: Research tasks are naturally parallel. Don't serialize them
- **Adding evaluator-optimizer without measurable criteria**: Review loops without clear quality metrics become "endless minor refinements"
- **Iterating without stopping criteria**: The most common anti-pattern. Always define max iterations
- **Complex workflows for simple tasks**: Single agents handle trivial tasks effectively. Don't add overhead
- **Neglecting aggregation strategy**: Parallel results without a clear merge strategy create confusion, not clarity

## Quotes / Key Excerpts

> "Each step in a workflow can still leverage an agent's reasoning and tool use, but the overall orchestration follows a defined path."

> "Agents don't hand off work to each other -- they operate autonomously and produce results that contribute to the overall task."

> "Generation and evaluation are different cognitive tasks. Separating them lets each agent specialize."

> "Set clear stopping criteria before you start iterating. Define maximum iteration counts and specific quality thresholds."

> "Default to sequential. Move to parallel when latency is the bottleneck and tasks are independent, and add evaluator-optimizer loops only when you can measure the quality improvement."
