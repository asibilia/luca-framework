# Cleanup Report: Todo Audit

## Summary

Of 11 D-series runtime todos plus 2 supplementary todos audited:

- **4 Obsolete (delete)**: D01, D02, D08, D11
- **6 Need Revision (rewrite)**: D03, D04, D05, D06, D07, D09
- **1 Needs Revision (minor)**: D10
- **1 Still Valid**: E04
- **1 Needs Revision (non-runtime)**: agent-collaboration-ui

The brainstorm fundamentally changed the architecture from a standalone `packages/luca-studio/` Bun.serve() app with vanilla JS to absorbing everything into the existing `packages/luca-observer/` Next.js 15 app (renamed to Luca Studio). This invalidates the entire server, package scaffolding, vanilla HTML/CSS/JS approach, and WebSocket layer. The core _functionality_ of D03-D07 is still needed, but every implementation detail must change.

## Per-Todo Assessment

### runtime-d01: Package scaffolding for luca-studio

- **Status**: Obsolete -- Delete
- **Reason**: Brainstorm decision (0.overview.md, "Architecture" row): "Absorb into existing Next.js app." There is no `packages/luca-studio/` package to scaffold. The observer already has package.json, tsconfig, directory structure, and 77 components. The Zod schemas defined in D01 (`studio.schemas.ts`) are useful but belong in the observer's `lib/` directory or in `src/` domain schemas, not in a separate package.

### runtime-d02: Dev server core with Bun.serve() routing

- **Status**: Obsolete -- Delete
- **Reason**: Brainstorm decision (0.overview.md): architecture is Next.js App Router, not Bun.serve(). All routing is handled by Next.js file-based routing (`app/api/*/route.ts` for API, `app/*/page.tsx` for pages). The SSE endpoint, static file serving, WebSocket upgrade, HTML page routes -- all of these are replaced by Next.js conventions. The brainstorm also explicitly chose SSE-only (no WebSocket), which contradicts D02's `/ws/state` WebSocket endpoint.

### runtime-d03: Data extraction layer for Studio views

- **Status**: Needs Revision
- **Reason**: The _functionality_ is still needed -- Studio needs to read agents, DAG, state, and eval data from the filesystem. But the implementation must change entirely:
  - **Location**: Files belong in `packages/luca-observer/lib/` or as Next.js API route handlers, not `packages/luca-studio/src/data/`
  - **Import paths**: `MONOREPO_ROOT` resolution (4 levels up from `data/`) is wrong for observer location
  - **API routes**: Data functions should be called from Next.js API routes (`app/api/*/route.ts`), not from a Bun.serve() `handleApi` function
  - **Schemas**: Should use observer's existing schema patterns and Zod conventions, not the D01 schemas
  - **DAG extraction**: D04 already revised the DAG approach to use `dagToTopology()` from `src/workflow/` -- D03's `getDagGraph()` is superseded
- **If revision needed**: Rewrite as Next.js API route handlers. Keep the filesystem reading logic but adapt paths, imports, and response format for Next.js. The agent data extraction, state reading, and eval parsing logic is solid and reusable.

### runtime-d04: DAG visualization view

- **Status**: Needs Revision
- **Reason**: D04 was _already partially revised_ to target luca-observer (it creates files in `packages/luca-observer/`), but it still references D01/D02/D03 dependencies and the luca-studio package. The brainstorm confirms DAG visualization belongs in the observer/studio app as a React Flow page. Specific issues:
  - **Dependencies list**: Still says `depends_on: [D01, D02, D03, A09]` -- D01 and D02 are obsolete
  - **API route import**: Uses `~/workflow` path alias which may not resolve across the Next.js/src boundary (the todo acknowledges this risk). Brainstorm doc 4.technical-architecture.md describes a sidecar approach for this boundary
  - **Navigation**: Brainstorm restructured navigation into OBSERVE/BUILD/CONFIGURE groups with 9 items. DAG becomes "Pipeline" under BUILD, not a separate `/dag-viewer` route
- **If revision needed**: Update dependencies to remove D01/D02. Rename route from `/dag-viewer` to `/pipeline` per brainstorm navigation. Resolve the `src/workflow` import boundary using the sidecar pattern from the technical architecture doc. Remove A09 dependency reference if `dagToTopology()` doesn't exist yet or clarify its status.

### runtime-d05: Agent browser view with tree navigation

- **Status**: Needs Revision
- **Reason**: Agent browsing is a core brainstorm feature (under BUILD group, "Agents" page). But the implementation is completely wrong:
  - **Technology**: Uses vanilla HTML (`agents.html`) + vanilla JS (`agent-browser.js`) + CSS variables. Brainstorm mandates React components with shadcn/ui + Tailwind CSS
  - **Location**: Files in `packages/luca-studio/src/views/` and `src/public/`. Should be React components in `packages/luca-observer/components/` and a page in `app/agents/page.tsx`
  - **Features**: Brainstorm specifies a much richer experience: card grid (not just tree), model routing table, fork/duplicate, enable/disable toggles, three-column layout (tree + editor + preview). D05 only has tree + detail panel
  - **Editing**: Brainstorm includes config editing (Tier 1) and read-only prompt viewing. D05 is purely read-only
  - **Data source**: Fetches from `/api/agents` (Bun.serve() stub). Should use Next.js API routes
- **If revision needed**: Complete rewrite as React/Next.js page. Use existing observer patterns (shadcn DataTable, card components). The brainstorm's UX design doc (2.ux-design.md) has detailed specifications for the three-column agent editor layout. Keep D05's core _concept_ (tree navigation, source/compiled side-by-side) but implement with React components.

### runtime-d06: State machine inspector view

- **Status**: Needs Revision
- **Reason**: State inspection is a brainstorm feature (under OBSERVE group). But implementation is wrong:
  - **Technology**: Vanilla HTML/JS. Must be React + shadcn
  - **Location**: `packages/luca-studio/src/views/state/`. Should be `packages/luca-observer/app/state/page.tsx`
  - **WebSocket**: Uses WebSocket for live updates (`/ws/state`). Brainstorm explicitly chose SSE-only, no WebSocket (0.overview.md: "SSE only, no WebSocket")
  - **Real-time**: Brainstorm says "V1 is entirely post-hoc observation. Real-time streaming is V2." D06's live WebSocket updates are V2 scope
  - **Features**: Brainstorm UX (2.ux-design.md Flow 4) specifies: pinned key fields, auto-refresh toggle (polling not WebSocket), freeze button, Send Event via Cmd+K. D06 has none of these
- **If revision needed**: Rewrite as React page. Replace WebSocket with polling or SSE. Implement the brainstorm's Flow 4 UX specification. Scope to post-hoc observation for v1.

  - **Features**: Brainstorm UX (2.ux-design.md Flow 5) specifies: colored horizontal segments for pass/fail summary, file path click opens read-only source viewer with error highlighting, "Re-run Harness" button with streaming terminal, history sidebar for last 10 runs. ### runtime-d08: File watcher with targeted recompilation

- **Status**: Obsolete -- Delete
- **Reason**: Brainstorm decision (0.overview.md): "File watcher: Dropped for v1. Manual refresh is sufficient; watcher adds complexity." The brainstorm explicitly dropped this. Additionally, the research revision (R4) changed the technology from raw `fs.watch` to `chokidar v5` -- but only for SSE file-change detection in the Next.js API route, not for triggered recompilation. D08's targeted recompilation concept may return in v2 but is out of scope.
- **Additional note**: D08's `recompile.ts` approach (calling `build-compile.ts`) is acknowledged in the todo itself as LOW confidence. The brainstorm replaced this with a compilation sidecar (4.technical-architecture.md) that compiles individual entities on save, which is a different and better approach.

### runtime-d09: SSE and WebSocket live update layer

- **Status**: Needs Revision
- **Reason**: SSE is confirmed needed (brainstorm: "SSE only, no WebSocket"). But D09 implements both SSE AND WebSocket, with the wrong architecture:
  - **WebSocket**: Must be removed entirely. Brainstorm says SSE only (0.overview.md, 4.technical-architecture.md)
  - **SSE implementation**: D09 uses Bun.serve() `ReadableStream` with `globalThis.__studio_sse_clients`. Brainstorm specifies Next.js API route SSE (`GET /api/events/route.ts`) with chokidar v5 file watching
  - **Event types**: D09 has `reload`, `state-change`, `eval-complete`. Brainstorm specifies richer event types: `file:changed`, `state:transition`, `compile:start`, `compile:complete`, `compile:error`, `ledger:entry`, `heartbeat`
  - **Client integration**: D09's `shared.js` uses vanilla EventSource. Brainstorm specifies a `useSSE()` React hook integrated with Jotai atoms
  - **Content-Encoding**: Brainstorm research (R1) found `Content-Encoding: none` header is critical for SSE in Next.js. D09 doesn't account for this
- **If revision needed**: Rewrite for Next.js. Remove all WebSocket code. Implement the brainstorm's SSE event type taxonomy. Use chokidar v5 for file watching. Add the `Content-Encoding: none` header. Client-side should be a React hook, not vanilla JS.

### runtime-d10: CLI command for luca studio

- **Status**: Needs Revision (minor)
- **Reason**: A CLI command to start Studio is still useful, but it now just starts `next dev` for the observer/studio app instead of `bun --hot packages/luca-studio/src/server.ts`:
  - **Command**: `bun --hot packages/luca-studio/src/server.ts` -> `cd packages/luca-observer && bun run dev` (which runs `next dev`)
  - **Flags**: `--port` still relevant (Next.js supports `-p`). `--no-open` still relevant. `--no-watch` is irrelevant (file watcher dropped for v1)
  - **Root script**: `"studio": "bun --hot packages/luca-studio/src/server.ts"` -> `"studio": "cd packages/luca-observer && bun run dev"`
  - **Package may be renamed**: Brainstorm mentions renaming `luca-observer` to `luca-studio`. If renamed, paths change
- **If revision needed**: Update server path and command. Remove `--no-watch` flag. Consider whether this todo is even necessary since `bun run dev` in the observer package already works. May be absorbed into a broader "package rename" todo.
