# Luca Studio: Observer + Studio Merger

## Summary

Luca Observer and the planned Luca Studio are being merged into a single app called **Luca Studio** — a glass control plane for the Luca agentic framework. The app supports three modes of interaction:

1. **Observe** — Watch what Luca is doing (sessions, memory, eval results, state)
2. **Browse** — Inspect what Luca is built from (agents, workflow DAG, rules, skills)
3. **Configure/Edit** — Customize how Luca behaves (workflow steps, agent selection, complexity routing, gates, and deep editing: agent prompts, custom agents, new workflow steps)

## Two User Personas

- **Framework Consumer**: Installs Luca into their project, uses the default workflow, wants to customize it via a UI
- **Framework Editor**: Develops Luca itself, needs deep internals access

Both personas use the same app. No permissions model — progressive disclosure handles the complexity gradient.

## What Existed Before

### Luca Observer (production, Next.js 15)

11 pages focused on MuninnDB memory observability:

| Page            | Purpose                                     |
| --------------- | ------------------------------------------- |
| Dashboard       | Stat cards, recent memories, todos          |
| Sessions        | Past workflow session explorer              |
| Memory          | 6-section MuninnDB dashboard                |
| Learning        | Pattern/decision/pitfall tracking           |
| Vault           | MuninnDB vault health                       |
| Knowledge Graph | Force-directed entity visualization         |
| Workflow Editor | Read-only React Flow pipeline visualization |
| Semantic Search | On-demand memory search                     |
| Decisions       | Decision trail                              |
| Contradictions  | Contradiction detector                      |
| Entities        | Entity catalog                              |

**Known issues**: Pages overlap significantly (8 pages all show MuninnDB data from different angles). Some pages never populate with real data. Navigation is a flat list with no grouping. All pages are read-only.

### Luca Studio (planned, never built)

A lightweight Bun.serve() dev server with:

- Agent Browser (source/compiled side-by-side, tree navigation)
- State Inspector (live state machine context + event log)
- Eval Results (harness pass/fail with drill-down)
- DAG Visualization (typed workflow pipeline)
- File Watcher with targeted recompilation (dropped for v1)

## Key Decisions Made

| Decision           | Choice                                  | Rationale                                                                                     |
| ------------------ | --------------------------------------- | --------------------------------------------------------------------------------------------- |
| App name           | **Luca Studio**                         | "Observer" no longer fits an app that also edits                                              |
| Real-time protocol | SSE only, no WebSocket                  | Simpler, works in Next.js API routes natively                                                 |
| File watcher       | Dropped for v1                          | Manual refresh is sufficient; watcher adds complexity                                         |
| Architecture       | Absorb into existing Next.js app        | Observer has 77 components, React Flow, shadcn — rebuilding in vanilla JS would be regression |
| Persona model      | Progressive disclosure, not permissions | Solo-developer tool; modes add overhead for a user base of one                                |

## Research-Informed Revisions

After the initial brainstorm, a 4-agent research team investigated 14 open questions. Key revisions:

| Revision       | Original              | Updated                                                                                   | Source |
| -------------- | --------------------- | ----------------------------------------------------------------------------------------- | ------ |
| Code editor    | Monaco Editor (2+ MB) | **CodeMirror 6** (~300 KB) + **Shiki** (~200 KB read-only)                                | R9     |
| Sidecar IPC    | Unix domain socket    | **TCP localhost** (port 3457) — Node.js fetch() can't do Unix sockets                     | R2     |
| File watching  | Raw fs.watch          | **chokidar v5** (FSEvents backend on macOS, built-in debounce)                            | R4     |
| Navigation     | 11 items in 3 groups  | **9 items** — merge Complexity+Gates into Config (tabs), add Memory                       | R8     |
| Launch scope   | All three tiers       | **Tier 1 only** (config editing + read-only prompt viewing)                               | R7     |
| Undo/redo      | Custom history stack  | **`jotai-history`** package (official, matches spec exactly)                              | R12    |
| Page priority  | Observe-first         | **BUILD pages first** (Pipeline, Agents, Skills, Rules) — OBSERVE pages need MuninnDB     | R5     |
| SSE            | Tentative             | **Confirmed viable** in Next.js App Router with `Content-Encoding: none` header           | R1     |
| TS round-trip  | Assumed feasible      | **Confirmed**: 129/129 entity files follow canonical template, `.config` getter available | R3     |
| Git rollback   | Per-edit commits      | **Batch-commit-on-publish** with `[studio-edit]` prefix                                   | R13    |
| Entity counts  | Unknown               | **47 agents, 58 skills, 24 rules** (129 total)                                            | R7     |
| Package rename | TBD                   | **Safe**: ~25 files, all-at-once single commit                                            | R14    |
