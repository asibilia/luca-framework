# Wave 01 — Phase 02: planning-time-confidence-emission

## What changed

### Task 1 — Carry-forward polish + `log` writer flags

**`packages/luca-core/src/confidence/schemas.ts`**
- Expanded JSDoc on `researchable`: clarifies that `true` = factual ambiguity resolvable by automated research; absent/false = human judgment required → `ask` bucket.
- Expanded JSDoc on `resolution`: documents each enum value (`auto`=proceed, `research`=trigger research, `ask`=escalate to human) and explains that it takes precedence over `confidence`+`researchable`.

**`packages/luca-core/src/confidence/gate.ts`** (D2)
- Replaced bare `else ask.push(entry)` with exhaustiveness guard:
  `else if (entry.resolution === 'ask') ask.push(entry); else { const _exhaustive: never = entry.resolution; ask.push(entry) }`
- Now a compile error if the `resolution` enum grows without updating the branch.

**`packages/luca-cli/src/commands/write-surface/confidence.ts`**
- Added `--researchable` (boolean) and `--resolution` (string, validated ∈ {auto,research,ask}) flags to `logCommand`.
- Threaded both into the flag-driven payload (conditional spread, preserving optional semantics).
- Tightened `gate --help` description: states output shape `{auto,research,ask,counts}`, explains bucketing precedence.

**`packages/luca-cli/src/write-surface/handlers/luca-confidence-log.ts`** (D1 — correctness)
- Added `researchable: z.boolean().optional()` and `resolution: z.enum(['auto','research','ask']).optional()` to `inputSchema` (~line 54).
- Threaded both into `appendConfidenceEntry` call via conditional spread, mirroring `reviewHint` pattern.
- Without this, the CLI flags would have been silently stripped by `safeParse`.
