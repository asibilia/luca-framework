# Plan 34-03: Child Actor Model and Event-Driven Architecture

## Objective

Implement the child actor model for phase lifecycle management and the event-driven architecture that enables hooks and skills to observe workflow transitions. The phase actor is a child machine invoked by the parent `workflowMachine` during the `executing` state -- it models wave execution, phase verification, and fix iterations as a self-contained lifecycle. The event-driven layer defines structured transition output that downstream consumers (hooks, skills, monitoring) can subscribe to.

This plan covers XSTATE-05 (event-driven architecture -- workflow transitions emit events for hooks/skills) and XSTATE-06 (child actor model -- phases as child actors, milestone as parent).

## Context

@src/state-machine/machine.ts -- The parent workflow machine from Plan 34-01. The `executing` state currently transitions on `PHASE_COMPLETE` and `PHASE_FAILED`. This plan modifies it to `invoke` the `phaseActor` child machine, with `onDone` and `onError` handling.

@src/state-machine/types.ts -- Existing Zod schemas for `WorkflowContext`, `WorkflowEvent`, and supporting types. This plan adds `PhaseContext`, `PhaseEvent`, and `TransitionRecord` schemas.

@src/state-machine/guards.ts -- Guard functions from Plan 34-01. The phase actor defines its own guards (`withinFixBudget`, `hasMoreWaves`) locally via its own `setup()`.

@src/state-machine/actions.ts -- Action functions from Plan 34-01. The parent machine's `recordPhaseResult` and `recordPhaseError` actions are triggered by the phase actor's `onDone`/`onError` callbacks.

@src/state-machine/persistence.ts -- Persistence layer from Plan 34-02. XState's `getPersistedSnapshot()` handles child actors automatically -- the phase actor state is included in the parent's persisted snapshot.

@src/state-machine/cli.ts -- CLI from Plan 34-02. The `send` and `status` subcommands work with the parent machine; the phase actor is an internal implementation detail managed by the parent.

@src/iteration/budget.ts -- Budget state management. Phase actor guards reference budget concepts (fix iteration limits come from complexity gating).

@src/complexity/defaults.ts -- `DEFAULT_COMPLEXITY_MATRIX` defines `harnessFixIterations` and `verifyFixIterations` per complexity level. These become the phase actor's iteration budget.

@src/harness/types.ts -- `HarnessResult` interface. The phase actor receives harness results as events to determine verification pass/fail.

@.claude/rules/complexity-gating.md -- Documents harness fix iterations and verify fix iterations per complexity level. The phase actor models these iteration loops.

### Task 2: Implement the phase actor machine

**Goal:** Create `src/state-machine/actors/phase-actor.ts` with the child state machine that models phase lifecycle: wave execution, evaluation, verification, and fix iterations.

**Files:** `src/state-machine/actors/phase-actor.ts` (create), `src/state-machine/actors/index.ts` (create)

**Steps:**

1. Create the directory `src/state-machine/actors/`.

2. Create `src/state-machine/actors/phase-actor.ts`:

   ```typescript
   import { setup, assign } from "xstate";
   import type { PhaseContext, PhaseEvent, PhaseInput } from "../types";

   /**
    * Phase lifecycle child actor machine.
    *
    * Models the execution of a single phase within the Luca workflow.
    * The parent workflowMachine invokes this actor when entering the
    * `executing` state and receives the outcome via `onDone`/`onError`.
    *
    * Lifecycle:
    *   idle -> wave_executing -> wave_evaluating
    *     -> (more waves) -> wave_executing
    *     -> (all done) -> phase_verifying
    *       -> (passed) -> phase_done
    *       -> (failed, within budget) -> phase_fixing -> phase_verifying
    *       -> (failed, budget exhausted) -> phase_blocked
    *   phase_done (final) -- success, output sent to parent
    *   phase_blocked (final) -- failure, output sent to parent
    */
   export const phaseActorMachine = setup({
     types: {
       context: {} as PhaseContext,
       events: {} as PhaseEvent,
       input: {} as PhaseInput,
       output: {} as {
         phase_id: number;
         outcome: string;
         outcome_reason: string;
       },
     },
     guards: {
       /** There are more waves to execute */
       hasMoreWaves: ({ context }) => {
         return context.current_wave < context.total_waves;
       },
       /** Fix iteration budget allows another attempt */
       withinFixBudget: ({ context }) => {
         return context.fix_iterations < context.max_fix_iterations;
       },
     },
     actions: {
       /** Record wave completion and advance wave counter */
       recordWaveComplete: assign({
         wave_results: ({ context, event }) => {
           const e = event as Extract<PhaseEvent, { type: "WAVE_COMPLETE" }>;
           return [
             ...context.wave_results,
             {
               wave_number: e.wave_number,
               plan_ids: context.plan_ids,
               status: "passed" as const,
               summary: e.summary ?? "",
               timestamp: new Date().toISOString(),
             },
           ];
         },
         current_wave: ({ context }) => context.current_wave + 1,
       }),

       /** Record wave failure */
       recordWaveFailed: assign({
         wave_results: ({ context, event }) => {
           const e = event as Extract<PhaseEvent, { type: "WAVE_FAILED" }>;
           return [
             ...context.wave_results,
             {
               wave_number: e.wave_number,
               plan_ids: context.plan_ids,
               status: "failed" as const,
               summary: e.error ?? "",
               timestamp: new Date().toISOString(),
             },
           ];
         },
         current_wave: ({ context }) => context.current_wave + 1,
       }),

       /** Mark harness as passed */
       markHarnessPassed: assign({
         harness_passed: () => true,
         last_harness_errors: () => 0,
       }),

       /** Record harness failure and increment fix counter */
       recordHarnessFailed: assign({
         harness_passed: () => false,
         last_harness_errors: ({ event }) => {
           const e = event as Extract<PhaseEvent, { type: "HARNESS_FAILED" }>;
           return e.error_count ?? 0;
         },
       }),

       /** Increment fix iteration counter */
       incrementFixIterations: assign({
         fix_iterations: ({ context }) => context.fix_iterations + 1,
       }),

       /** Mark phase as passed */
       markPassed: assign({
         outcome: () => "passed" as const,
         outcome_reason: () => "All waves completed and harness passed",
         completed_at: () => new Date().toISOString(),
       }),

       /** Mark phase as blocked (fix budget exhausted) */
       markBlocked: assign({
         outcome: () => "blocked" as const,
         outcome_reason: ({ context }) =>
           `Fix budget exhausted after ${context.fix_iterations} iterations with ${context.last_harness_errors} remaining errors`,
         completed_at: () => new Date().toISOString(),
       }),

       /** Record start timestamp */
       recordStart: assign({
         started_at: () => new Date().toISOString(),
       }),
     },
   }).createMachine({
     id: "phase",
     initial: "idle",
     context: ({ input }) => ({
       phase_id: input.phase_id,
       plan_ids: input.plan_ids ?? [],
       current_wave: 0,
       total_waves: input.total_waves ?? 1,
       wave_results: [],
       fix_iterations: 0,
       max_fix_iterations: input.max_fix_iterations ?? 3,
       harness_passed: false,
       last_harness_errors: 0,
       outcome: "pending" as const,
       outcome_reason: "",
       started_at: "",
       completed_at: "",
     }),

     states: {
       idle: {
         entry: "recordStart",
         on: {
           PLAN_WAVE: {
             target: "wave_executing",
           },
         },
       },

       wave_executing: {
         on: {
           WAVE_COMPLETE: {
             target: "wave_evaluating",
             actions: "recordWaveComplete",
           },
           WAVE_FAILED: {
             target: "wave_evaluating",
             actions: "recordWaveFailed",
           },
         },
       },

       wave_evaluating: {
         always: [
           {
             target: "wave_executing",
             guard: "hasMoreWaves",
           },
           {
             target: "phase_verifying",
           },
         ],
       },

       phase_verifying: {
         on: {
           HARNESS_PASSED: {
             target: "phase_done",
             actions: ["markHarnessPassed", "markPassed"],
           },
           HARNESS_FAILED: [
             {
               target: "phase_fixing",
               guard: "withinFixBudget",
               actions: ["recordHarnessFailed", "incrementFixIterations"],
             },
             {
               target: "phase_blocked",
               actions: ["recordHarnessFailed", "markBlocked"],
             },
           ],
         },
       },

       phase_fixing: {
         on: {
           FIX_COMPLETE: {
             target: "phase_verifying",
           },
           FIX_FAILED: {
             target: "phase_blocked",
             actions: "markBlocked",
           },
         },
       },

       phase_done: {
         type: "final",
       },

       phase_blocked: {
         type: "final",
       },
     },

     output: ({ context }) => ({
       phase_id: context.phase_id,
       outcome: context.outcome,
       outcome_reason: context.outcome_reason,
     }),
   });
   ```

3. Create `src/state-machine/actors/index.ts`:

### Task 4: Implement transition record builder

**Goal:** Create `src/state-machine/events.ts` with functions to build structured `TransitionRecord` objects from machine snapshots. This is the event-driven output format that enables hooks and skills to observe workflow transitions.

**Files:** `src/state-machine/events.ts` (create)

**Steps:**

1. Create `src/state-machine/events.ts`:

   ```typescript
   import type { TransitionRecord, WorkflowContext } from "./types";
   import { transitionRecordSchema } from "./types";

   /**
    * Build a TransitionRecord from a state transition.
    *
    * Called by the CLI after every `send` command to produce structured
    * output that downstream consumers (hooks, skills, monitoring) can
    * parse and act on.
    *
    * @param previousState - Machine state before the transition
    * @param currentState - Machine state after the transition
    * @param eventType - The event type that triggered the transition
    * @param eventData - Event payload (without the 'type' field)
    * @param context - Current machine context after the transition
    * @param actionsExecuted - Names of actions that were executed
    * @returns Validated TransitionRecord
    */
   export function buildTransitionRecord(
     previousState: string,
     currentState: string,
     eventType: string,
     eventData: Record<string, any> = {},
     context: WorkflowContext,
     actionsExecuted: string[] = [],
   ): TransitionRecord {
     return transitionRecordSchema.parse({
       previous_state: previousState,
       current_state: currentState,
       event_type: eventType,
       event_data: eventData,
       actions_executed: actionsExecuted,
       context: {
         session_id: context.session_id,
         complexity: context.complexity,
         oversight: context.oversight,
         current_phase: context.current_phase,
         verification_attempts: context.verification_attempts,
         phases_completed: context.phase_results.length,
       },
       timestamp: new Date().toISOString(),
       session_id: context.session_id,
     });
   }

   /**
    * Extract a minimal context summary for transition records.
    *
    * Produces a small, relevant subset of the full context to include
    * in transition records. Avoids exposing the full complexity matrix
    * and configuration to consumers.
    *
    * @param context - Full workflow context
    * @returns Minimal context summary
    */
   export function extractContextSummary(
     context: WorkflowContext,
   ): Record<string, any> {
     return {
       session_id: context.session_id,
       ticket_id: context.ticket_id,
       complexity: context.complexity,
       oversight: context.oversight,
       current_phase: context.current_phase,
       current_milestone: context.current_milestone,
       verification_attempts: context.verification_attempts,
       phases_completed: context.phase_results.length,
       last_error: context.last_error,
     };
   }

   /**
    * Determine if a transition is "significant" for notification purposes.
    *
    * Significant transitions are those that hooks and monitoring tools
    * should be alerted about. Routine transitions (like recordTransition
    * timestamp updates) are not significant.
    *
    * @param previousState - State before transition
    * @param currentState - State after transition
    * @returns true if the transition should trigger notifications
    */
   export function isSignificantTransition(
     previousState: string,
     currentState: string,
   ): boolean {
     // State didn't change (guard blocked transition)
     if (previousState === currentState) return false;

     // All state changes are significant
     return true;
   }

   /**
    * Get a human-readable description of a transition for logging.
    *
    * @param record - The transition record
    * @returns Human-readable string describing the transition
    */
   export function describeTransition(record: TransitionRecord): string {
     return `[${record.session_id.slice(0, 8)}] ${record.previous_state} -> ${record.current_state} (${record.event_type})`;
   }
   ```
