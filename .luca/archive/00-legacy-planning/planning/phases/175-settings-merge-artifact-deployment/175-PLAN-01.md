# Phase 175 Plan 1: Deploy & Merge Schemas

## Objective

Define the Zod schemas and inferred types that underpin the deploy manifest and three-tier settings merge algorithm. These schemas are the foundation for all subsequent library functions in Plans 2 and 3.

## Tasks

### 1. Create deploy manifest Zod schema

**Type:** auto
**TDD:** false
**Depends on:** none

Create `packages/luca-framework/src/utils/deploy-manifest.schemas.ts` with the `DeployManifestSchema`. This schema defines the structure for `~/.luca/manifests/deploy-manifest.json` and is distinct from the per-project `LucaManifest` type.

The schema must include:

- `deployed_at`: ISO timestamp string
- `package_version`: string (from `LUCA_VERSION`)
- `mode`: enum `"copy"` (only mode for npm global)
- `source_path`: string (absolute path to the package root)
- `settings_backup_path`: optional string (path to the settings.json backup taken during deploy)
- `artifacts`: record of relative path to `{ hash: string, source_type: string }` (where source_type is "agent", "skill", "hook", "rule", "statusline", "lib")

Reuse `hashFile()` and `hashContent()` from `manifest.ts` -- do not duplicate hashing logic.

Export the inferred type: `export type DeployManifest = z.infer<typeof DeployManifestSchema>`.

**Files to create:**

- `packages/luca-framework/src/utils/deploy-manifest.schemas.ts`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- Schema can be parsed with `.safeParse({})` to get meaningful validation errors (confirms schema shape)
- Type `DeployManifest` is exported and usable

### 2. Create settings merge types and schemas

**Type:** auto
**TDD:** false
**Depends on:** none

Create `packages/luca-framework/src/utils/settings-merge.schemas.ts` with the Zod schemas and types needed by the merge algorithm:

- `HookSlotKeySchema`: string type alias for the composite key format `"{Event}:{matcher}"` or `"{Event}:"` (no matcher)
- `HookEntrySchema`: schema for a single hook entry `{ type, command, timeout, async?, statusMessage? }`
- `HookSlotSchema`: schema for a slot group `{ matcher?: string, hooks: HookEntry[] }`
- `MergeActionSchema`: discriminated union:
  - `{ type: "auto-merge", slot_key: string }` -- new slot, add silently
  - `{ type: "auto-skip", slot_key: string, command: string }` -- identical hook exists
  - `{ type: "conflict", slot_key: string, existing_command: string, proposed_command: string }` -- same slot, different command
- `MergeResultSchema`: `{ actions: MergeAction[], merged_settings: Record<string, unknown> }`
- `ConflictResolutionSchema`: enum `"keep-existing" | "replace-with-luca" | "keep-both"`

Export all inferred types.

**Files to create:**

- `packages/luca-framework/src/utils/settings-merge.schemas.ts`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- All types are exported and referenceable from other files
