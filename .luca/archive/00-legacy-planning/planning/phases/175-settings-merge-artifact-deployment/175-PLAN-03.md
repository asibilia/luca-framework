### 1. Implement conflict prompt UI

**Type:** auto
**TDD:** false
**Depends on:** none (uses Plan 1 schemas for types)

Create `packages/luca-framework/src/utils/conflict-prompt.ts` with the interactive conflict resolution UI using `@clack/prompts`.

**`promptConflictResolution(conflicts: MergeAction[]): Promise<Map<string, ConflictResolution>>`**

- For each conflict action, display a `@clack/prompts` select showing:
  - The slot key (event + matcher)
  - The existing hook command
  - The proposed Luca hook command
  - Three choices: "Keep existing", "Replace with Luca", "Keep both"
- Returns a Map of slot_key to resolution
- Non-interactive fallback: if `process.stdin.isTTY === false` (CI, piped), default all conflicts to `"keep-both"` to avoid data loss, log a warning

Include JSDoc documentation.

### 2. Refactor deploy-global.ts to use library functions

**Type:** auto
**TDD:** false
**Depends on:** 1

Refactor `scripts/deploy-global.ts` to import and use the new library functions instead of its inline implementations. This is the integration task that ties everything together.

Changes to `deploy-global.ts`:

1. **Import new modules:**
   - `backupSettings`, `rotateBackups` from `backup-manager`
   - `computeMergeActions`, `applyMerge`, `getKnownLucaScripts` from `settings-merger`
   - `promptConflictResolution` from `conflict-prompt`
   - `createDeployManifest`, `writeDeployManifest` from `deploy-manifest-writer`
   - `getLucaHomePaths`, `ensureLucaHome` from `luca-home`
   - `generateClaudeHooksConfigFromCanonical` from `config-generators`
   - `resolveCanonicalRegistry` from `hook-registry`

2. **Replace `mergeSettings()`** with new flow:
   - Call `ensureLucaHome()` to create directories
   - Call `backupSettings()` before any modification
   - Call `rotateBackups()` after backup
   - Generate proposed hooks via `generateClaudeHooksConfigFromCanonical()` using the canonical registry
   - Call `computeMergeActions()` to diff
   - If conflicts exist, call `promptConflictResolution()`
   - Call `applyMerge()` with resolutions
   - Write the merged settings.json

3. **Replace `writeManifest()`** with new flow:
   - Collect all deployed file paths during deploy phases
   - Call `createDeployManifest()` with the file list
   - Call `writeDeployManifest()` to `~/.luca/manifests/`
   - Remove the old `.luca-deploy-manifest.json` in `~/.claude/` if present

4. **Remove inline `lucaScripts` arrays** (3 copies):
   - In `mergeSettings()` (line 637-654)
   - In `removeGlobalArtifacts()` (lines 769-784 and 830-845)
   - Replace all three with calls to `getKnownLucaScripts()`

5. **Remove `rewriteWrapperPaths()`** if Phase 174 context-aware wrappers make it unnecessary (verify first, keep if still needed for backward compat).

6. **Update `MANIFEST_PATH`** from `~/.claude/.luca-deploy-manifest.json` to `~/.luca/manifests/deploy-manifest.json`.

7. **Update `removeGlobalArtifacts()`** to:
   - Read manifest from new location
   - Clean up settings using the merge library (not inline script lists)
   - Fallback to old manifest location for backward compat

Keep the `--dry-run`, `--copy`, and `--remove` flags working. The `--copy` flag should now be the only mode (symlink is deprecated for global deploy, but keep the flag for backward compat with a deprecation warning).

**Files to edit:**

- `scripts/deploy-global.ts`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- `bun scripts/deploy-global.ts --dry-run` executes without errors and shows the expected output
- Confirm `--dry-run` makes zero filesystem writes (no backup created at `~/.luca/backups/`, no manifest written to `~/.luca/manifests/`, no changes to `~/.claude/settings.json`)
- No more hardcoded `lucaScripts` arrays in the file

### 3. Wire deploy functions into luca init flow

**Type:** auto
**TDD:** false
**Depends on:** 2

Add artifact deployment as an optional step in `packages/luca-framework/src/commands/init.ts`. After MuninnDB setup (step 6), add a new step:

**Step 7: Deploy artifacts to ~/.claude/**

- Prompt user: "Deploy Luca agents, skills, hooks, and rules to ~/.claude/?" (Y/n)
- If yes:
  - Import the following from each library module:
    - `backupSettings`, `rotateBackups` from `backup-manager`
    - `computeMergeActions`, `applyMerge`, `getKnownLucaScripts` from `settings-merger`
    - `promptConflictResolution` from `conflict-prompt`
    - `createDeployManifest`, `writeDeployManifest` from `deploy-manifest-writer`
  - Import `getLucaHomePaths`, `ensureLucaHome` from `luca-home`
  - Import `generateClaudeHooksConfigFromCanonical` from `config-generators`
  - Import `resolveCanonicalRegistry` from `hook-registry`
  - Use `detectRuntimeContext()` to determine source path
  - Deploy agents, skills, hooks, rules, statusline using the existing `deployFile`/`deployDir` logic from `deploy-global.ts` (import the file copy helpers, or inline minimal versions if import is not practical -- document the choice)
  - Run the three-tier settings merge
  - Write the deploy manifest
  - Show summary of what was deployed

This step is skippable with `--skip-deploy` flag.

Also add a note about `luca update` (future Phase 176) for updating existing deployments.
