# Plan 06-03: HTTP & Credential Safety

## Frontmatter
- **ID**: 06-03
- **Title**: HTTP Request & Credential Safety
- **Wave**: 3
- **Depends on**: 06-01 (uses Zod validation patterns established in Wave 1)

## Objective

Harden the Jira REST API adapter against URL injection, credential leakage, and malformed API responses. Add `ticketId` format validation before URL construction, enforce HTTPS for the base URL, sanitize error messages to prevent credential leakage, and add Zod schemas for runtime validation of Jira API response shapes. This wave builds on the Zod patterns introduced in Wave 1 (06-01).

### Task 3: Add credential sanitization to error paths

**Goal**: Prevent credential leakage by sanitizing error messages before they are returned to callers. Strip Authorization header values, Base64 credential strings, and API tokens from error messages.

**File:** `packages/luca-framework/src/adapters/jira-adapter.ts`

**Changes:**
1. Add a `sanitizeJiraError()` helper function at module level:
   ```typescript
   /**
    * Sanitize error messages to prevent credential leakage.
    * Strips Authorization header values, Base64 strings, and API tokens.
    */
   function sanitizeJiraError(error: unknown): string {
     const message = error instanceof Error ? error.message : String(error);
     return message
       .replace(/Basic\s+[A-Za-z0-9+/=]+/g, 'Basic [REDACTED]')
       .replace(/Bearer\s+[A-Za-z0-9._-]+/g, 'Bearer [REDACTED]')
       .replace(/[A-Za-z0-9+/]{40,}={0,2}/g, '[REDACTED]')
       .replace(/token[=:]\s*\S+/gi, 'token=[REDACTED]');
   }
   ```
   Note: The Base64 pattern uses `{40,}` (minimum 40 chars) to avoid false positives on short strings that happen to look like Base64.

2. Update `getTicket()` catch block (lines 262-269):
   ```typescript
   // Before:
   const errorMessage = error instanceof Error ? error.message : String(error);
   return { success: false, error: `Jira API request failed: ${errorMessage}` };

   // After:
   return { success: false, error: `Jira API request failed: ${sanitizeJiraError(error)}` };
   ```

3. Update `validate()` catch block (lines 314-321):
   ```typescript
   // Before:
   const errorMessage = error instanceof Error ? error.message : String(error);
   return { success: false, error: `Jira API connection failed: ${errorMessage}` };

   // After:
   return { success: false, error: `Jira API connection failed: ${sanitizeJiraError(error)}` };
   ```

**Impact on existing tests:**
- The test `'returns error for network failure'` checks for `'Network unreachable'` in the error message. This string does not match any redaction pattern, so the test still passes.
- The test `'returns error on network failure during validate'` checks for `'DNS resolution failed'` -- also unaffected by redaction patterns.

**Verification:**
- `bun test __tests__/packages/luca-framework/src/adapters/jira-adapter.test.ts` -- all existing tests pass
- New tests verify credential redaction (see Task 4)

### Task 4: Add Zod response schema for Jira API

**Goal**: Add runtime validation of the Jira API response shape to catch malformed data early, replacing the TypeScript-only `as JiraIssueResponse` cast.

**File:** `packages/luca-framework/src/adapters/jira-adapter.ts`

**Changes:**
1. Add a Zod schema at module level for the Jira issue response:
   ```typescript
   const jiraIssueResponseSchema = z.object({
     key: z.string(),
     fields: z.object({
       summary: z.string(),
       description: z.unknown(),
       issuetype: z.object({ name: z.string() }).optional(),
       priority: z.object({ name: z.string() }).optional(),
       status: z.object({ name: z.string() }).optional(),
       assignee: z.object({ displayName: z.string() }).optional(),
     }),
   });
   ```

2. Replace the TypeScript cast with Zod parsing in `getTicket()` (line 247):
   ```typescript
   // Before:
   const data: JiraIssueResponse = await response.json();

   // After:
   const rawData = await response.json();
   const parseResult = jiraIssueResponseSchema.safeParse(rawData);
   if (!parseResult.success) {
     return {
       success: false,
       error: `Jira API returned unexpected response format: ${parseResult.error.message}`,
     };
   }
   const data = parseResult.data;
   ```

3. The `JiraIssueResponse` TypeScript interface (lines 34-44) can be replaced with `z.infer<typeof jiraIssueResponseSchema>` or kept as documentation alongside the schema. Recommendation: keep the interface for documentation but derive it from the schema:
   ```typescript
   type JiraIssueResponse = z.infer<typeof jiraIssueResponseSchema>;
   ```

**Impact on existing tests:**
- All existing test fixtures (`fullJiraIssueResponse`, `minimalJiraIssueResponse`) conform to the schema, so existing tests pass unchanged.
- However, the `minimalJiraIssueResponse` fixture uses `undefined` for optional fields. With `z.optional()`, undefined values are accepted. Verify this is the case (Zod `.optional()` allows `undefined`).

**Verification:**
