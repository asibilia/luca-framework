## Objective

Harden the template rendering pipeline by restricting EJS to safe output-only mode (`<%= %>`), replacing the manual YAML frontmatter generator with the `js-yaml` library for proper escaping, and sanitizing section titles used as XML tag names in the Cursor format output. This wave is fully independent and can run at any point.

- `__tests__/packages/luca-framework/src/utils/template.test.ts` -- 15+ tests; includes tests for `<% %>` code blocks (lines 43-57) and `<%- %>` unescaped output (lines 59-65) that will need updating

### Task 2: Restrict EJS to safe output mode in template.ts

**Goal**: Add template content sanitization that converts `<%- %>` (unescaped output) to `<%= %>` (escaped output) and strips `<% %>` (code execution) tags, then apply this sanitization before `ejs.render()`.

**File:** `packages/luca-framework/src/utils/template.ts`

**Changes:**
1. Add a `sanitizeTemplate()` function before `processTemplate()`:
   ```typescript
   /**
    * Sanitize EJS template content to only allow safe output tags.
    *
    * - Converts <%- %> (unescaped output) to <%= %> (escaped output)
    * - Strips <% %> (code execution) tags entirely
    * - Leaves <%= %> (safe output) unchanged
    */
   function sanitizeTemplate(content: string): string {
     // Step 1: Convert <%- (unescaped) to <%= (escaped)
     let sanitized = content.replace(/<%-([\s\S]*?)%>/g, '<%=$1%>');
     // Step 2: Strip <% %> code execution tags (NOT <%= output tags)
     sanitized = sanitized.replace(/<%(?!=)([\s\S]*?)%>/g, '');
     return sanitized;
   }
   ```

2. Update `processTemplate()` to call `sanitizeTemplate()` before rendering:
   ```typescript
   export async function processTemplate(
     templateContent: string,
     context: Record<string, unknown>
   ): Promise<string> {
     const safeContent = sanitizeTemplate(templateContent);
     return render(safeContent, context, {
       strict: false,
     });
   }
   ```

3. Update the JSDoc comment for `processTemplate()` to reflect the new security behavior:
   - Remove documentation of `<%- %>` and `<% %>` as supported syntax
   - Document that only `<%= %>` is supported
   - Note that `<%-` is automatically converted to `<%=` for backward compatibility

**Impact on existing tests:**
- `template.test.ts` test `'handles EJS code blocks'` (line 43): `<% if (show) { %>visible<% } %>` -- after sanitization, the `<% if (show) { %>` and `<% } %>` tags are stripped, leaving just `visible`. The test expects `'visible'` when `show: true`, which will now always return `'visible'` regardless of `show`. This test needs updating.
- `template.test.ts` test `'returns empty for false conditional'` (line 51): Same template, `show: false` -- after sanitization, still returns `'visible'` since conditionals are stripped. This test needs updating.
- `template.test.ts` test `'handles unescaped output'` (line 59): `<%- raw %>` becomes `<%= raw %>` -- the output will be HTML-escaped. If `raw = '<b>bold</b>'`, the result becomes `'&lt;b&gt;bold&lt;/b&gt;'` instead of `'<b>bold</b>'`. This test needs updating.

### Task 4: Replace manual YAML generation with js-yaml

**Goal**: Replace the hand-rolled string concatenation in `formatFrontmatter()` with `js-yaml`'s `dump()` function, which automatically handles escaping of special YAML characters.

**File:** `src/shared/utils.ts`

**Changes:**
1. Add import at top of file:
   ```typescript
   import yaml from 'js-yaml';
   ```

2. Replace the entire `formatFrontmatter()` function body:
   ```typescript
   export function formatFrontmatter(frontmatter: Record<string, unknown>): string {
     if (Object.keys(frontmatter).length === 0) {
       return '---\n---';
     }
     const yamlContent = yaml.dump(frontmatter, {
       indent: 2,
       lineWidth: -1,
       quotingType: '"',
       forceQuotes: false,
       sortKeys: false,
     });
     return `---\n${yamlContent.trimEnd()}\n---`;
   }
   ```

**Key behavioral differences from manual implementation:**
- js-yaml only quotes strings when necessary (special chars, leading/trailing spaces, reserved words)
- Simple strings like `my-agent` will NOT be quoted (manual implementation always quoted strings)
- Booleans: `true`/`false` rendered the same
- Arrays: `- item` format (same, but indentation may differ slightly)
- Nested objects: indented `key: value` (same format)
- Empty object: handled by the explicit check, returns `---\n---`

### Task 6: Add XML tag name sanitization to format.ts

**Goal**: Sanitize section titles before using them as XML tag names in `toCursorFormat()`, ensuring only valid characters (`[a-z0-9_-]`) appear in tag names.

**File:** `src/shared/format.ts`

**Changes:**
1. Add a `sanitizeTagName()` function:
   ```typescript
   /**
    * Sanitize a string for use as an XML tag name.
    * Allows only [a-z0-9_-], replaces other characters with hyphens,
    * collapses consecutive hyphens, and ensures the result starts with a letter.
    */
   function sanitizeTagName(name: string): string {
     const sanitized = name
       .toLowerCase()
       .replace(/[^a-z0-9_-]/g, '-')
       .replace(/-+/g, '-')
       .replace(/^-|-$/g, '');

     if (!sanitized || /^[0-9]/.test(sanitized)) {
       return `section-${sanitized || 'unknown'}`;
     }
     return sanitized;
   }
   ```

2. Update `toCursorFormat()` to use `sanitizeTagName()` instead of raw `.toLowerCase()`:
   ```typescript
   // Before (line 21):
   return `\n<${section.title.toLowerCase()}>\n${section.content}\n</${section.title.toLowerCase()}>\n`;

   // After:
   const tagName = sanitizeTagName(section.title);
   return `\n<${tagName}>\n${section.content}\n</${tagName}>\n`;
   ```

### Task 8: Add path traversal prevention in copyTemplates()

**Goal**: Prevent path traversal attacks when template filenames are processed through `processFilename()`. If a variable value contains `../`, the resolved output path could escape the destination directory.

**File:** `packages/luca-framework/src/utils/template.ts`

**Changes:**
1. Add a `assertWithinDirectory()` helper:
   ```typescript
   import { resolve, relative } from 'pathe';

   /**
    * Verify that a resolved path is within the expected base directory.
    * Prevents path traversal via '../' in variable values.
    */
   function assertWithinDirectory(filePath: string, baseDir: string): void {
     const resolved = resolve(filePath);
     const base = resolve(baseDir);
     const rel = relative(base, resolved);
     if (rel.startsWith('..') || resolve(base, rel) !== resolved) {
       throw new Error(`Path traversal detected: ${filePath} escapes ${baseDir}`);
     }
   }
   ```

2. In `copyTemplates()`, after `processFilename()` produces the output filename and before writing the file, call:
   ```typescript
   const outputPath = join(destDir, processedFilename);
   assertWithinDirectory(outputPath, destDir);
   ```

3. Similarly, when constructing source paths with user-influenced values, add the containment check.
