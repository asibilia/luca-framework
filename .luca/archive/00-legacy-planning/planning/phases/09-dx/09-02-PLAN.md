# Plan 09-02: Doctor Command — Verbose Mode, Fix Commands, and Deep Config Validation

## Frontmatter
- **ID**: 09-02
- **Title**: Doctor Command — Verbose Mode, Fix Commands, and Deep Config Validation
- **Wave**: 1
- **Depends on**: none

## Objective
Fix the doctor command so that (1) `--verbose` actually works instead of being a no-op, (2) fix suggestions reference commands that actually exist, (3) config validation checks branding field values (not just top-level key existence), and (4) JSON parse errors produce actionable diagnostics. Currently the doctor command advertises features it does not implement and suggests flags (`--force`, `--repair`) that do not exist.

## Context
- `packages/luca-framework/src/commands/doctor.ts` — Doctor command definition, declares `--verbose` arg but never reads it (lines 9-15, 17-20)
- `packages/luca-framework/src/utils/doctor/index.ts` — `executeDoctor()` takes no parameters, suggests `--verbose` in error message (line 67)
- `packages/luca-framework/src/utils/doctor/checks/config-validation.ts` — Config validation check with non-existent fix commands and shallow validation (lines 27-71)
- `packages/luca-framework/src/utils/doctor/types.ts` — `DoctorCheck` and `CheckResult` type definitions
- `packages/luca-framework/src/utils/branding.ts` — `validateBranding()` function available for reuse (line 117)
- `packages/luca-framework/src/utils/sanitize.ts` — `sanitizeJsonParse()` used for config parsing

**Pre-existing failures:** 6 tests in `executeDoctor`/`configValidationCheck` have `process.cwd()` mocking issues. These are NOT caused by Phase 9 changes and must NOT regress further.

### Task 2: Update `executeDoctor()` to accept and use verbose option
**Goal**: Make `executeDoctor()` accept a verbose flag and use it to (a) show extra details per check, and (b) remove the misleading "Run with --verbose" message when not in verbose mode.
**Findings**: DX-006 (HIGH)
**File:** `packages/luca-framework/src/utils/doctor/index.ts`
**Changes:**
1. Add an options parameter `{ verbose?: boolean }` to `executeDoctor()`.
2. When verbose is true, always show `result.details` for every check (not just failed ones).
3. Remove or conditionalize the `"Run with --verbose for more details"` message at line 67. When not verbose, say `"Run with --verbose to see details."` as actionable guidance. When verbose, omit the message since details are already shown.

**Before (lines 4, 26-40, 66-68):**
```typescript
export async function executeDoctor(): Promise<number> {
  // ...
  for (const result of results) {
    // ...
    if (result.details) {
      logger.info(`  ${result.details}`);
    }
  }
  // ...
  if (failCount > 0) {
    logger.error('Some checks failed. Run with --verbose for more details.');
    return 1;
  }
```

**After:**
```typescript
export async function executeDoctor(options: { verbose?: boolean } = {}): Promise<number> {
  const { verbose = false } = options;
  // ...
  for (const result of results) {
    // ...
    if (result.details && (verbose || result.status !== 'pass')) {
      logger.info(`  ${result.details}`);
    }
  }
  // ...
  if (failCount > 0) {
    if (!verbose) {
      logger.error('Some checks failed. Run with --verbose to see full details.');
    } else {
      logger.error('Some checks failed. Review the details above.');
    }
    return 1;
  }
```

**Verification:**
- `luca doctor` (no verbose) shows details only for non-passing checks, suggests `--verbose`
- `luca doctor --verbose` shows details for ALL checks, does not suggest `--verbose`
- `bun test` — no new failures

### Task 4: Add deep branding validation to config-validation check
**Goal**: Validate branding sub-fields (frameworkName, commandPrefix, ticketPattern, placeholderTicket) and their formats, not just top-level key existence. Also validate `stack` and `workTracker` values.
**Findings**: DX-010 (HIGH)
**File:** `packages/luca-framework/src/utils/doctor/checks/config-validation.ts`
**Changes:**
1. Import `validateBranding` from `../../branding`.
2. After the top-level key check passes, validate branding field values using `validateBranding()`.
3. Validate that `stack` is a string value.
4. Validate that `workTracker` is one of `'jira' | 'github' | 'none'`.
5. Return warnings (not failures) for invalid values, since the project may still function.

**Before (lines 29-41):**
```typescript

    const missingFields = requiredFields.filter(f => !config[f]);

    if (missingFields.length > 0) {

        name: this.name,

        details: `Missing required fields: ${missingFields.join(', ')}`,

```

**After (insert deep validation after the missing fields check and before the manifest check):**
```typescript
    const requiredFields = ['branding', 'stack', 'workTracker'];
    const missingFields = requiredFields.filter(f => !config[f]);

    if (missingFields.length > 0) {
      return {
        name: this.name,
        status: 'fail',
        message: 'config.json invalid',
        fixCommand: 'Delete .planning/ directory, then run: npx luca init',
        details: `Missing required fields: ${missingFields.join(', ')}`,
      };
    }

    // Deep validation of branding fields
    const warnings: string[] = [];

    if (config.branding && typeof config.branding === 'object') {
      const brandingValidation = validateBranding(config.branding as Record<string, string>);
      if (!brandingValidation.valid) {
        const errorList = Object.entries(brandingValidation.errors)
          .map(([field, error]) => `${field}: ${error}`)
          .join('; ');
        warnings.push(`Branding validation: ${errorList}`);
      }
    }

    // Validate workTracker value
    const validTrackers = ['jira', 'github', 'none'];
    if (config.workTracker && !validTrackers.includes(config.workTracker as string)) {
      warnings.push(`workTracker "${config.workTracker}" is not a recognized value (expected: ${validTrackers.join(', ')})`);
    }

    if (warnings.length > 0) {
      return {
        name: this.name,
        status: 'warning',
        message: 'config.json has validation warnings',
        fixCommand: 'Review .planning/config.json and correct the flagged values',
        details: warnings.join('. '),
      };
    }
```

Also add the import at the top of the file:
