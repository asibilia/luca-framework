# 05-02: Type Safety

## Objective
Eliminate `any` types from core type definitions and shared utilities. Replace with proper generics or `unknown`.

## Tasks

### Task 1: Fix Index Signatures in Type Definitions
**Files:**
- `src/agents/types/agent.types.ts:13` — `[key: string]: any` → `[key: string]: unknown`
- `src/skills/types/skill.types.ts:12` — `[key: string]: any` → `[key: string]: unknown`
- `src/rules/types/rule.types.ts:12` — `[key: string]: any` → `[key: string]: unknown`

**Impact analysis:**
- These index signatures allow arbitrary properties on frontmatter objects
- Changing to `unknown` forces callers to narrow types before use
- Check all consumers of `AgentFrontmatter`, `SkillFrontmatter`, `RuleFrontmatter`
- Update Zod schemas if needed to match

### Task 2: Tighten Shared Utility Types
**File:** `src/shared/utils.ts`
- `formatFrontmatter(frontmatter: Record<string, any>)` → `Record<string, unknown>`
- Update internal handling to properly narrow types

### Task 3: Fix `any` in Rule Content Files
**Files:**
- `src/rules/general/no-classes.rule.ts:100` — cache set method `(key: string, value: any)`
- `src/rules/general/functional-api-reuse.rule.ts:94-97` — object transform helpers

Note: These are in code examples within rule content strings. If fixing would break the example readability, add a comment explaining the intentional `any`.

## Exit Criteria
- Zero `any` in `src/*/types/*.ts` files
