# Phase 4 Plan 1: Graph Data Foundation

## Objective

Build the data foundation for the Knowledge Graph Explorer: type definitions, a new `/api/muninn/graph-data` API route that returns nodes+links (not JSON-LD), the `useKnowledgeGraph` data hook, nav registration, and the page shell. After this plan, the page exists in the app with real data flowing from MuninnDB, ready for visual components.

### 3. Create /api/muninn/graph-data route

**Type:** auto
**TDD:** false
**Depends on:** none

Create a new API route that returns graph data in `{ nodes, links }` format ready for ForceGraph2D. This is the CRITICAL fix for Pitfall 4+5 from research: `exportGraph` returns JSON-LD with zero edges, so we need a dedicated route.

**Implementation:**

- Use `muninnProxyHandler` and `parseQueryParams` from `muninn-route-helper.ts`
- Create `GraphDataQuerySchema` with vault (default "default") and limit (default 500, max 2000) parameters
- Inside the handler:
  1. Call `client.listEngrams(vault, limit)` to get engrams with tags and timestamps
  2. Call `client.entityClusters(vault, 100, 1)` to get co-occurrence edges
  3. Build entity nodes from engram tags (aggregate: name, resolved type, engram_count, first_seen, last_seen)
  4. Build links from entityClusters (source=entity_a, target=entity_b, weight=count)
  5. Use the same `resolveEngramType` logic (memory_type field or concept prefix) for type classification
  6. Return `{ nodes, links, total_nodes, total_links }`
- Use `Promise.all` for parallel fetching of engrams and clusters
- Add the GraphDataQuerySchema and GraphDataResponseSchema to `muninn-schemas.ts`

**Files to create:**

- `packages/luca-observer/app/api/muninn/graph-data/route.ts`

**Files to edit:**

- `packages/luca-observer/lib/muninn-schemas.ts` — add GraphDataQuerySchema, GraphDataResponseSchema

**Verification:**

- `bunx --bun tsc --noEmit` passes
- Route handler follows the exact same pattern as existing routes (e.g., entity-clusters/route.ts)
- Response shape: `{ nodes: [{id, name, type, engram_count, first_seen, last_seen}], links: [{source, target, weight}], total_nodes, total_links }`

### 4. Create useKnowledgeGraph hook

**Type:** auto
**TDD:** false
**Depends on:** 2, 3

Create the data hook following the canonical `use-vault-health.ts` pattern. This hook owns ALL state for the knowledge graph view.

**State managed:**

- `rawNodes` / `rawLinks` — raw data from API
- `expandedTypes` — Set<string> of expanded cluster types
- `selectedNode` — currently selected GraphNode or null
- `hoveredNode` — currently hovered GraphNode or null
- `timeRange` — [start, end] timestamps or null (no filter)
- `loading` / `error` / `lastUpdated` / `configured`

**Derived data (useMemo):**

- `graphData` — computed from rawNodes+rawLinks+expandedTypes+timeRange via `buildClusteredGraph`
- `timeExtent` — [min, max] timestamps across all nodes (for slider bounds)
- `timeHistogram` — array of bucket counts for the slider histogram

**Functions exposed:**

- `toggleCluster(type: string)` — expand/collapse a cluster type
- `selectNode(node: GraphNode | null)` — set selected node
- `hoverNode(node: GraphNode | null)` — set hovered node
- `setTimeRange(range: [number, number] | null)` — set time filter
- `refresh()` — re-fetch all data
- `resetView()` — clear selection, collapse all clusters, clear time filter

**Key implementation details:**

- Use `fetchingRef` to prevent double-fetch in React strict mode
- Use `Promise.allSettled` for resilient data fetching
- Check for 503 NotConfiguredError (same pattern as use-vault-health)
- `buildClusteredGraph` function: groups nodes by type, creates cluster supernodes for collapsed types, filters links to only show visible node endpoints
- Time filtering: exclude nodes outside timeRange before cluster building
- Memoize graphData with `useMemo([rawNodes, rawLinks, expandedTypes, timeRange])`

**Files to create:**

- `packages/luca-observer/hooks/use-knowledge-graph.ts`

**Verification:**

- `bunx --bun tsc --noEmit` passes
- Hook exports all listed state and functions
- buildClusteredGraph logic handles: all collapsed (only clusters), one expanded (mix), all expanded (all individual nodes)
