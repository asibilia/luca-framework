# Phase 126 Plan 05: Todo Tracking Integration

## Task Objective

Display todos from the `.planning/todos/` directory in the observer dashboard, providing visibility into project work items with clear state differentiation and metadata.

## Context

- Todos exist in `.planning/todos/pending/` and `.planning/todos/done/` directories
- Todo files contain frontmatter metadata (title, area, priority, source, created date)
- Need to decide between filesystem reads vs SpacetimeDB table for data source
- Should be displayed alongside existing notes in observer dashboard
- Clear visual differentiation needed between pending and done states

## Files to Create

1. `components/dashboard/todo-tracker.tsx` - New component for displaying todos
2. `hooks/use-todos.ts` - Hook for reading and parsing todo files

OR (if using SpacetimeDB):
1. `tables/todos.ts` - SpacetimeDB table definition for todos

## Files to Update

1. `app/page.tsx` - Integrate todo tracker into dashboard
2. Potentially `hooks/use-ledger.ts` if using SpacetimeDB approach

## Execution Steps

1. **Data Source Decision:**
   - Option A: Filesystem reads (simpler, direct access to todo files)
     - Use Bun's filesystem APIs to read markdown files
     - Parse frontmatter for metadata
     - Pros: Direct, no duplication
     - Cons: Requires server-side reads, not reactive
   
   - Option B: SpacetimeDB table (more complex, but integrated with existing architecture)
     - Add todo entries to existing SpacetimeDB schema
     - Already in ledger.jsonl, can be materialized in tables
     - Pros: Reactive, consistent with other data
     - Cons: Requires schema changes, dual-write complexity
   
   - **Decision**: Start with filesystem reads for simplicity, can migrate to SpacetimeDB later

2. **Create use-todos Hook:**
   - Read from `.planning/todos/pending/*.md` and `.planning/todos/done/*.md`
   - Parse frontmatter metadata (title, area, priority, created, source)
   - Return typed todo items with state (pending/done)
   - Handle errors gracefully

3. **Create TodoTracker Component:**
   - Display todos in organized sections (Pending / Done)
   - Show metadata: title, area, created date, source
   - Visual differentiation:
     - Pending: Yellow/warning styling
     - Done: Green/success styling with strikethrough
   - Include counts for each section
   - Support sorting/filtering by area if needed

4. **Integrate into Dashboard:**
   - Add TodoTracker to main dashboard page alongside existing sections
   - Ensure layout works with other dashboard components
   - Add loading state while reading todos

5. **Testing:**
   - Verify todos display correctly from both directories
   - Test with empty directories (show empty state)
   - Verify metadata parsing is accurate

## Verification

- [ ] `hooks/use-todos.ts` exists and exports useTodos hook

- [ ] Dashboard displays todos from both pending and done directories

- [ ] TypeScript compiles without errors

- Metadata accurately displayed for each todo
- Performance is acceptable for typical todo counts (<100 files)
- Users can track project work items at a glance
- Architecture allows for future SpacetimeDB migration
