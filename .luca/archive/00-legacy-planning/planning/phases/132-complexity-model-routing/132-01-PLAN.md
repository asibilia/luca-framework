# Plan 132-01: Audit complexity reads and add model routing table

## Objective

Replace complexity-based step skipping with per-agent model routing. Audit all complexity reads, enhance the model routing table, and create granular sub-agents.

## Context

Existing infrastructure:

- `src/complexity/__schemas/complexity.schemas.ts` — ModelTierSchema (fast/balanced/capable), ComplexityLevel, gating matrix
- `src/agents/__schemas/agent.schemas.ts` — already has `model_tier: ModelTierSchema.optional()` and `model_routing` config
- Model routing was added in v2.3.0

## Tasks

### Task 1: Audit all complexity reads for step-skipping behavior

- Grep for `complexity` across `src/` to find all reads
- Categorize each read as: "gates a step" vs "informs routing" vs "informational"
- Document findings in a catalog: file, line, purpose, skip-or-route
- Check `packages/luca-framework/src/state/guards.ts` for guard-based skipping

### Task 2: Add modelTier field to all agent definitions

- Read all `.agent.ts` files in `src/agents/general/` and `src/agents/luca/`
- For agents missing `model_tier`, add the appropriate tier:
  - `fast`: lightweight agents (lu-learner, lu-cognition)
  - `balanced`: standard agents (lu-executor, lu-planner, lu-router)
  - `capable`: deep-analysis agents (lu-verifier, lu-debugger, code-architect)

### Task 3: Create model-routing table

- Read existing `MODEL_TIER_TO_MODEL` in complexity schemas
- Create `src/complexity/__helpers/model-routing.ts` with:
  - `ModelRoutingTableSchema` — maps agent name -> complexity level -> model tier
  - `resolveModelForAgent(agentName: string, complexity: ComplexityLevel): ModelTier` — returns the right model tier
  - Default routing: at TRIVIAL/SIMPLE use fast, at MODERATE use balanced, at COMPLEX/CRITICAL use capable
  - Allow per-agent overrides
- Export from `src/complexity/index.ts`

### Task 4: Document complexity matrix repurposing

- The current complexity matrix (skip/run) should evolve to a routing matrix (which model tier to use)
- Document the transition plan in a SUMMARY noting which steps transition from skip/run to model routing
- Do NOT remove the existing matrix yet — that's a follow-up

## Verification Criteria

- [ ] All complexity reads audited and categorized
- [ ] All agents have model_tier defined
- [ ] Model routing table resolves agent -> complexity -> tier
- [ ] `bunx --bun tsc --noEmit` passes
- [ ] `bun test` passes
