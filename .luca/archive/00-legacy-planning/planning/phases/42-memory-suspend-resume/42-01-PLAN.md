# 42-01: Suspend/Resume, Checkpoint Persistence, Auto-Persist on Context Warning

## Objective

Implement step-level suspend/resume within phases (MEM-01, MEM-03), auto-persist WORKING.md on context HIGH warning (MEM-02), and checkpoint persistence for suspended phases. After this plan, the workflow can be suspended mid-phase and resumed later with full context restoration.

## Context

### Current State

- The workflow machine has 12 states but no `suspended` state distinct from `paused`
- `paused` is triggered by `VERIFY_HALTED` (human review needed) — different from suspension
- Session-level pause exists (`session-pause.skill.ts`) creating `.continue-here.md`, but it's manual and session-scoped, not phase-scoped
- Iteration checkpoints exist (`src/iteration/checkpoint.ts`) for error recovery, but not for intentional suspension
- Context monitor detects degrading/stop zones but doesn't auto-persist WORKING.md
- The `context-monitor.sh` hook warns but doesn't take action

### Design Decisions

1. **`suspended` as a new state (not reusing `paused`)**: Paused is specifically for human verification holds. Suspended is for context warnings and intentional phase suspension with resume metadata.
2. **Checkpoint file format**: JSON at `.planning/checkpoints/suspend-{phase}.json` with phase progress, wave index, completed tasks, and WORKING.md snapshot.
3. **Auto-persist trigger**: When context monitor detects `degrading` or `stop` zone, auto-serialize WORKING.md to disk and optionally trigger SUSPEND event.
4. **Resume flow**: RESUME_PHASE event loads checkpoint, restores wave index and progress, and re-enters executing state.

### Task 2: Add Suspended State to Machine (42-01-T2)

**Goal:** Wire the `suspended` state into the state machine with proper transitions.

**Transitions:**

- `executing` + `SUSPEND` → `suspended` (persist checkpoint, record metadata)
- `suspended` + `RESUME_PHASE` → `executing` (restore from checkpoint)
- `suspended` + `ABORT` → `idle` (abandon suspended work)
- `suspended` + `RESET` → `idle` (full reset)

**Actions on SUSPEND:**

- Set `suspend_metadata` with timestamp, reason, and checkpoint path
- Record last_transition_at

**Actions on RESUME_PHASE:**

- Clear `suspend_metadata`
- Restore wave index if checkpoint provides it

**Verification:** Machine transitions correctly between executing ↔ suspended. Existing tests still pass.

### Task 4: Auto-Persist WORKING.md on Context Warning (42-01-T4)

**Goal:** When context usage reaches "degrading" or "stop" zone, auto-persist WORKING.md.

**Changes to `context-monitor.ts`:**

Add an `autoPersistWorking()` method to the context monitor factory:

```typescript
autoPersistWorking: async (): Promise<{ persisted: boolean; zone: string }> => {
  const usage = await checkContextUsage();
  if (usage.zone === "degrading" || usage.zone === "stop") {
    // Read current WORKING.md, serialize with timestamp marker
    const workingFile = Bun.file(join(projectDir, ".planning/WORKING.md"));
    if (await workingFile.exists()) {
      const content = await workingFile.text();
      const parsed = parseWorkingMemory(content);
      if (parsed.success) {
        const withMarker = addSection(
          parsed.data,
          "session_info",
          `\n**Auto-persisted:** ${new Date().toISOString()} (zone: ${usage.zone})`,
        );
        await Bun.write(
          join(projectDir, ".planning/WORKING.md"),
          serializeWorkingMemory(withMarker),
        );
        return { persisted: true, zone: usage.zone };
      }
    }
    return { persisted: false, zone: usage.zone };
  }
  return { persisted: false, zone: usage.zone };
};
```

**Changes to `context-monitor.sh`:**

Add auto-persist call when zone is degrading/stop:

```bash
# After detecting high usage, auto-persist working memory
if [ "$ZONE" = "degrading" ] || [ "$ZONE" = "stop" ]; then
  bun run src/memory/bridge.ts append-working \
    --section=session_info \
    --content="Auto-persisted at $(date -u +%Y-%m-%dT%H:%M:%SZ) (zone: $ZONE)" \
    2>/dev/null || true
fi
```

**Verification:** Context monitor hook auto-persists when zone is degrading. Unit test for autoPersistWorking().

### Task 5: Phase-Execute Suspend Semantics (42-01-T5)

**Goal:** Update phase-execute skill to handle suspension gracefully.

**Additions to phase-execute skill instructions:**

1. Before each wave, check context usage via `bun run src/memory/bridge.ts check-context`
2. If zone is "stop", trigger suspension:
   - Create suspend checkpoint with current progress
   - Send SUSPEND event via bridge: `luca-state transition --event=SUSPEND --data='{"reason":"context_exhaustion"}'`
   - Write `.continue-here.md` with resume instructions
   - Exit skill with suspension notice
3. On resume (detected via suspend checkpoint):
   - Load checkpoint: `loadSuspendCheckpoint(phaseId)`
   - Skip completed waves
   - Continue from the wave_index in checkpoint
   - Clear checkpoint after successful completion

**Verification:** Phase-execute skill instructions reference suspend/resume flow.
