# Phase 02: Strip SpacetimeDB from Observer - Research

**Researched:** 2026-03-09
**Domain:** SpacetimeDB dependency removal / Next.js observer app cleanup
**Confidence:** HIGH

## Summary

This research catalogs the complete SpacetimeDB deletion surface in the `packages/luca-observer` Next.js app. The investigation identified 43 files in `module_bindings/`, 15 SpacetimeDB-dependent hooks, 8 page components to replace with placeholders, 18 components to delete, and 4 files requiring surgical modification (providers.tsx, header.tsx, next.config.ts, notes/page.tsx).

The dependency graph is straightforward: `module_bindings/` is the root of the SpacetimeDB data layer. All 15 SpacetimeDB hooks import from it. All 8 SpacetimeDB-dependent pages import from those hooks. Component cascading is clean -- each component directory (agents/, cost/, decisions/, harness/, iteration/, planning/, tribunal/, workflow/) maps to exactly one page route.

**Primary recommendation:** Delete bottom-up: module_bindings/ directory first, then hooks, then components, then page implementations. Modify providers.tsx, header.tsx, next.config.ts, and notes/page.tsx. Remove `spacetimedb` from package.json. This ordering prevents transient import errors during execution.

## Architecture Patterns

### Pattern 1: Bottom-Up Deletion Order

**What:** Delete files in dependency order to avoid transient broken imports during multi-file operations.
**When to use:** When removing an entire dependency tree.

**Deletion order:**

```
1. module_bindings/  (43 files - leaf dependency, imported by hooks)
2. hooks/use-*.ts    (15 SpacetimeDB hooks - imported by pages/components)
3. components/       (18 domain components consumed only by deleted pages)
4. app/*/page.tsx    (8 page files - replace with placeholders)
5. lib/spacetimedb-config.ts  (config file - only imported by providers.tsx)
6. Modify: providers.tsx, header.tsx, next.config.ts, notes/page.tsx
7. package.json      (remove spacetimedb dependency)
```

### Pattern 2: Placeholder Page Template

**What:** Minimal "coming soon" page that preserves the route.
**When to use:** For all 8 pages being gutted.

```tsx
import { PageContainer } from "~/components/layout/page-container";

export default function PlaceholderPage() {
  return (
    <PageContainer
      title="[Page Name]"
      subtitle="Coming soon — rebuilding with MuninnDB"
    >
      <div className="flex flex-col items-center justify-center py-16 text-center">
        <p className="font-mono text-sm text-muted-foreground">
          This page is being rebuilt with MuninnDB data sources.
        </p>
      </div>
    </PageContainer>
  );
}
```

### Anti-Patterns to Avoid

- **Partial deletion:** Do not leave any file that imports from `module_bindings` or `spacetimedb` -- the package will be removed, so any remaining import will cause build failure.
- **Leaving dead code in providers.tsx:** Remove the entire SpacetimeDBProvider wrapper, not just comment it out.

## Common Pitfalls

### Pitfall 1: Missing Import Cleanup in notes/page.tsx

**What goes wrong:** The CONTEXT.md says "Keep notes/page.tsx (uses /api/todos)" but the actual notes/page.tsx uses `useTable` and `useReducer` from `spacetimedb/react` plus `tables, reducers` from `~/module_bindings`. It does NOT use `useTodos`.
**Why it happens:** The CONTEXT.md conflated the notes page with the todo tracker (which does use /api/todos).
**How to avoid:** Treat notes/page.tsx as a SpacetimeDB-dependent page and replace it with a placeholder. The TodoTracker component (on the dashboard) is the one that uses /api/todos.
**Warning signs:** Build errors referencing `spacetimedb/react` or `~/module_bindings` in notes/page.tsx.

### Pitfall 2: StatusIndicator Depends on Deleted Hook

**What goes wrong:** `components/shared/status-indicator.tsx` imports `useWorkflowState` from `~/hooks/use-workflow-state` which is being deleted. This component is rendered by `components/layout/header.tsx` which is in the layout, so it breaks every page.
**Why it happens:** StatusIndicator is in `components/shared/` (looks clean) but actually depends on a SpacetimeDB hook.
**How to avoid:** Either replace StatusIndicator with a static version or remove it from the header.
**Warning signs:** Build failures in the layout that cascade to all pages.

### Pitfall 3: Header Connection Status Uses SpacetimeDB Hook

**What goes wrong:** `components/layout/header.tsx` directly imports `useSpacetimeDB` from `spacetimedb/react` for connection status display. This is a layout-level component rendered on every page.
**Why it happens:** Connection status was a core feature of the SpacetimeDB-backed observer.
**How to avoid:** Remove the `useSpacetimeDB` import and connection status UI from the header.
**Warning signs:** Build failure on `import { useSpacetimeDB } from "spacetimedb/react"`.

### Pitfall 4: CSP Headers Reference SpacetimeDB WebSocket URI

**What goes wrong:** `next.config.ts` derives WebSocket URIs from `NEXT_PUBLIC_SPACETIMEDB_URI` env var for Content-Security-Policy headers. After SpacetimeDB removal, these references are dead code and the env var is unnecessary.
**Why it happens:** CSP was configured to allow WebSocket connections to SpacetimeDB.
**How to avoid:** Simplify `connect-src` to just `'self'` and remove the WebSocket URI derivation.

### Pitfall 5: Orphaned Component Directories

**What goes wrong:** After deleting all files in a component directory (e.g., `components/agents/`), the empty directory remains.
**Why it happens:** `git rm` removes files but may leave empty dirs (git doesn't track empty dirs).
**How to avoid:** Use `rm -rf` for entire component directories after confirming all files are accounted for.

## Code Examples

### Simplified providers.tsx (after cleanup)

```tsx
"use client";

import { useEffect } from "react";
import type { ReactNode } from "react";

import { Provider as JotaiProvider, useAtomValue } from "jotai";

import { themeAtom } from "~/stores/theme";

function ThemeSync() {
  const theme = useAtomValue(themeAtom);

  useEffect(() => {
    const root = document.documentElement;
    root.classList.remove("dark", "light");
    root.classList.add(theme);
  }, [theme]);

  return null;
}

export function Providers({ children }: { children: ReactNode }) {
  return (
    <JotaiProvider>
      <ThemeSync />
      {children}
    </JotaiProvider>
  );
}
```

### Simplified header.tsx (after cleanup)

```tsx
"use client";

import { useAtom } from "jotai";
import { PanelLeftClose, PanelLeftOpen, Sun, Moon } from "lucide-react";

import { sidebarOpenAtom } from "~/stores/sidebar";
import { themeAtom } from "~/stores/theme";

export function Header() {
  const [isOpen, setIsOpen] = useAtom(sidebarOpenAtom);
  const [theme, setTheme] = useAtom(themeAtom);

  const toggleTheme = () => setTheme(theme === "dark" ? "light" : "dark");

      role="banner"

            <PanelLeftOpen className="h-4 w-4" />
```
