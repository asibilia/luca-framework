# Plan 04-03: Command Tests

## Frontmatter
- **ID**: 04-03
- **Title**: Command Tests (init, update, doctor)
- **Wave**: 2
- **Depends on**: 04-01

## Objective

Write unit tests for the three CLI commands: `init`, `update`, and `doctor`. These are the user-facing entry points that orchestrate multiple utilities. Testing focuses on the decision-tree logic within each command's `run()` function -- which code path is taken based on arguments and detected context -- using mocked dependencies throughout.

## Context

- `packages/luca-framework/src/commands/init.ts` -- `initCommand` (citty `defineCommand`), orchestrates detect, wizard, files
- `packages/luca-framework/src/commands/update.ts` -- `updateCommand`, orchestrates manifest, template, backup, conflict resolution
- `packages/luca-framework/src/commands/doctor.ts` -- default export, delegates to `executeDoctor()`
- `packages/luca-framework/src/types.ts` -- `LucaConfig`, `ProjectContext`, `LucaManifest`, `FileComparison`, `BrandingConfig`
- `__tests__/utils/mock-clack.ts` -- shared @clack/prompts mock (from 04-01)
- `__tests__/utils/fixtures.ts` -- `validLucaConfig`, `validProjectContext`, `validLucaManifest` (from 04-01)

## Tasks

### Task 1: Init Command Tests
**Goal**: Test all code paths in the init command's `run()` function.
**Files**: Create `__tests__/packages/luca-framework/src/commands/init.test.ts`
**Details**:

The init command has these dependencies to mock:
- `../utils/detect` -- `detectProjectContext()`
- `../utils/wizard` -- `runWizard()`, `createConfigFromArgs()`, `loadConfigFromFile()`
- `../utils/files` -- `generateFiles()`, `setupCleanupHandler()`
- `../utils/logger` -- `logger` (silence output)
- `@clack/prompts` -- `p.outro()`, `p.cancel()`
- `process.exit` -- prevent test process from exiting

Since all imports are module-level, use `mock.module()` BEFORE dynamically importing the command:

```typescript
import { describe, test, expect, mock, beforeEach, spyOn } from 'bun:test';
import { validLucaConfig, validProjectContext } from '../../../../utils/fixtures';
```

Mock setup pattern (call in `beforeEach` or per-test):

```typescript
// Mock process.exit to throw instead of exiting
const mockExit = spyOn(process, 'exit').mockImplementation((code?: number) => {
  throw new Error(`process.exit(${code})`);
});

// Mock all dependencies
mock.module('../../../../../../packages/luca-framework/src/utils/detect', () => ({
  detectProjectContext: async () => ({ ...validProjectContext, hasLuca: false }),
}));

mock.module('../../../../../../packages/luca-framework/src/utils/wizard', () => ({
  runWizard: async () => validLucaConfig,
  createConfigFromArgs: () => validLucaConfig,
  loadConfigFromFile: async () => validLucaConfig,
}));

mock.module('../../../../../../packages/luca-framework/src/utils/files', () => ({
  generateFiles: async () => ({ success: true, manifest: {} }),
  setupCleanupHandler: () => {},
}));

mock.module('../../../../../../packages/luca-framework/src/utils/logger', () => ({
  logger: { info: () => {}, error: () => {}, warn: () => {}, debug: () => {}, box: () => {}, success: () => {}, start: () => {}, step: () => {} },
}));

mock.module('@clack/prompts', () => ({
  outro: () => {},
  cancel: () => {},
  intro: () => {},
  note: () => {},
  spinner: () => ({ start: () => {}, stop: () => {} }),
}));
```

Then dynamically import:
```typescript
const { initCommand } = await import('../../../../../../packages/luca-framework/src/commands/init');
```

Access the `run` function from the citty command definition. The `run` property is a function that receives `{ args }`. Call it directly:

```typescript
await initCommand.run!({ args: { quick: false, config: undefined, name: undefined, prefix: undefined, stack: undefined, tracker: undefined } });
```

**Test cases:**

1. **Already installed (hasLuca === true)**: Mock `detectProjectContext` to return `{ ...validProjectContext, hasLuca: true }`. Expect `process.exit(1)` to be called (caught by mock). Verify logger.error was called with message about "already installed".

2. **Config file mode -- success**: Set `args.config = './luca.json'`. Mock `loadConfigFromFile` to return `validLucaConfig`. Mock `generateFiles` to return `{ success: true }`. Assert `generateFiles` was called, `p.outro` was called.

3. **Config file mode -- file error**: Mock `loadConfigFromFile` to throw `Error('ENOENT')`. Expect `process.exit(1)`.

4. **Quick mode (args.quick = true)**: Set `args.quick = true`. Assert `createConfigFromArgs` was called (not `runWizard`).

5. **Explicit args mode (name provided)**: Set `args.name = 'MyBot'`. Assert `createConfigFromArgs` called with `{ name: 'MyBot', ... }`.

6. **Interactive mode -- wizard completes**: No args set. Mock `runWizard` to return `validLucaConfig`. Assert `generateFiles` called.

7. **Interactive mode -- wizard cancelled (returns null)**: Mock `runWizard` to return `null`. Expect `process.exit(0)`.

8. **File generation failure**: Mock `generateFiles` to return `{ success: false }`. Expect `process.exit(1)`.

9. **File generation success**: Mock `generateFiles` to return `{ success: true, manifest: {} }`. Assert `p.outro` called, no `process.exit`.

10. **setupCleanupHandler called**: Verify `setupCleanupHandler` mock was called during `run()`.

**Verification**: `bun test __tests__/packages/luca-framework/src/commands/init.test.ts` -- all tests pass.

### Task 2: Update Command Tests
**Goal**: Test the key code paths in the update command. This is the most complex command, so focus on the decision logic, not the full file I/O.
**Files**: Create `__tests__/packages/luca-framework/src/commands/update.test.ts`
**Details**:

The update command has many dependencies. Mock them similarly to init. Key dependencies:
- `../utils/manifest` -- `readManifest()`, `writeManifest()`, `compareFiles()`, `hashContent()`
- `../utils/template` -- `getTemplatesDir()`, `processTemplate()`, `processFilename()`
- `../utils/branding` -- `createBrandingContext()`
- `../utils/logger` -- `logger`
- `@clack/prompts` -- `p.spinner`, `p.select`, `p.isCancel`, `p.outro`, `p.cancel`
- `fs/promises` -- `readFile`, `writeFile`, `cp`, `rm`, `mkdir`, `readdir`
- `fs` -- `existsSync`
- `fs-extra` -- `ensureDir`
- `process.exit`, `process.cwd`

Because this command has many internal functions and is very complex, focus tests on the main decision points rather than trying to test every internal helper:

**Test cases:**

1. **No manifest (Luca not installed)**: Mock `readManifest` to return `null`. Expect `process.exit(1)` with error about "not installed".

2. **Conflicting options (--accept-theirs + --accept-mine)**: Set both args. Expect `process.exit(1)` with error about "conflicting".

3. **Dry run mode**: Mock `readManifest` returning valid manifest, mock `compareFiles` returning comparisons. Set `args.dryRun = true`. Assert no files are written, summary is shown.

4. **Nothing to update**: Mock `compareFiles` returning all `status: 'unchanged'` comparisons. Assert message about "up to date".

5. **Files with updates (no conflicts)**: Mock `compareFiles` returning mix of `unchanged` and `new`. Assert files are written.

6. **User cancels conflict resolution**: Mock `compareFiles` returning `user-modified` entries. Mock `p.select` to return cancel symbol. Expect `process.exit(0)`.

7. **--force flag**: Set `args.force = true`. Mock `compareFiles` with `user-modified`. Assert updates applied without prompt.

8. **--accept-theirs**: Set `args.acceptTheirs = true`. Mock `compareFiles` with `user-modified`. Assert new content overwrites.

9. **--accept-mine**: Set `args.acceptMine = true`. Mock `compareFiles` with `user-modified`. Assert file is skipped (user version kept).

**Note**: Some of the internal functions (`getAllFiles`, `createBackup`, `restoreBackup`) are module-scoped and not exported. They are tested implicitly through the command. Detailed filesystem-level testing of backup/restore is lower priority and can be deferred.

**Verification**: `bun test __tests__/packages/luca-framework/src/commands/update.test.ts` -- all tests pass.

### Task 3: Doctor Command Tests

**Files**: Create `__tests__/packages/luca-framework/src/commands/doctor.test.ts`
**Details**:

The doctor command is minimal -- it calls `executeDoctor()` and passes the exit code to `process.exit()`.

```typescript
import { describe, test, expect, mock, spyOn } from 'bun:test';
```

Mock dependencies:
```typescript
mock.module('../../../../../../packages/luca-framework/src/utils/doctor', () => ({
  executeDoctor: async () => mockExitCode,
}));
```

**Test cases:**

1. **All checks pass (exit code 0)**: Mock `executeDoctor` returning `0`. Assert `process.exit(0)` called.

2. **Some checks fail (exit code 1)**: Mock `executeDoctor` returning `1`. Assert `process.exit(1)` called.

3. **executeDoctor is called**: Verify the mock function was invoked.

**Verification**: `bun test __tests__/packages/luca-framework/src/commands/doctor.test.ts` -- all tests pass.
