# Plan 22-01: Marketplace Manifest (marketplace.json)

## Objective

Generate a `marketplace.json` file at `dist/plugin/.claude-plugin/marketplace.json` that follows the Claude Code marketplace specification. This manifest enables users to discover and install the Luca plugin via `/plugin marketplace add`. The file is generated at build time -- version sourced from package.json, metadata from project constants -- so it never drifts from source. This plan adds the generation logic to `build-all.ts` (appended to the existing plugin build section) and the corresponding `BuildPluginResult` type extension.

## Context

@scripts/build-all.ts -- Unified build script (414 lines). Plugin build section starts at line 361 where `buildPlugin()` is called. After consolidation in Plan 22-03 the plugin logic moves inline, but this plan adds marketplace generation to the EXISTING build-plugin.ts `buildPlugin()` function so it works both standalone and via build-all.ts.

@scripts/build-plugin.ts -- Plugin build script (553 lines). `buildPlugin()` function at line 228. Plugin manifest generation at lines 477-498 using `generatePluginManifest()`. The marketplace.json generation should be added immediately after plugin.json generation (after line 498), using the same `version`, `agentNames`, `skillNames` variables already available in scope.

@dist/plugin/.claude-plugin/plugin.json -- Current plugin manifest (139 lines). The marketplace.json will sit alongside this file in the same directory.

@src/compilers/plugin.types.ts -- Plugin manifest Zod schema and `generatePluginManifest()` function. The marketplace.json does NOT use this schema (it has a different structure per the Claude Code marketplace spec). Generate marketplace JSON directly.

@.planning/phases/22-distribution/22-RESEARCH.md -- Section 1 covers the marketplace spec in detail. Section 1.2 shows the Anthropic reference marketplace.json. Section 1.5 has the proposed Luca marketplace.json structure. Section 6.1 discusses the location decision.

@package.json -- Root package.json with project metadata (name, description, author, license, keywords).

## Tasks

### Task 1: Add marketplace.json generation to buildPlugin()

**Goal:** Generate `dist/plugin/.claude-plugin/marketplace.json` as part of the plugin build, immediately after the existing plugin.json manifest generation.

**Files:** `scripts/build-plugin.ts` (modify)

**Steps:**

1. Read `scripts/build-plugin.ts` and locate the plugin manifest generation section (lines 475-498, after `// --- Plugin Manifest ---`).
2. After the `plugin.json` write (line 497: `console.log("  Generated .claude-plugin/plugin.json");`), add marketplace.json generation:

   ```typescript
   // --- Marketplace Manifest ---

   const marketplaceManifest = {
     $schema: "https://anthropic.com/claude-code/marketplace.schema.json",
     name: "luca-marketplace",
     description:
       "Luca - Agentic development framework with cognitive memory and spec-driven workflow",
     owner: {
       name: "Alec Sibilia",
     },
     plugins: [
       {
         name: "luca",
         description:
           "Agentic development framework with cognitive memory and spec-driven workflow",
         source: ".",
         category: "development",
         version,
         author: {
           name: "Alec Sibilia",
         },
         homepage: "https://github.com/alecsibilia/luca-framework",
         repository: "https://github.com/alecsibilia/luca-framework",
         license: "MIT",
         keywords: [
           "agent",
           "ai",
           "framework",
           "luca",
           "workflow",
           "cognitive",
         ],
       },
     ],
   };

   await Bun.write(
     path.join(manifestDir, "marketplace.json"),
     JSON.stringify(marketplaceManifest, null, 2) + "\n",
   );
   console.log("  Generated .claude-plugin/marketplace.json");
   ```

3. Key design choices:
   - `source: "."` -- because marketplace.json lives inside `dist/plugin/.claude-plugin/`, the plugin root is the parent directory (self-contained distribution)
   - `version` reuses the already-resolved `version` variable from `readVersion()` (line 477)
   - Follows the Anthropic reference structure (flat root-level fields, NOT nested under `metadata`)
   - `category: "development"` matches the Anthropic pattern for dev tools
   - `$schema` included for spec compliance (URL does not actually resolve, consistent with Anthropic's own usage)

4. Update the `totalFiles` calculation (line 502) to account for the new file:

   ```typescript
   const totalFiles = agentCount + skillCount + commandCount + hookCount + 3; // +3 for hooks.json, plugin.json, marketplace.json
   ```

5. Update the summary output (lines 504-510) to mention marketplace.json:
   ```typescript
   console.log("\n=== Plugin Build Summary ===");
   console.log(`Agents:      ${agentCount}`);
   console.log(`Skills:      ${skillCount}`);
   console.log(`Commands:    ${commandCount}`);
   console.log(`Hooks:       ${hookCount}`);
   console.log(`Manifests:   plugin.json + marketplace.json`);
   console.log(`Total:       ${totalFiles} files`);
   console.log(`Output:      dist/plugin/`);
   ```

**Verification:**

- [ ] `dist/plugin/.claude-plugin/marketplace.json` is generated alongside `plugin.json`
- [ ] marketplace.json contains required fields: `name`, `owner`, `plugins[]`
- [ ] `plugins[0].version` matches the version in `plugin.json`
- [ ] `plugins[0].source` is `"."`
- [ ] `plugins[0].category` is `"development"`
- [ ] JSON is valid and formatted with 2-space indentation + trailing newline
- [ ] TypeScript compiles without errors: `bunx --bun tsc --noEmit`
