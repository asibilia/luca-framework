# Plan 32-01: lu-discuss-researcher Agent Definition + Registration

## Objective

Create the `lu-discuss-researcher` agent -- a web-enabled research agent that autonomously answers gray area questions identified during phase discussion. When phase-discuss runs in `--auto` mode (Plan 32-02), it spawns one instance of this agent per gray area question. The agent researches the question using WebSearch and WebFetch, scopes its queries to the project's tech stack (read from BRAIN.md), and returns a cited recommendation with confidence level. This plan creates the agent definition, registers it, adds it to AGENT_CATEGORIES in build-shared.ts, and writes tests.

## Context

@src/agents/general/lu-phase-researcher.agent.ts -- Existing web research agent for phase research. The lu-discuss-researcher follows the same tool set and source hierarchy patterns (Context7 > Official Docs > WebSearch) but with a narrower scope: answering a single gray area question rather than producing a full RESEARCH.md. Use this as the structural template.

@src/agents/general/lu-project-researcher.agent.ts -- Broader ecosystem researcher. Shares the same confidence-level tracking pattern (HIGH/MEDIUM/LOW) and verification protocol. The lu-discuss-researcher inherits these patterns but produces a much smaller output (a single recommendation with citations, not multiple files).

@src/agents/base/base-agent.ts -- BaseAgentImpl class that all agents extend. Constructor validates config with Zod schema.

@src/agents/types/agent.types.ts -- AgentConfig, AgentFrontmatter, AgentSection, BaseAgent interfaces.

@src/agents/index.ts -- Agent registry. Maps agent names to factory functions. New agent must be imported and registered here.

@scripts/build-shared.ts -- Contains AGENT_CATEGORIES mapping used for README generation. The new agent must be added under the "Research" category.

@.planning/BRAIN.md -- Project identity file loaded at session start. The lu-discuss-researcher reads this at spawn to scope its web searches to the project's tech stack.

@.cursor/luca/workflows/discuss-phase.md -- The discuss-phase workflow that identifies gray areas. In auto mode (Plan 32-02), this workflow will spawn lu-discuss-researcher per question instead of asking the user.

## Tasks

### Task 1: Create the lu-discuss-researcher agent definition file

**Goal:** Create `src/agents/general/lu-discuss-researcher.agent.ts` following the established agent definition pattern. The agent is an LLM prompt agent -- its sections contain natural language instructions that tell the LLM how to research a single gray area question and return a cited recommendation.

**Files:** `src/agents/general/lu-discuss-researcher.agent.ts` (create)

**Steps:**

1. Create the file with standard imports:

   ```typescript
   import { BaseAgentImpl } from "../base/base-agent";
   import type { AgentConfig } from "../types/agent.types";
   ```

2. Define the agent config with frontmatter:
   - `name`: `"lu-discuss-researcher"`
   - `description`: `"Researches a single gray area question for phase-discuss auto mode. Uses WebSearch and WebFetch scoped to project tech stack to produce a cited recommendation with confidence level."`
   - `tools`: `["Read", "Grep", "Glob", "WebSearch", "WebFetch"]`
   - `color`: `"cyan"`
   - `cognition`: `{ default_tier: "T1", promotable_to: "T1", memory_tags: ["stack", "architecture"] }`
   - `context`: `{ default_tier: "T1", promotable_to: "T1", isolation: "none" }`

3. Define the sections array with the following ordered sections:

   **Section 1 - "role" (order: 1):**
   The role section must instruct the LLM to:
   - Act as a focused web researcher answering a single gray area question for phase-discuss
   - Receive: the gray area question, the phase context (name, description, goal), and the project tech stack from BRAIN.md
   - Scope all web searches to the project's tech stack (e.g., if stack is TypeScript + Bun, search for "Bun best practice for X" not generic "best practice for X")
   - Return a single recommendation with cited rationale, not an exhaustive survey
   - Include confidence level (HIGH/MEDIUM/LOW) following the same source hierarchy as lu-phase-researcher:
     - HIGH: Context7 or official documentation
     - MEDIUM: WebSearch verified with official source
     - LOW: WebSearch only, single source, unverified
   - Be opinionated: "Use X because Y" not "Consider X or Y"
   - Include cognition integration block (T1 memory-reader) for recalling relevant stack decisions and architecture patterns

   **Section 2 - "research_protocol" (order: 2):**
   The research protocol section must define:
   - Step 1: Parse the input. Extract the gray area question, phase context, and tech stack constraints.
   - Step 2: Read BRAIN.md to understand the project's stack, conventions, and architecture patterns. Use this to scope all searches.
   - Step 3: Formulate search queries. Always include the project's primary technology in queries (e.g., "TypeScript", "Bun", "React"). Always include the current year for freshness.
   - Step 4: Execute research using WebSearch first for discovery, then WebFetch for verification against official docs.
   - Step 5: Cross-reference findings. Apply the verification protocol: WebSearch findings must be verified with official docs or multiple sources to upgrade confidence.
   - Step 6: Form recommendation. Pick the best option based on evidence. Be prescriptive.

   **Section 3 - "output_format" (order: 3):**
   The output format section must define the return structure:

   ```
   ## RESEARCH ANSWER

   **Question:** {the gray area question}
   **Recommendation:** {clear, prescriptive answer}
   **Confidence:** {HIGH/MEDIUM/LOW}

   ### Rationale

   {2-3 sentences explaining WHY this recommendation, citing specific sources}

   ### Sources

   - [{source title}]({url}) - {what it confirmed}
   - [{source title}]({url}) - {what it confirmed}

   ### Alternatives Considered

   - {alternative}: {why not recommended}

   ### Tech Stack Scoping

   **Searched within:** {technologies used to scope queries}
   ```

   **Section 4 - "guardrails" (order: 4):**
   The guardrails section must instruct the LLM on:
   - Stay focused on the single question. Do not expand scope or research tangential topics.
   - Do not recommend scope additions. The phase boundary is fixed.
   - If the question cannot be answered with web research (e.g., it is a user preference question like "what color scheme?"), return a structured response indicating `researchable: false` with reason "This is a user preference question that requires human input."
   - Time-box: Aim for 2-4 web searches per question. Do not exhaustively survey the ecosystem.
   - Honest reporting: "I couldn't find definitive guidance" is a valid answer. Do not fabricate sources or overstate confidence.

4. Export the class:

   ```typescript
   export class LuDiscussResearcherAgent extends BaseAgentImpl {
     constructor() {
       super(luDiscussResearcherConfig);
     }
   }
   ```
