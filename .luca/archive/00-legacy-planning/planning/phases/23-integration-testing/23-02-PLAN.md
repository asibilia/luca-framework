# Plan 23-02: Hook Path Resolution, Event Type Validation, and Compilation Format Tests

## Objective

Create automated tests that validate hook scripts use the correct `${CLAUDE_PLUGIN_ROOT}` path variable, that hooks.json contains only valid Claude Code event types, and that compiled SKILL.md files have the required YAML frontmatter format. These tests cover TEST-03 (hook path resolution) and TEST-04 (skill/agent compilation parity -- specifically the plugin-specific format requirements that drift tests do not check). Note: `commands/` was removed from the plugin (it is a legacy approach; skills/ handles slash commands directly).

The tests live in a new file `scripts/plugin-spec-hooks-format.test.ts` and run as part of the standard `bun test` suite.

## Context

@dist/plugin/hooks/hooks.json -- The plugin hooks configuration. Contains event type keys (PostToolUse, PreToolUse, Stop, SessionEnd, SessionStart) mapped to arrays of hook entries. Each hook entry has a `command` field that must use `${CLAUDE_PLUGIN_ROOT}/scripts/<name>.sh` path format. The event types must be valid Claude Code hook events.

@dist/plugin/scripts/ -- Contains the actual hook shell scripts (post-edit-format.sh, post-edit-typecheck.sh, pre-commit-gate.sh, context-monitor.sh, session-persist.sh, session-start.sh). These are the scripts referenced by hooks.json.

@dist/plugin/skills/ -- Contains skill subdirectories, each with a SKILL.md file. Per the Claude Code plugin spec, each SKILL.md must have YAML frontmatter with a `description` field.

@dist/plugin/agents/ -- Contains agent .md files. Agents can optionally have YAML frontmatter (for cognition/context config) but must always contain markdown content.

@src/hooks/index.ts -- The hook registry and definitions. Exports `HookDefinition` interface and `hookRegistry` object. The registry defines which Claude Code events are valid for this project.

@scripts/build-shared.ts -- Exports `PLUGIN_EXCLUDED_HOOKS` (hooks not included in plugin builds) and `generatePluginHooksConfig()` which builds the hooks.json structure.

@scripts/check-drift.test.ts -- Existing drift tests. The "Plugin Output Freshness" section checks byte-for-byte parity of hook scripts and hooks.json against generated output. **DO NOT duplicate those checks.** This plan validates spec-conformance aspects that drift tests do not cover: event type validity, path variable format, and frontmatter presence.

@23-CONTEXT.md -- Phase 23 context. Decision 3 specifies: hooks.json event types must be valid Claude Code events (PreToolUse, PostToolUse, Notification, Stop, SubagentTool, SessionStart, SessionEnd). SKILL.md files must have description frontmatter.

### Task 1: Create the test file with hooks.json event type validation (TEST-03, part 1)

**Goal:** Create `scripts/plugin-spec-hooks-format.test.ts` with a `describe("Hook Event Type Validation (TEST-03)")` block that validates all event types in hooks.json are recognized by Claude Code.

**File:** `scripts/plugin-spec-hooks-format.test.ts` (create)

**Steps:**

1. Create the file with standard imports:

   ```typescript
   import { describe, test, expect } from "bun:test";
   import { readdirSync, readFileSync, existsSync } from "node:fs";
   import path from "path";
   ```

2. Define constants:

   ```typescript
   const PLUGIN_ROOT = path.resolve(import.meta.dir, "..", "dist", "plugin");

   /**
    * Valid Claude Code hook event types.
    *
    * This is the authoritative set of events that Claude Code recognizes
    * in a plugin's hooks.json file. Any event type NOT in this set will
    * be silently ignored or could cause loading errors.
    *
    * Source: Claude Code plugin specification.
    */
   const VALID_CLAUDE_CODE_EVENTS = new Set([
     "PreToolUse",
     "PostToolUse",
     "Notification",
     "Stop",
     "SubagentTool",
     "SessionStart",
     "SessionEnd",
   ]);
   ```

3. Add the describe block `"Hook Event Type Validation (TEST-03)"`:

   a. **Test: hooks.json contains only valid Claude Code event types.** Parse `dist/plugin/hooks/hooks.json`, iterate over all top-level keys, and assert each key is in `VALID_CLAUDE_CODE_EVENTS`.

   ```typescript
   const hooksJson = JSON.parse(
     readFileSync(path.join(PLUGIN_ROOT, "hooks", "hooks.json"), "utf8"),
   );
   const eventTypes = Object.keys(hooksJson);
   const invalidEvents = eventTypes.filter(
     (event) => !VALID_CLAUDE_CODE_EVENTS.has(event),
   );
   expect(invalidEvents).toEqual([]);
   ```

   b. **Test: every hook entry has required fields.** For each event type's entries array, for each matcher group, for each hook object, assert it has `type` (string), `command` (string), and `timeout` (number). These are the minimum required fields per the Claude Code hook spec.

   c. **Test: every hook entry type is "command".** Claude Code plugin hooks only support the `command` type (not `prompt` or `agent`). Assert every hook entry's `type` field equals `"command"`.

**Verification:**

- [ ] `scripts/plugin-spec-hooks-format.test.ts` exists
- [ ] 3 tests pass in the "Hook Event Type Validation" block
- [ ] Invalid event types are caught and reported
- [ ] `bun test scripts/plugin-spec-hooks-format.test.ts` passes

### Task 2: Add ${CLAUDE_PLUGIN_ROOT} path resolution tests (TEST-03, part 2)

**Goal:** Add tests that validate all hook command paths in hooks.json use the `${CLAUDE_PLUGIN_ROOT}` variable and that every referenced script file exists in `dist/plugin/scripts/`.

**File:** `scripts/plugin-spec-hooks-format.test.ts` (modify -- add to existing TEST-03 describe block)

**Steps:**

1. Add these tests to the existing describe block:

   a. **Test: all hook commands use ${CLAUDE_PLUGIN_ROOT} path prefix.** Parse hooks.json, extract all `command` strings from all hook entries across all event types, and assert each one starts with `${CLAUDE_PLUGIN_ROOT}/scripts/`.

   ```typescript
   const commands: string[] = [];
   for (const entries of Object.values(hooksJson)) {
     for (const group of entries as any[]) {
       for (const hook of group.hooks) {
         commands.push(hook.command);
       }
     }
   }

   const missingPrefix = commands.filter(
     (cmd) => !cmd.startsWith("${CLAUDE_PLUGIN_ROOT}/scripts/"),
   );
   expect(missingPrefix).toEqual([]);
   ```

   b. **Test: every referenced script exists in dist/plugin/scripts/.** For each `command` string extracted above, derive the script filename (everything after the last `/`) and assert the file exists in `dist/plugin/scripts/`.

   c. **Test: every script in dist/plugin/scripts/ is referenced by hooks.json.** Read the `scripts/` directory, extract all `.sh` filenames, and assert each one appears in at least one hook command path. This catches orphan scripts that the plugin system would never invoke.

   d. **Test: all hook scripts are executable shell files.** For each `.sh` file in `dist/plugin/scripts/`, read the first line and assert it starts with `#!/usr/bin/env bash` or `#!/bin/bash` (valid shebang).

**Verification:**

- [ ] 4 new tests pass (path prefix, script existence, no orphan scripts, shebang lines)
- [ ] `${CLAUDE_PLUGIN_ROOT}` is validated as the only path mechanism
- [ ] Script existence is cross-referenced bidirectionally (hooks.json -> scripts, scripts -> hooks.json)

### Task 3: Add SKILL.md frontmatter validation (TEST-04, part 1)

**Goal:** Add a `describe("SKILL.md Frontmatter Validation (TEST-04)")` block that validates every SKILL.md in the plugin has the required YAML frontmatter with a `description` field. This is a plugin-spec requirement that drift tests do not check (drift tests check content parity, not frontmatter presence).

**File:** `scripts/plugin-spec-hooks-format.test.ts` (modify -- add new describe block)

**Steps:**

1. Create a simple YAML frontmatter parser helper (inline in the test file, not a separate module):

   ```typescript
   /**
    * Extract YAML frontmatter from a markdown file.
    * Returns null if no frontmatter found.
    */
   function extractFrontmatter(content: string): Record<string, string> | null {
     const match = content.match(/^---\n([\s\S]*?)\n---/);
     if (!match) return null;

     const fields: Record<string, string> = {};
     for (const line of match[1].split("\n")) {
       const colonIndex = line.indexOf(":");
       if (colonIndex > 0) {
         const key = line.slice(0, colonIndex).trim();
         const value = line.slice(colonIndex + 1).trim();
         fields[key] = value;
       }
     }
     return fields;
   }
   ```

2. Add the describe block `"SKILL.md Frontmatter Validation (TEST-04)"`:

   a. **Test: every SKILL.md has YAML frontmatter.** Read all subdirectories in `dist/plugin/skills/`, read each `SKILL.md`, and assert the content starts with `---\n`.

   b. **Test: every SKILL.md frontmatter has a description field.** For each SKILL.md, extract frontmatter using the helper, and assert `fields.description` is a non-empty string.

   c. **Test: no SKILL.md has empty or whitespace-only description.** For each SKILL.md, assert the `description` value (after trimming) has length > 0.

**Verification:**

- [ ] 3 tests pass for SKILL.md frontmatter
- [ ] Every SKILL.md in the plugin is validated (not just a sample)
- [ ] Empty/missing descriptions are caught
