### 2. Fix barrel import violation in resolve-model (M14)

**Type:** auto
**TDD:** false
**Depends on:** none

**Problem:** Line 36 of `src/agents/__helpers/resolve-model.ts` imports `resolveModelForAgent` from `~/complexity/__helpers/model-routing` instead of the barrel `~/complexity`. This violates the module boundary rule (Rule 4: never import from another domain's `__helpers/`).

**Fix:** Change the import to use the barrel export.

**Files to edit:**

- `src/agents/__helpers/resolve-model.ts` (line 36)

**Change:**

```typescript
// Before
import { resolveModelForAgent } from "~/complexity/__helpers/model-routing";

// After
import { resolveModelForAgent } from "~/complexity";
```

**Verification:**

- `grep "__helpers/model-routing" src/agents/__helpers/resolve-model.ts` returns no results
- `grep "from \"~/complexity\"" src/agents/__helpers/resolve-model.ts` returns the fixed import
- `bunx --bun tsc --noEmit` passes

### 4. Fix stale bridge references in cognitive-preflight.md (Gap 1)

**Type:** auto
**TDD:** false
**Depends on:** none

**Problem:** `.cursor/luca/workflows/cognitive-preflight.md` (manually-maintained, NOT in the build pipeline) still references `src/memory/__helpers/bridge.ts read-memory` on lines 71 and 99. This file no longer exists after MuninnDB migration. The source template at `packages/luca-framework/templates/framework/workflows/cognitive-preflight.md` was already fixed but uses different MuninnDB-aware wording.

**Fix:** Replace the two `bun run src/memory/__helpers/bridge.ts read-memory` shell blocks in the `.cursor/` copy with MuninnDB MCP recall comments matching the pattern already used in the source template.

**Files to edit:**

- `.cursor/luca/workflows/cognitive-preflight.md` (lines ~71 and ~99)

**Change (line ~71):**

```bash
# Before:
RECALL_JSON=$(bun run src/memory/__helpers/bridge.ts read-memory \
    --milestone="${CURRENT_MILESTONE}" \
    --tags="${TASK_TAGS}" \
    --limit=5 2>/dev/null)

# After:
# Milestone-scoped recall via MuninnDB MCP
# Use mcp__muninn__muninn_recall with milestone + task tags as context
# Example MCP call (executed by the agent, not shell):
#   mcp__muninn__muninn_recall(vault="default", context="milestone:${CURRENT_MILESTONE} tags:${TASK_TAGS}")
# Fallback: grep MEMORY.md for milestone-tagged entries
RECALL_JSON=$(grep -A5 "milestone.*${CURRENT_MILESTONE}" .planning/MEMORY.md 2>/dev/null || echo "")
```

**Change (line ~99):** Same pattern, replacing the tag-based bridge call with MuninnDB MCP comments.

**Verification:**

- `grep "src/memory/__helpers/bridge" .cursor/luca/workflows/cognitive-preflight.md` returns no results
- `grep "mcp__muninn__muninn_recall" .cursor/luca/workflows/cognitive-preflight.md` returns the new MCP references
