# Plan 15-04: Agent Cognition Wiring

## Objective

Wire cognition metadata into all 27 agent `.agent.ts` registry files and add `<cognition_integration>` sections to the 6 agent `.agent.ts` source files that need them. Also retroactively tag all existing MEMORY.md entries with domain tags for selective recall. This is the batch-update plan that applies the infrastructure from Plans 15-02 and 15-03 to the full agent roster and memory store.

- **All 27 `.agent.ts` files need cognition metadata** in their `frontmatter` object
- **6 agent `.agent.ts` source files need `<cognition_integration>` sections** added to their `sections[0].content` template literal (not breaking existing content)

```xml
## Cognition Integration (Tier: T2 — Session-Aware)

**Memory Recall:** Before beginning task execution, check if a cognitive report was provided in your prompt context. If present, use recalled patterns, decisions, and pitfalls to inform implementation:

- **Patterns**: Follow validated coding approaches from past sessions
- **Pitfalls**: Avoid known issues (e.g., `|| true` swallowing exit codes, Bun.spawn timeout quirks)
- **Decisions**: Respect past architectural choices and conventions

**Session Tracking:** During execution, append findings to WORKING.md:

- Code observations and unexpected behaviors
- Dependencies discovered during implementation
- Candidate patterns (approaches that worked well)
- Candidate pitfalls (issues encountered)

**Format for WORKING.md entries:**
```

- HH:MM [FINDING] Description of what was observed
- HH:MM [CANDIDATE-PATTERN] Description of approach that worked
- HH:MM [CANDIDATE-PITFALL] Description of issue encountered

```
</cognition_integration>
```

### Task 3: Retroactively Tag MEMORY.md Entries

**Goal:** Add `Tags:` field to every existing entry in MEMORY.md using domain tags from TAG-VOCABULARY.md.
**File:** `.planning/MEMORY.md`

Read every entry in MEMORY.md and assign 1-3 domain tags based on the entry's content. Use the TAG-VOCABULARY.md as the reference for valid tags.

**Tagging heuristics:**

| Entry Content Keywords                 | Assign Tags    |
| -------------------------------------- | -------------- |
| "pattern", "approach", "validated"     | `patterns`     |
| "pitfall", "gotcha", "breaks", "wrong" | `pitfalls`     |
| "decided", "chose", "trade-off"        | `decisions`    |
| "code", "implementation", "refactor"   | `coding`       |
| "architecture", "design", "layer"      | `architecture` |
| "test", "bun test", "coverage"         | `testing`      |
| "verify", "signal", "harness"          | `verification` |
| "plan", "wave", "dependency"           | `planning`     |
| "debug", "investigate", "root cause"   | `debugging`    |
| "bun", "typescript", "library"         | `stack`        |
| "security", "credential", "injection"  | `security`     |
| "performance", "startup", "bundle"     | `performance`  |
| "convention", "naming", "standard"     | `conventions`  |
| "complexity", "gating", "tier"         | `complexity`   |

**Format for tagged entries:**

Before:

```markdown
#### Entry Title

- **Pattern**: Description
- **When to use**: Context
- **Confidence**: High
- **Added**: 2026-02-10
```

After:

```markdown
#### Entry Title

- **Pattern**: Description
- **When to use**: Context
- **Tags**: [coding, patterns]
- **Confidence**: High
- **Added**: 2026-02-10
```

Insert the `Tags:` line BEFORE the `Confidence:` line in each entry.

**Requirements:**

- Tag ALL entries (patterns, decisions, pitfalls, conventions, anti-patterns, preferences)
- Every entry must have at least 1 tag
- No entry should have more than 3 tags
- Use only tags from the TAG-VOCABULARY.md
