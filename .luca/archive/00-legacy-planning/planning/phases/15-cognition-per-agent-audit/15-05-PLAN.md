# Plan 15-05: Audit Findings Capture

## Objective

Extract actionable patterns, decisions, and pitfalls from the Phase 15 cognition audit and capture them in MEMORY.md. This is the learning loop closure for the audit phase, following the established pattern from Phase 14's Plan 14-03.

- **MEMORY.md:** `.planning/MEMORY.md` (recently updated with Tags field by Plan 15-04)

- **WORKING.md:** `.planning/WORKING.md` (session findings to extract)

## Tasks

### Task 1: Extract Findings from Audit Report (15-01)

**Goal:** Identify patterns, decisions, and pitfalls from the cognition audit report.
**Source:** `COGNITION-AUDIT.md`

Extract:

- **Patterns**: Per-agent cognition profiling methodology (4-tier system, audit matrix approach)
- **Patterns**: Metadata-driven configuration (cognition config in agent frontmatter, not hardcoded in orchestrator)
- **Decisions**: 4-tier cognition system (T0-T3) as the standard for agent cognition classification
- **Decisions**: Dynamic tier with fixed default (complexity-driven promotion with ceiling cap)
- **Pitfalls**: Context bloat from aggressive memory recall (too many T2/T3 agents = context window pressure)

### Task 2: Extract Findings from Code Changes (15-02, 15-03, 15-04)

**Goal:** Identify patterns, decisions, and pitfalls from the implementation work.
**Sources:** Schema changes, compiler updates, agent wiring, MEMORY.md tagging

Extract:

- **Patterns**: Tag-based selective memory recall (coarse domain tags + keyword scoring = efficient filtering)
- **Patterns**: Retroactive metadata migration (adding Tags to ~108 entries without breaking backward compatibility)
- **Decisions**: YAML frontmatter for compiled agents (machine-readable at runtime without TypeScript imports)
- **Decisions**: Tag vocabulary size (~14 tags) balances recall precision vs. vocabulary maintenance overhead
- **Pitfalls**: Stale tags on MEMORY.md entries (static labels on dynamic knowledge, mitigated by legacy backward compat)
- **Pitfalls**: Cognition config in both .agent.ts AND compiled .md (two sources of truth, compiler is the bridge)

### Task 3: Write MEMORY.md Entries

**Goal:** Add all extracted findings to MEMORY.md with proper tagging using the new Tags field format.
**File:** `.planning/MEMORY.md`

Requirements:

- At least 3 new patterns added
- At least 2 new decisions added
- At least 2 new pitfalls added
- All entries tagged with `[Phase 15]` in their entry title
- All entries include `Tags:` field using TAG-VOCABULARY.md vocabulary
- Memory statistics updated (pattern/decision/pitfall counts in document header or summary)
- WORKING.md cleared after extraction (session findings moved to MEMORY.md)

**Entry format (must match updated lu-learner template from Plan 15-03):**

```markdown
#### [Phase 15] Entry Title

- **Pattern/Decision/Pitfall**: Description
- **When to use**: Context for when this applies
- **Agent**: Which agent this is most relevant to
- **Relevant to**: [list of agents that benefit from this knowledge]
- **Tags**: [domain tags from vocabulary]
- **Confidence**: High/Medium/Low
- **Added**: 2026-02-11
```

**Example entries to write:**

```markdown

- **Pattern**: Classify agents into T0 (Stateless), T1 (Memory-Reader), T2 (Session-Aware), T3 (Fully-Cognitive) based on their role and output quality impact. Use audit matrix (5 feature columns) to assess current state, then gap analysis to identify promotions.
- **When to use**: When evaluating which agents should receive memory context and at what depth
- **Agent**: lu-cognition
- **Relevant to**: [lu-cognition, lu-router, all agents]
- **Tags**: [architecture, complexity]
- **Confidence**: High
- **Added**: 2026-02-11
```
