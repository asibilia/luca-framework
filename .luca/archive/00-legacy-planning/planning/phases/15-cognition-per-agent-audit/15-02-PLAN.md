# Plan 15-02: Agent Schema & Tier Resolution Infrastructure

## Objective

Extend the TypeScript infrastructure to support per-agent cognition configuration. Add cognition schemas, types, complexity matrix extensions, a tier resolution function, and compiler updates for YAML frontmatter emission. This is the code foundation that Plans 15-03 and 15-04 build upon.

## Context

- **Agent schemas:** `src/agents/types/agent.schemas.ts` (30 lines -- agentFrontmatterSchema, agentSectionSchema, agentConfigSchema)
- **Agent types:** `src/agents/types/agent.types.ts` (34 lines -- AgentFrontmatter, AgentSection, AgentConfig, BaseAgent interfaces)
- **Complexity types:** `src/complexity/types.ts` (93 lines -- ComplexityGate interface, ComplexityLevel, COMPLEXITY_ORDER)
- **Complexity defaults:** `src/complexity/defaults.ts` (119 lines -- DEFAULT_COMPLEXITY_MATRIX with 5 levels)
- **Claude compiler:** `src/compilers/claude.compiler.ts` (25 lines -- ClaudeCompiler class with compileAgent)
- **Base compiler:** `src/compilers/base.compiler.ts` (20 lines -- BaseCompiler abstract class)
- **Base agent:** `src/agents/base/base-agent.ts` (toClaudeFormat/toCursorFormat implementations)
- **Example agent .ts:** `src/agents/general/lu-executor.agent.ts` (frontmatter structure reference)

## Design Decisions (from 15-CONTEXT.md)

- **Decision 5:** Cognition config lives in AgentFrontmatter with `defaultTier`, `promotableTo`, `memoryTags`
- **Decision 6:** Complexity matrix extends with `cognitionPromotions` per level. **Note:** 15-CONTEXT.md Decision 6 illustrates promotions as agent-name-keyed (`"code-architect": "T1"`). This plan implements tier-to-tier mapping instead (`T1: 'T2'`), which is more maintainable — per-agent configuration lives in agent frontmatter, not duplicated in the complexity matrix. The generic tier mapping applies uniformly; the agent's `promotable_to` ceiling handles per-agent limits.
- **Decision 7:** Compiled .md files get YAML frontmatter with cognition fields
- **API convention:** Schema fields use snake_case (`default_tier`, `promotable_to`, `memory_tags`)
- **Optional with defaults:** `cognition` field is optional; when absent, agent defaults to T0

### Task 4: Create Tier Resolution Function

**Goal:** Create a pure function that resolves an agent's effective cognition tier given its default, ceiling, and current complexity level.
**File:** `src/agents/cognition/resolve-tier.ts` (NEW file)

The function implements this logic:

1. Look up `cognitionPromotions` from the complexity matrix for the given complexity level
2. If no promotions defined, return the default tier unchanged
3. If promotions defined, look up the promoted tier for the agent's default tier
4. Cap the promoted tier at `promotableTo` ceiling (never exceed the agent's maximum)
5. Return the effective tier

````typescript
import type { CognitionTier } from "../types/agent.types";
import type { ComplexityLevel } from "../../complexity/types";
import { DEFAULT_COMPLEXITY_MATRIX } from "../../complexity/defaults";

/** Numeric order for tier comparison */
const TIER_ORDER: Record<CognitionTier, number> = {
  T0: 0,
  T1: 1,
  T2: 2,
  T3: 3,
};

/**
 * Resolves the effective cognition tier for an agent.
 *
 * Takes the agent's default tier, its promotion ceiling, and the
 * current task complexity level. Returns the effective tier after
 * applying complexity-driven promotions, capped at the ceiling.
 *
 * @param defaultTier - Agent's default cognition tier from frontmatter
 * @param promotableTo - Maximum tier this agent can reach
 * @param complexityLevel - Current task complexity level
 * @returns The effective cognition tier for this invocation
 *
 * @example
 * ```typescript
 * // lu-executor: default T2, promotable to T3, at COMPLEX complexity
 * resolveEffectiveTier('T2', 'T3', 'COMPLEX') // Returns 'T3'
 *
 * // code-architect: default T0, promotable to T1, at CRITICAL complexity
 * resolveEffectiveTier('T0', 'T1', 'CRITICAL') // Returns 'T1'
 *
 * // code-simplifier: default T0, promotable to T0, at CRITICAL complexity
 * resolveEffectiveTier('T0', 'T0', 'CRITICAL') // Returns 'T0' (ceiling blocks promotion)
 * ```
 */
export function resolveEffectiveTier(
  defaultTier: CognitionTier,
  promotableTo: CognitionTier,
  complexityLevel: ComplexityLevel,
): CognitionTier {
  const gate = DEFAULT_COMPLEXITY_MATRIX[complexityLevel];
  const promotions = gate.cognitionPromotions;

  if (!promotions) return defaultTier;

  const promoted = promotions[defaultTier] ?? defaultTier;

  // Cap at promotable_to ceiling
  if (TIER_ORDER[promoted] > TIER_ORDER[promotableTo]) {
    return promotableTo;
  }

  return promoted;
}
````

Also export a `TIER_ORDER` constant for use by other modules that need tier comparison.

### Task 5: Extend Compiler for YAML Frontmatter Emission

**Goal:** Update the Claude compiler to include cognition metadata as YAML frontmatter in compiled agent .md files.
**Files:** `src/compilers/claude.compiler.ts`, `src/agents/base/base-agent.ts`

The compiled agent .md output should include YAML frontmatter at the top:

```yaml
---
name: lu-executor
cognition:
  default_tier: T2
  promotable_to: T3
  memory_tags:
    - coding
    - patterns
    - pitfalls
    - conventions
---
```

**Approach:** The `compileAgent` method in `ClaudeCompiler` currently calls `agent.toClaudeFormat()` which returns the .md content. Modify the flow so that:

1. The `toClaudeFormat()` method (or a wrapper in the compiler) reads the agent's frontmatter
2. If `cognition` is present in frontmatter, generate YAML frontmatter block using `js-yaml` dump
3. Prepend the YAML frontmatter to the compiled markdown output
4. If `cognition` is absent, emit no frontmatter (backward compatible)

This enables lu-cognition to parse compiled .md files and extract cognition config at runtime without importing TypeScript modules.
