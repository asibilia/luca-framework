# Phase 127 Plan 01: TTL Cleanup Implementation

## Task Objective

Implement automatic TTL (time-to-live) cleanup for high-volume SpacetimeDB tables
(`observer_events` and `token_usage`) to prevent unbounded data growth.

## Context

- `observer_events` table accumulates event logs rapidly
- `token_usage` table tracks usage metrics with continuous writes
- Both tables need periodic cleanup to maintain database performance
- SpacetimeDB supports scheduled reducers for automated cleanup

## Files to Update

1. `packages/luca-spacetime/spacetimedb/src/schema.ts` - Add timestamp indexes if needed
2. `packages/luca-spacetime/spacetimedb/src/index.ts` - Add cleanup reducers and scheduled job

## Execution Steps

1. **observer_events TTL cleanup:**
   - Add cleanup reducer that deletes events where `timestamp < (now - 24 hours)`
   - Make TTL threshold configurable (default: 24 hours)
   - Preserve most recent N events as safety net (e.g., last 1000 events)

2. **token_usage TTL cleanup:**
   - Add cleanup reducer that deletes records where `timestamp < (now - 7 days)`
   - Make TTL threshold configurable (default: 7 days)
   - Preserve most recent N records as safety net

3. **Schedule periodic cleanup:**
   - Use `#[schedule(interval)]` attribute on cleanup reducer
   - Run cleanup every hour
   - Add logging for deleted record counts

## Verification

- [ ] Cleanup reducer uses `ctx.db.observer_events.filter()` with timestamp comparison
- [ ] Cleanup reducer uses `ctx.db.token_usage.filter()` with timestamp comparison
- [ ] Tests verify records older than threshold are deleted
- [ ] Tests verify recent records (within threshold) are preserved
- [ ] Scheduled reducer configured with `#[schedule]` attribute
- [ ] Cleanup runs automatically at defined interval

## Success Criteria

- TTL cleanup logic exists for both high-volume tables
- Cleanup runs automatically every hour
- Old records deleted without affecting recent data
- Configurable TTL thresholds
