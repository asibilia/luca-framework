# Phase 01 Plan 02: Compaction-Resilient Orchestrators

## Objective

Make phase-execute survive context compaction without losing progress. Currently, wave completion state and code review findings live only in the LLM's context window — a compaction event silently loses both. This plan adds three additive instruction blocks to `phase-execute.skill.ts`: (A) an append-only JSONL wave journal written after each wave, (B) a REVIEW.md written after Step 8.1 code review processing, and (C) a context budget pre-wave check that converts a potential mid-session compaction crash into a clean handoff with resume instructions.

### 2. Add context budget pre-wave check

**Type:** auto
**TDD:** false
**Depends on:** task 1

In `src/skills/general/phase-execute.skill.ts`, inside the **Step 4 (Execute Waves)** loop, insert a pre-wave context budget check before the "Read plan contents" block — so it fires at the start of each wave iteration, before any new work begins.

The check must:

1. Instruct: if the transcript feels large (many agent results consumed) or context zone reads as "degrading" or higher, trigger the handoff sequence.
2. Handoff sequence:
   a. Write the current wave state to the JSONL journal (use the same format from Task 1)
   b. Write `.continue-here.md` to the phase directory with fields: phase number, last completed wave, completed plan list, remaining waves list, and resume command (`/phase-execute {phase_number}`)
   c. Print a formatted banner to the user:
   ```
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Luca ► CONTEXT BUDGET HIGH — GRACEFUL HANDOFF
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   Context budget is in the HIGH/CRITICAL zone before wave {N}.
   Progress saved to .wave-progress.jsonl and .continue-here.md.
   Start a fresh session and run /phase-execute {phase_number} to resume.
   ```
   d. Stop.
3. Include a clarifying note: "This is a lighter check than Step 4.5 (which handles the 'stop' zone with bridge suspend/resume). This check fires earlier to convert a potential compaction crash into a clean handoff."

The check must be inserted before the "Read plan contents" block, not after it — the goal is to avoid spending any context on a wave that cannot complete.

**Files to edit:**

- `src/skills/general/phase-execute.skill.ts`

**Verification:**

- The pre-wave context budget check appears before the "Read plan contents" block inside Step 4
- The check references `.continue-here.md` and `.wave-progress.jsonl`
- The banner text includes "GRACEFUL HANDOFF" and instructs the user to start a fresh session
- The clarifying note distinguishing this check from Step 4.5 is present
- Step 4.5 (existing suspend/resume) is unchanged

### 3. Write REVIEW.md after Step 8.1 code review processing

**Type:** auto
**TDD:** false
**Depends on:** none

The instruction must:

1. Show a `cat > {phase_dir}/REVIEW.md` heredoc command that writes a structured markdown file with:
   - Header: `# Code Review — Phase {phase_number}`
   - Fields: timestamp, file count reviewed, reviewer list (dx-advocate, code-simplifier, code-architect, ui, security-auditor)
   - Summary table: severity counts (CRITICAL, HIGH, MEDIUM, LOW)
   - Findings section: merged and deduplicated findings in YAML or markdown
2. Explain: "This file persists reviewer findings across context compaction. It is referenced by session-resume when recovering a mid-review session."
3. Position it as part of Step 8.1 completion — before the Step 9 `VERIFY_PASSED` state transition fires. This ordering is critical: a compaction event between Steps 8 and 9 must not lose review data.

The instruction is additive — the existing Step 8.1 routing (`**If CRITICAL/HIGH:** ...`, `**If clean (or LOW only):** ...`) must remain unchanged.
