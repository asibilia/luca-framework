## CRITICAL Findings (2)

### CRIT-01: Duplicate class name `GenericruledescripRule`

**Files:** `src/rules/general/file-naming.rule.ts:83`, `src/rules/general/lodash-preference.rule.ts:211`
**Source:** DX Advocate
**Pre-existing:** Yes (not introduced by v1.3.0)

Both files export `class GenericruledescripRule extends BaseRuleImpl`, requiring aliased imports in `src/rules/index.ts`. This is fragile -- if both are imported in the same module without aliasing, one silently shadows the other. The truncated class names are auto-generated artifacts that were never corrected.

**Recommendation:** Rename to `FileNamingRule` and `LodashPreferenceRule` respectively. This is a quick fix that addresses the naming debt across all 19 auto-generated rule classes.

### CRIT-02: Duplicate `lu-workflow.rule.ts` at two paths with divergent content

**Files:** `src/rules/lu-workflow.rule.ts` (LuWorkflowRule), `src/rules/general/lu-workflow.rule.ts` (LucaworkflowsystemRule)
**Source:** DX Advocate
**Pre-existing:** Yes (not introduced by v1.3.0)

Two competing rule files with different class names and divergent content. The top-level file is directly imported by build-all.ts for the "Luca-specific" compilation path, while the general/ version is registered in `ruleRegistry` under the `lu-workflow` key. They produce different compiled output.

**Recommendation:** Determine which is canonical and remove the other. Update imports/registry accordingly.

## HIGH Findings (12)

### Deduplication Theme (cross-agent consensus)

Multiple reviewers independently flagged the same duplication patterns:

**H-01: PluginCompiler.compileAgent() is verbatim copy of ClaudeCompiler.compileAgent()**

- 35-line method body is character-for-character identical
- `compileRule()` is also identical between the two compilers
- The only meaningful PluginCompiler difference is `compileSkill()` (adds description frontmatter)
- **Fix:** Extract shared frontmatter logic to a utility function, or have PluginCompiler extend ClaudeCompiler and override only `compileSkill()`

**H-02: Triple duplication of compilation pipeline**

- `build-all.ts`, `check-drift.ts`, and `check-drift.test.ts` independently enumerate every registry, instantiate every compiler, handle every Luca-specific entity, and construct every manifest
- Any registry or entity addition must be synchronized across 3 files
- **Fix:** Extract `generateAllOutputs(): Map<string, string>` into `build-shared.ts`

**H-03: Marketplace manifest duplicated in 3 files**

- `build-all.ts:590`, `check-drift.ts:256`, `check-drift.test.ts:607`
- Same 17-line object with hardcoded URLs, author name, keywords
- **Fix:** Extract `generateMarketplaceManifest(version)` into `build-shared.ts`

**H-04: Test utility duplication**

- `VALID_CLAUDE_CODE_EVENTS` constant duplicated in `plugin-spec-e2e.test.ts` and `plugin-spec-hooks-format.test.ts`
- `extractFrontmatter()` helper duplicated in same two files
- **Fix:** Extract to shared test helpers module

**H-05: build-utils.ts uses node:fs instead of Bun APIs**

- Per CLAUDE.md and bun-preference rules, should prefer Bun.file APIs
- `check-drift.test.ts` uses inline `require('fs')` calls
- **Fix:** Migrate to Bun.file for file operations

**H-06: BaseCompiler class hierarchy violates no-classes rule** (Architect)

- `BaseCompiler` is an abstract class, all 3 compilers use class inheritance
- Project rule states: "No exceptions -- use functional patterns for all new code"
- **Fix:** Refactor to factory-function pattern. Low urgency since this is foundational v1.0 architecture.
