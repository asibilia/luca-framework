# Memory Snapshot — v2.5.1 Code Health & Test Reliability

**Snapshot Date:** 2026-03-02

## Patterns Validated

- **lodash/get null-handling**: `get(obj, path)` only applies default for `undefined`, NOT `null`. Always use `get(obj, path) ?? fallback` for null-safe behavior. Validated in `initializeContext()` fix.
- **XState DoneActorEvent typing**: `AssignArgs` generic doesn't expose `output` from child actor completion. Use `(event as unknown as { output?: T }).output` cast pattern.
- **Barrel purity extraction**: When extracting logic from barrels, the index.ts becomes a single re-export line. Logic moves to `__helpers/` or a sibling orchestration file.
- **initializeContext spread pattern**: Spread all input fields first (`...inputFields`), then apply config-derived defaults for only fields not explicitly provided.

## Decisions Made

- **R2.4 (parsers barrel) — BY DESIGN**: Subdirectory barrels don't need the same purity constraints as domain root barrels. The `parserRegistry` construction is appropriate in `parsers/index.ts`.
- **R2.7 (CLI entry) — N/A**: CLI entry points are inherently imperative and don't benefit from barrel purity extraction.
- **R3 (test isolation) — PARKED**: Deep Bun module cache issue affecting ~29 tests in full suite. Root cause identified but fix requires Bun runtime changes or significant test restructuring. Tests pass individually.

## Pitfalls Discovered

- **lodash/get third-arg trap**: Using `get(obj, path, defaultValue)` seems safe but `defaultValue` only applies when the result is `undefined`, not `null`. This caused silent `null` propagation in `initializeContext()`.
- **XState action type narrowing**: XState's `assign()` callback receives a generic `AssignArgs` type that strips child actor output types. Must cast through `unknown` to access `output`.
- **phaseResultSchema blocked status**: The `status` field supports `"passed" | "failed" | "blocked"` but the phase actor done handler was flattening `blocked` to `failed`, losing the distinction.
