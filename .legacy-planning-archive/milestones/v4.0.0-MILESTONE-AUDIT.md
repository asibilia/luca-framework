### Integration Gaps

#### GAP 1 (CRITICAL): PREMORTEM_COMPLETE uses wrong bridge subcommand

**File:** `src/skills/general/phase-discuss.skill.ts` line 323
**Phases affected:** 02, 03

`phase-discuss.skill.ts` calls `emit-event --type=PREMORTEM_COMPLETE` (observability telemetry) instead of `transition --event=PREMORTEM_COMPLETE` (state machine advance). The state machine will never receive the event, causing the `discussing` state to stall after pre-mortem approval. The `recordPremortemResult` action never runs, so `pre_mortem_result` is never stored in workflow context.

**Fix:** Replace `emit-event --type=PREMORTEM_COMPLETE` with `transition --event=PREMORTEM_COMPLETE`.

#### GAP 2 (MEDIUM): outcome-completion metric key inconsistency

**Files:** `outcome.skill.ts` (line 155), `lu-process-data.agent.ts` (line 190), `lu-cognition.agent.ts` (line 455)
**Phases affected:** 04, 05

`outcome.skill` stores metrics under `metric:outcome-completion`. `lu-process-data` computes the aggregate under `metric:outcome-completion-rate`. The aggregate is stored in MuninnDB but never consumed by any skill or agent. `lu-cognition` reads the per-invocation key (correct), but the aggregate connection between Phase 4 and Phase 5 is broken.

**Fix:** Align key naming — either rename lu-process-data's aggregate key to match, or add a consumer for the aggregate in milestone-complete graduation criteria.

#### GAP 3 (MEDIUM): Build output not staged

Compiled output for lu-premortem, lu-process-data, and outcome skill exists as untracked files but hasn't been committed. `bun run check:drift` will fail until these are staged.

**Fix:** Run `bun run build:all` outside Claude Code and commit the generated output.
