## Summary

Fixed the statusline not appearing for npm-installed users. The root cause was that `statusline.sh` referenced TypeScript source files in `src/`, which is not published to npm. The fix bundles statusline.ts into a standalone `dist/statusline.bundle.js` that ships with the package.

### Key Decisions

1. **Targeted import over barrel** — The statusline was importing `resolveStateValue` from the state barrel (`index.ts`), which pulled in the entire XState machine (25k lines) and caused side effects on stdout. Changed to direct import from `__helpers/resolve-state-value.ts`, reducing bundle to 19k lines with zero XState code.

2. **Bundle-first with source fallback** — The wrapper prefers `dist/statusline.bundle.js` (exists on npm installs) and falls back to `src/hooks/scripts/statusline.ts` (exists in monorepo). `LUCA_PACKAGE_ROOT` env var still routes directly to source for active development.

3. **Bun.build() for bundling** — Used Bun's native bundler with `target: "bun"` to produce a single self-contained file. Only Node.js builtins (`fs`, `path`) remain as external imports.
