## Tasks

### 1. Create useSemanticSearch hook

**Type:** auto
**TDD:** false
**Depends on:** none

Create `packages/luca-observer/hooks/use-semantic-search.ts` following the established hook pattern with these key differences from other hooks:

- **On-demand, NOT auto-fetch.** No `useEffect` on mount. The hook exposes a `search(query, options)` function that the page calls on form submit.
- **Duplicate `fetchJson` and `createNotConfiguredError`** locally (matching the 6 existing copies exactly).
- **Use `fetchingRef` pattern** to prevent double-fetch in React strict mode.
- **Store `lastQuery`** in state so the `explainResult()` function can pass the original search context.

**Exported interfaces:**

```typescript
export interface SearchOptions {
  mode?: "semantic" | "recent" | "balanced" | "deep";
  profile?:
    | "default"
    | "causal"
    | "confirmatory"
    | "adversarial"
    | "structural";
  threshold?: number;
}

export interface SemanticSearchResult {
  id: string;
  concept: string;
  content: string;
  score: number;
  confidence: number;
  score_components?: Record<string, number>;
  tags?: string[];
  memory_type?: string;
  why?: string;
  explain?: MuninnExplainResult; // Populated on-demand
}

export interface SemanticSearchData {
  results: SemanticSearchResult[];
  loading: boolean;
  error: string | null;
  configured: boolean;
  lastQuery: string | null;
  lastUpdated: Date | null;
  totalFound: number;
  search: (query: string, options?: SearchOptions) => void;
  explainResult: (engramId: string) => Promise<void>;
  refresh: () => void;
}
```

**Search implementation:**

- POST to `/api/muninn/activate` with body `{ context: [query], vault: "default", limit: 20 }`
- Map `MuninnActivation[]` response to `SemanticSearchResult[]`
- Advanced options (mode, profile, threshold) are stored in hook state but only `context`, `vault`, `limit` are sent to the API (ActivateRequestSchema only supports those three). Future: extend API if MuninnDB supports them.

**Explain implementation:**

- `explainResult(engramId)` calls POST `/api/muninn/explain` with `{ vault: "default", engram_id: engramId, query: [lastQuery] }`
- On success, merge the `MuninnExplainResult` into the matching result's `explain` field via state update
- On failure, silently degrade (no error shown for explain failures)

**Refresh implementation:**

- `refresh()` re-runs the last search (using stored lastQuery + lastOptions). No-op if no prior search.

- No `useEffect` auto-fetch on mount

### 2. Create useContradictions hook

**Type:** auto
**TDD:** false
**Depends on:** none

Create `packages/luca-observer/hooks/use-contradictions.ts` following the use-decision-trail.ts pattern exactly:

- **Auto-fetch on mount** via `useEffect(() => { void fetchAll(); }, [fetchAll])`
- **Duplicate `fetchJson` and `createNotConfiguredError`** locally
- **Use `fetchingRef` pattern** to prevent double-fetch

**Exported interfaces:**

```typescript
export interface ContradictionPair {
  id_a: string;
  id_b: string;
  concept_a: string;
  concept_b: string;
  reason: string;
}

export interface ContradictionsData {
  contradictions: ContradictionPair[];
  loading: boolean;
  error: string | null;
  configured: boolean;
  lastUpdated: Date | null;
  refresh: () => void;
  forgetEngram: (engramId: string) => Promise<boolean>;
}
```

**Fetch implementation:**

- GET `/api/muninn/contradictions` (no body needed)
- Check for 503 NotConfiguredError gracefully (set configured=false, no error state)
- Map response `contradictions` array to `ContradictionPair[]`

**Forget implementation:**

- `forgetEngram(engramId)` calls POST `/api/muninn/forget` with `{ vault: "default", id: engramId }`
- On success, remove any contradiction pairs that reference the forgotten engram ID (filter out pairs where id_a or id_b matches), return true
- On failure, return false (caller handles UI feedback)

### 3. Add forget API route and MuninnClient.forget method

**Type:** auto
**TDD:** false
**Depends on:** none

Three small changes to add forget capability:

**3a. Add `forget` method to MuninnClient interface and implementation** in `packages/luca-observer/lib/muninn-config.ts`:

```typescript
// Add to MuninnClient interface:
forget(vault: string, id: string): Promise<{ forgotten: boolean }>;

// Add to createMuninnClient implementation:
async forget(vault, id) {
  const res = await muninnFetch("/api/forget", {
    method: "POST",
    body: JSON.stringify({ vault, id }),
  });
  if (!res.ok) throw new Error(`MuninnDB forget: ${res.status}`);
  return res.json();
},
```

**3b. Add ForgetRequestSchema and ForgetResponseSchema** to `packages/luca-observer/lib/muninn-schemas.ts`:

```typescript
export const ForgetRequestSchema = z.object({
  vault: z.string().min(1).max(100).default("default"),
  id: z.string().min(1, "id is required"),
});
export type ForgetRequest = z.infer<typeof ForgetRequestSchema>;

export const ForgetResponseSchema = z
  .object({
    forgotten: z.boolean(),
  })
  .passthrough();
```
