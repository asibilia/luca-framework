### 1. Create memory-metrics schemas

**Type:** auto
**TDD:** false
**Depends on:** none

Create `src/shared/__schemas/memory-metrics.schemas.ts` with three Zod schemas:

1. **MemoryFeedbackEntrySchema** — represents a single feedback event:
   - `engram_id: z.string().min(1)` — the engram that received feedback
   - `concept: z.string().optional()` — engram concept for readability
   - `useful: z.boolean()` — whether the engram was useful
   - `phase: z.number().int().positive()` — phase where feedback was given
   - `verification_passed: z.boolean()` — whether phase verification passed
   - `feedback_at: z.string()` — ISO 8601 timestamp

2. **MemoryPhaseMetricsSchema** — per-phase memory effectiveness metrics:
   - `phase: z.number()` — phase number
   - `milestone: z.string()` — milestone identifier
   - `total_recalled: z.number().int().nonnegative()` — engrams recalled for this phase
   - `total_applied: z.number().int().nonnegative()` — engrams marked as applied by executor
   - `total_ignored: z.number().int().nonnegative()` — engrams recalled but not applied
   - `recall_precision: z.number().min(0).max(1)` — applied / recalled (0 if no recalls)
   - `hit_rate: z.number().min(0).max(1)` — phases_with_useful_recall / total_phases
   - `memory_tokens_injected: z.number().int().nonnegative()` — tokens used for memory context
   - `stale_engram_pct: z.number().min(0).max(1)` — percentage of recalled engrams with no positive feedback in 5+ phases
   - `confidence_calibration: z.number().min(0).max(1)` — correlation between engram confidence and actual usefulness
   - `computed_at: z.string()` — ISO 8601 timestamp

3. **MemoryHealthSummarySchema** — aggregated health for progress display:
   - `total_engrams_recalled: z.number().int().nonnegative()`
   - `total_feedback_given: z.number().int().nonnegative()`
   - `overall_precision: z.number().min(0).max(1)`
   - `stale_count: z.number().int().nonnegative()` — engrams with no positive feedback recently
   - `last_feedback_phase: z.number().optional()` — most recent phase where feedback was given
   - `health_status: z.enum(["healthy", "degraded", "no_data"])` — summary status

All schemas use snake_case per API convention rule. Include JSDoc documentation with examples. Export inferred types alongside schemas.

### 3. Create memory-feedback helper

**Type:** auto
**TDD:** false
**Depends on:** 1, 2

Create `src/shared/__helpers/memory-feedback.ts` with feedback determination logic.

This module provides:

1. **`determineFeedback(config)`** — Given a list of recalled engrams and a verification result, returns an array of `MemoryFeedbackEntry` objects ready for `muninn_feedback` calls.

   Config schema (internal, camelCase):
   - `recalledEngrams: RecalledEngram[]` — from recall cache
   - `verificationPassed: boolean` — from lu-verifier result
   - `appliedEngramIds: string[]` — IDs the executor reported as applied (optional, default `[]`)
   - `phase: number` — current phase number

   Logic (SIMPLE heuristic per research Pitfall 2):
   - If `verificationPassed` is `true`: mark ALL recalled engrams as `useful: true`
   - If `verificationPassed` is `false` AND `appliedEngramIds` is non-empty: mark applied engrams as `useful: false`, mark non-applied as `useful: true` (they were not responsible for the failure)
   - If `verificationPassed` is `false` AND `appliedEngramIds` is empty: mark ALL recalled engrams as `useful: false`

   Returns `MemoryFeedbackEntry[]`.

2. **`computeMemoryPhaseMetrics(config)`** — Given feedback entries and token cost data, compute the five effectiveness metrics.

   Config schema (internal, camelCase):
   - `feedbackEntries: MemoryFeedbackEntry[]` — from `determineFeedback()`
   - `totalRecalled: number` — total engrams recalled
   - `totalApplied: number` — total engrams marked as applied
   - `memoryTokensInjected: number` — from `estimateTokens()` on memory context block
   - `phase: number`
   - `milestone: string`

   Computes:
   - `recall_precision = totalApplied / totalRecalled` (0 if totalRecalled is 0)
   - `hit_rate = feedbackEntries.filter(e => e.useful).length / totalRecalled` (0 if none)
   - `memory_tokens_injected` — pass-through
   - `stale_engram_pct` — set to 0 for now (requires historical data, populated at milestone boundary)
   - `confidence_calibration` — set to 0 for now (requires multi-phase data)

   Returns `MemoryPhaseMetrics`.

Use Zod schemas from task 1. Import `RecalledEngram` from recall-cache. Follow functional patterns (no classes). Include comprehensive JSDoc with examples.
