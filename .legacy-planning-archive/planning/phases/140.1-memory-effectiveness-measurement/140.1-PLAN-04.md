### Feedback-Based Confidence Evolution

After the standard confidence assignment, check MuninnDB for feedback history on the engrams you just wrote or evolved.

For each engram written during this learning extraction:

1. **Recall feedback history** for similar engrams (same concept pattern):

mcp__muninn__muninn_recall(

Use muninn_evolve to update the engram content with the new confidence level:

mcp__muninn__muninn_evolve(
  vault: "default",

- Only evolve confidence for engrams that have 3+ feedback data points (avoid premature adjustment)
- Never override an explicit human-set confidence (engrams with "Confidence: High [human-set]" in content)
- This augments the session-local heuristic, it does not replace it. For brand-new engrams with no feedback history, the session-local "2-3 validations" heuristic still applies.

### 2. Add feedback_score signal to lu-cognition composite scoring

**Type:** auto
**TDD:** false
**Depends on:** none

In `src/agents/general/lu-cognition.agent.ts`, find the 6-signal composite scoring model (around lines 299-371) and add a 7th `feedback_score` signal.

**Weight rebalancing:**

The current 6-signal weights sum to 1.0:

- semantic_similarity: 0.25
- tag_overlap: 0.15
- milestone_proximity: 0.30
- agent_match: 0.15
- confidence: 0.075
- recency: 0.075

Add `feedback_score` with weight **0.075** and reduce `milestone_proximity` from 0.30 to 0.225 to maintain the 1.0 sum. Milestone proximity loses the least relative importance since it is currently over-weighted relative to the other signals.

**New 7-signal model:**

- semantic_similarity: 0.25 (unchanged)
- tag_overlap: 0.15 (unchanged)
- milestone_proximity: 0.225 (was 0.30, reduced by 0.075)
- agent_match: 0.15 (unchanged)
- confidence: 0.075 (unchanged)
- recency: 0.075 (unchanged)
- feedback_score: 0.075 (NEW)

**feedback_score computation:**

```
feedback_score:
  - If engram has received muninn_feedback calls:
    - positive_ratio = positive_feedback_count / total_feedback_count
    - feedback_score = positive_ratio (ranges 0.0 to 1.0)
  - If engram has no feedback history:
    - feedback_score = 0.5 (neutral default — neither boosted nor penalized)
```

The feedback history is available because MuninnDB's SGD-based scoring updates happen automatically when `muninn_feedback` is called. However, lu-cognition cannot directly query feedback counts from MuninnDB. Instead, use a proxy:

- Engrams with "Confidence: High" in content AND recent milestone mentions → `feedback_score = 0.8`
- Engrams with "Confidence: Medium" or no confidence in content → `feedback_score = 0.5`
- Engrams with "Confidence: Low" in content → `feedback_score = 0.2`

This proxy works because lu-learner (Plan 4, Task 1) now evolves confidence based on actual feedback data. So "Confidence: High" correlates with positive feedback, and "Confidence: Low" correlates with negative feedback.

**CAUTION (from research Pitfall 5):** The weight is deliberately small (0.075) to avoid circular amplification. MuninnDB's SGD already adjusts scoring weights from feedback. This signal is a secondary boost in lu-cognition's ranking, not the primary feedback mechanism.

Update all relevant documentation within the agent:

1. The composite scoring formula (both occurrences around lines 304 and 358)
2. The checklist item mentioning "six signals" → "seven signals"
3. Any comments referencing the signal count
