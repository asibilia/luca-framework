## Key Design Decisions

1. **Proxy approach for feedback_score**: lu-cognition cannot directly query MuninnDB feedback counts, so it uses engram confidence level as a proxy. This works because lu-learner (Task 1) now evolves confidence based on actual feedback data, creating a reliable correlation.

2. **Weight budget from milestone_proximity**: The 0.075 weight for feedback_score was taken from milestone_proximity (0.30 -> 0.225) as specified in the plan. Milestone proximity was the most over-weighted signal relative to its informational value.

3. **Circular amplification prevention**: The feedback_score weight is deliberately kept small (0.075) because MuninnDB's internal SGD already adjusts scoring from `muninn_feedback` calls. This signal is a secondary ranking boost, not the primary feedback mechanism.
