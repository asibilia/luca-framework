# Phase 126 Plan 02: Error Boundaries

## Task Objective

Create and integrate React error boundaries across observer dashboard pages to gracefully handle rendering errors and provide user-friendly error states with retry functionality.

## Context

- Currently no observer pages have React error boundaries
- Errors in data-dependent sections can crash entire pages
- Need to add console.error logging in hook catch blocks (e.g., use-ledger.ts:26)
- Shared error boundary should be reusable across all pages

## Files to Create

1. `components/shared/error-boundary.tsx` - New shared error boundary component

## Files to Update

1. `app/agents/page.tsx`
2. `app/iterations/page.tsx`
3. `app/planning/page.tsx`
4. `app/workflow/page.tsx`
5. `app/harness/page.tsx`
6. `app/cost/page.tsx`
7. `app/decisions/page.tsx`
8. `app/notes/page.tsx`
9. `app/memory/page.tsx`
10. `app/tribunal/page.tsx`
11. `hooks/use-ledger.ts` - Add console.error in catch blocks

## Execution Steps

1. Create `components/shared/error-boundary.tsx` with:
   - Error boundary class component or useErrorBoundary hook pattern
   - User-friendly error display with error message
   - Retry button to reset error state
   - Automatic error logging to console.error

2. Wrap data-dependent sections in each page with error boundary:
   - Wrap main content areas, not entire pages
   - Allow sections to fail independently
   - Preserve navigation and layout

3. Update hooks to log errors:
   - Add `console.error` in all catch blocks
   - Include context about what operation failed
   - Preserve stack traces for debugging

4. Test error states:
   - Verify error boundary catches rendering errors
   - Verify retry functionality works
   - Verify console.error output is helpful

## Verification

- [ ] `components/shared/error-boundary.tsx` exists and exports ErrorBoundary component
- [ ] All 10 observer pages use error boundary around data-dependent sections
- [ ] `console.error` calls added to hook catch blocks
- [ ] Error banner displays with user-friendly message on errors
- [ ] Retry button resets error state and re-renders content
- [ ] TypeScript compiles without errors
- [ ] Test suite passes

## Success Criteria

- Graceful error handling across all observer dashboard pages
- Users can understand what went wrong and retry
- Errors are logged for debugging
- No complete page crashes from data rendering issues
