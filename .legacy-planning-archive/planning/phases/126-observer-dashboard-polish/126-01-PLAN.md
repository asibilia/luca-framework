# Phase 126 Plan 01: Loading Skeleton Consistency

## Task Objective

Replace ad-hoc inline loading states with the existing LoadingSkeleton component across 7 observer dashboard pages for visual consistency and maintainability.

## Context

- LoadingSkeleton component exists at `components/shared/loading-skeleton.tsx` with 4 variants: card, table, chart, text
- 7 pages currently use inline animate-pulse divs instead of the shared component
- This is a straightforward UI refactor with no behavioral changes

## Files to Update

1. `/app/agents/page.tsx`
2. `/app/iterations/page.tsx`
3. `/app/planning/page.tsx`
4. `/app/workflow/page.tsx`
5. `/app/harness/page.tsx`
6. `/app/cost/page.tsx` - also add animate-pulse to loading text
7. `/app/decisions/page.tsx`

## Execution Steps

1. Read each page file to identify current loading patterns
2. Replace inline loading divs with appropriate LoadingSkeleton variant based on content type:
   - Card layouts → LoadingSkeleton variant="card"
   - Table data → LoadingSkeleton variant="table"
   - Charts → LoadingSkeleton variant="chart"
   - Text content → LoadingSkeleton variant="text"
3. For cost page: ensure loading text has animate-pulse class
4. Verify no other inline animate-pulse patterns remain

## Verification

- [ ] `grep -r "animate-pulse" packages/luca-observer/app/` shows only expected instances (cost page loading text, LoadingSkeleton component itself)
- [ ] All 7 pages render loading states consistently
- [ ] No visual regressions in loading state appearance
- [ ] TypeScript compiles without errors

## Success Criteria

- All inline loading patterns replaced with LoadingSkeleton component
- Consistent loading experience across observer dashboard
- Code is more maintainable with single source of truth for loading states
