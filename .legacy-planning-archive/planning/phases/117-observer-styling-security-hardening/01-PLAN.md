# PLAN-117-01: Tailwind Arbitrary Value Cleanup & Dark Mode Verification

## Objective

Replace the single remaining Tailwind arbitrary grid-cols value in the observer, verify `max-w-[1400px]` is already resolved, confirm dark mode support is complete via the existing CSS variable system, and audit responsive grid patterns for correctness.

Source: `.planning/v2.7.0-MILESTONE-AUDIT.md` -- CRITICAL #2 (arbitrary Tailwind values), HIGH #8 (dark mode), HIGH #9 (responsive grid overrides).

## Context

@file packages/luca-observer/components/layout/detail-layout.tsx -- The only file using arbitrary `grid-cols-[1fr_320px]`. Replace with a Tailwind theme extension or standard utility.

@file packages/luca-observer/tailwind/base.css -- Source Tailwind v4 CSS. Already defines `html.light` and `html.dark` color palettes via CSS custom properties. Components use semantic tokens (`bg-card`, `text-foreground`, etc.), so dark mode should already work without per-component `dark:` classes.

@file packages/luca-observer/app/globals.css -- Compiled Tailwind output. Contains the `.lg\:grid-cols-\[1fr_320px\]` utility. Regenerated by `bun run tw:build`.

## Tasks

### Task 1: Replace arbitrary grid-cols in detail-layout.tsx

**Goal:** Remove `lg:grid-cols-[1fr_320px]` and use standard Tailwind grid utilities instead.

**File:** `packages/luca-observer/components/layout/detail-layout.tsx`

**Current code (line 14):**

```tsx
<div className="grid grid-cols-1 gap-6 lg:grid-cols-[1fr_320px]">
```

**Target code:**

```tsx
<div className="grid grid-cols-1 gap-6 lg:grid-cols-3">
  <div className="flex flex-col gap-6 lg:col-span-2">{main}</div>
  <div className="flex flex-col gap-6">{sidebar}</div>
</div>
```

This uses standard `lg:grid-cols-3` with `lg:col-span-2` for the main column, giving a roughly 2:1 ratio (similar to 1fr_320px at typical viewport widths) without arbitrary values.

**Verification:**

- `grep -r 'grid-cols-\[' packages/luca-observer/components/ packages/luca-observer/app/` returns zero matches
- Run `bun run tw:build` in the observer package to regenerate globals.css
- Visual: detail pages (cost, iterations, tribunal, agents) render two-column layout at lg+ breakpoints

**Expected result:** `grep -r 'max-w-\[1400' packages/luca-observer/` returns zero matches (already confirmed during planning exploration).

### Task 3: Verify dark mode support completeness

**Goal:** Confirm the observer's dark mode support is complete and functional.

**Analysis from planning exploration:**

- `tailwind/base.css` defines `html.light` and `html.dark` CSS variable overrides (all semantic tokens)
- All observer components use semantic color classes (`bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`, etc.)
- Zero instances of hardcoded `bg-white`, `bg-gray-*`, `text-gray-*`, `bg-slate-*` found in .tsx files
- The ThemeSync component (from themeAtom) toggles `html.light`/`html.dark` classes

**Action:** No code change needed. Dark mode is already fully supported via the CSS variable system established in Phase 111. Document as complete.

### Task 4: Audit responsive grid patterns

**Goal:** Review grid patterns across observer for overly aggressive responsive overrides.

**Current grid patterns (from grep):**

- `grid-cols-2 lg:grid-cols-4 xl:grid-cols-8` (overview-cards) -- 3-step breakpoint, fine
- `sm:grid-cols-2` (iteration-timeline, loading-skeleton) -- standard pattern
- `lg:grid-cols-2` (multiple pages) -- standard pattern
- `lg:grid-cols-3` (memory page) -- standard pattern
- `grid-cols-1 md:grid-cols-4` (cost page) -- jumps from 1 to 4 columns, verify readability
- `grid-cols-3` (session-plan-overview) -- no responsive, could be tight on mobile

**Action:** Review the `md:grid-cols-4` and fixed `grid-cols-3` patterns. If they cause layout issues at small viewports, add intermediate breakpoints. This is a minor cleanup pass, not a rewrite.

**Verification:**

- `bunx --bun tsc --noEmit` passes with no errors in luca-observer
- `bun run tw:build` succeeds in observer package
