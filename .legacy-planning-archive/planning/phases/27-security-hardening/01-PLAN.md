# Plan 27-01: Hook Script Hardening

## Objective

Harden the three hook shell scripts against low-severity security gaps identified in the audit: validate `transcript_path` in `context-monitor.sh` to reject relative paths and paths outside `$HOME` (SEC-01), sanitize `END_REASON` in `session-persist.sh` against markdown injection via allowlisting and truncation (SEC-02), and document the `COMMAND` variable extraction logic in `pre-commit-gate.sh` to prevent future misuse (SEC-05). ## Tasks

### Task 1: Validate `transcript_path` in `context-monitor.sh` (SEC-01)

**Goal:** Reject relative paths and paths that resolve outside `$HOME`, preventing information leakage (file size) from arbitrary filesystem locations.

**Files:** `src/hooks/scripts/context-monitor.sh`

**Steps:**

1. Insert a path validation block immediately after the `TRANSCRIPT_PATH` extraction (after line 47, before the `# --- Primary check` comment on line 49). Add the following between lines 47 and 49:

   ```bash
   # ─── SEC-01: Validate transcript path ──────────────────────────────────
   # Reject relative paths and paths outside $HOME to prevent
   # information leakage (file size) from arbitrary filesystem locations.
   if [ -n "$TRANSCRIPT_PATH" ]; then
     # Must be an absolute path
     case "$TRANSCRIPT_PATH" in
       /*) ;; # absolute path — OK
       *)
         TRANSCRIPT_PATH=""  # reject relative paths
         ;;
     esac
   fi

   if [ -n "$TRANSCRIPT_PATH" ]; then
     # Resolve symlinks and verify path is within home directory
     RESOLVED_PATH=$(realpath "$TRANSCRIPT_PATH" 2>/dev/null || echo "")
     case "$RESOLVED_PATH" in
       "$HOME"/*) ;; # within home directory — OK
       *)
         TRANSCRIPT_PATH=""  # outside home directory — reject
         ;;
     esac
   fi
   # ──────────────────────────────────────────────────────────────────────
   ```

2. Verify the script still has valid bash syntax: `bash -n src/hooks/scripts/context-monitor.sh`

**Verification:**

- [ ] `bash -n src/hooks/scripts/context-monitor.sh` exits 0 (valid syntax)
- [ ] The validation block is placed between the `TRANSCRIPT_PATH` extraction (line 47) and the primary check (line 49)

- [ ] Absolute paths under `$HOME` would pass validation unchanged
- [ ] Symlinks resolving outside `$HOME` would be rejected

### Task 2: Sanitize `END_REASON` in `session-persist.sh` (SEC-02)

**Goal:** Strip markdown-breaking characters from `END_REASON` and truncate to a reasonable length, preventing markdown injection into WORKING.md.

**Files:** `src/hooks/scripts/session-persist.sh`

**Steps:**

1. Insert a sanitization block immediately after the `END_REASON` extraction (after line 27, before the `WORKING_MD` assignment on line 29). Add the following between lines 27 and 29:

   ```bash
   # ─── SEC-02: Sanitize END_REASON ───────────────────────────────────────
   # Allow only alphanumeric, spaces, hyphens, underscores, and periods.
   # Prevents markdown injection into WORKING.md.
   END_REASON=$(printf '%s' "$END_REASON" | tr -cd '[:alnum:] _.-')
   # Truncate to 100 characters to prevent absurdly long reason strings.
   END_REASON="${END_REASON:0:100}"
   # ──────────────────────────────────────────────────────────────────────
   ```

2. Verify the script still has valid bash syntax: `bash -n src/hooks/scripts/session-persist.sh`

**Verification:**

- [ ] `bash -n src/hooks/scripts/session-persist.sh` exits 0 (valid syntax)

### Task 3: Document `COMMAND` extraction in `pre-commit-gate.sh` (SEC-05)

**Goal:** Add a comprehensive security documentation comment block before the `COMMAND` extraction logic, making the safety properties explicit for future maintainers.

**Files:** `src/hooks/scripts/pre-commit-gate.sh`

**Steps:**

1. Replace the existing two-line comment block at lines 29-30 with a comprehensive security documentation block. Replace:

   ```bash
   # Extract the Bash command being executed
   # Claude Code: tool_input.command, Cursor: command (top-level)
   ```

   With:

   ```bash
   # ─── COMMAND EXTRACTION: SECURITY NOTES ───────────────────────────────
   #
   # INPUT FORMAT (two platforms):
   #   Claude Code: { "tool_input": { "command": "git commit -m 'msg'" } }
   #   Cursor:      { "command": "git commit -m 'msg'" }
   #
   # EXTRACTION METHOD:
   #   Uses bun -e with JSON.parse() to safely extract the command string.
   #   No shell interpolation occurs — the command is never eval'd or exec'd.
   #   The printf '%s' format prevents format string injection.
   #
   # MATCHING STRATEGY:
   #   The case statement uses shell glob patterns (NOT regex).
   #   Only substring matches are checked — the command is never executed.
   #   This is safe because:
   #     1. case/esac does pattern matching, not execution
   #     2. $COMMAND is double-quoted, preventing word splitting
   #     3. No eval, exec, or subshell uses $COMMAND
   #
   # MAINTENANCE WARNING:
   #   - NEVER eval, exec, or source $COMMAND — it contains untrusted input
   #   - NEVER use $COMMAND in arithmetic expressions
   #   - Adding new case patterns is safe (glob matching only)
   #   - If you need to pass $COMMAND to another tool, use environment
   #     variables (like HOOK_CMD="$COMMAND" bun -e "...") — NOT arguments
   # ──────────────────────────────────────────────────────────────────────
   ```

2. Verify the script still has valid bash syntax: `bash -n src/hooks/scripts/pre-commit-gate.sh`

**Verification:**

- [ ] `bash -n src/hooks/scripts/pre-commit-gate.sh` exits 0 (valid syntax)
- [ ] The old 2-line comment is replaced by the comprehensive security block
- [ ] No functional code is changed — documentation only
- [ ] The COMMAND extraction (`printf '%s' ... | bun -e "..."`) immediately follows the comment block
