# Phase 6 Plan 1: Learning Evolution View

## Objective

Build a Learning Evolution page that visualizes how knowledge accumulates over time in MuninnDB. The page shows summary statistics, a timeline bar chart of learning activity, a category breakdown chart, and a recent learnings list. This phase also establishes reusable CSS-based charting patterns (no JS chart library) for future observer pages.

## Context

@lib/constants.ts — NAV_ITEMS array and design tokens
@components/layout/sidebar.tsx — Sidebar navigation with ICON_MAP
@hooks/use-memory.ts — Hook pattern: fetchingRef, Promise.allSettled, manual refresh
@hooks/use-decision-trail.ts — Focused hook pattern for single-page data
@app/memory/page.tsx — Page template: PageContainer + actions + ErrorBoundary + LoadingSkeleton
@components/memory/memory-entries.tsx — Category resolution logic (resolveCategory, KNOWN_CATEGORIES, CATEGORY_DISPLAY)
@lib/muninn-types.ts — MuninnEngram interface (memory_type, created_at, concept, confidence, tags)
@app/api/muninn/engrams/route.ts — Existing engrams endpoint (supports limit, type, since params)
@components/shared/loading-skeleton.tsx — LoadingSkeleton with "chart" variant
@components/shared/empty-state.tsx — EmptyState component
@components/layout/page-container.tsx — PageContainer wrapper

### 2. Create useLearningEvolution hook

**Type:** auto
**TDD:** false
**Depends on:** 1

Create `hooks/use-learning-evolution.ts` that fetches engrams from `/api/muninn/engrams?limit=500` and produces aggregated data for the learning page.

The hook must:

- Use the same `fetchingRef` + `Promise.allSettled` + manual `refresh()` pattern as `use-memory.ts`
- Reuse the `fetchJson` helper pattern (inline, since it is not exported from use-memory)
- Resolve each engram's category using the same hybrid mapping strategy as `memory-entries.tsx` (memory_type field, then concept prefix, then "uncategorized")
- Group engrams by category and compute counts: `{ pattern: number, decision: number, pitfall: number, preference: number, uncategorized: number }`
- Group engrams by time period for the timeline: `Array<{ label: string, counts: Record<string, number>, total: number }>`. Use day granularity. If data spans > 30 days, auto-bucket into weekly periods
- Sort timeline entries chronologically (oldest first)
- Return: `{ stats, timeline, categoryBreakdown, recentLearnings, loading, error, lastUpdated, refresh, configured }`
  - `stats`: `{ total: number, patterns: number, decisions: number, pitfalls: number, preferences: number }`
  - `timeline`: array of `{ label: string, counts: Record<string, number>, total: number }`
  - `categoryBreakdown`: array of `{ category: string, label: string, color: string, count: number, percentage: number }`
  - `recentLearnings`: the 20 most recent engrams sorted by `created_at` descending (raw `MuninnEngram[]`)
  - `configured`, `loading`, `error`, `lastUpdated`, `refresh`: same semantics as `use-memory`

**Files to create/edit:**

- `hooks/use-learning-evolution.ts` (new)

**Verification:**

- `bunx --bun tsc --noEmit` passes
- Hook exports match the return type described above
- No imports from `use-memory` internals (the hook is self-contained)
