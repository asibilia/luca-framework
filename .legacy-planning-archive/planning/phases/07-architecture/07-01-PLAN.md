# Plan 07-01: Fix Generated Rule Import Paths & Module Boundaries

## Frontmatter
- **ID**: 07-01
- **Title**: Fix Generated Rule Import Paths & Module Boundaries
- **Wave**: 1
- **Depends on**: none

## Objective

Fix the systematic import path bug in all 19 generated rule files under `src/rules/general/` and the generator script that produces them. Currently, every generated rule file imports from `./base/base-rule` and `./types/rule.types` (which resolve to the non-existent `src/rules/general/base/` and `src/rules/general/types/` directories). The correct paths are `../base/base-rule` and `../types/rule.types` (resolving to `src/rules/base/` and `src/rules/types/`). Additionally, document the intentional duplication of `sanitizeJsonParse` across the two isolated domains (`src/` and `packages/`).

## Context

- `scripts/generate-rules-from-cursor.ts` -- the generator script with the import path bug (lines 99-100)
- `scripts/generate-agents-from-cursor.ts` -- reference for correct import path pattern (`../base/base-agent`)
- `scripts/generate-skills-from-cursor.ts` -- reference for correct import path pattern (`../base/base-skill`)
- `src/rules/general/*.rule.ts` -- all 19 generated rule files with wrong imports
- `src/rules/base/base-rule.ts` -- the actual base class location
- `src/rules/types/rule.types.ts` -- the actual types location
- `src/shared/validation-utils.ts` -- contains duplicated `sanitizeJsonParse` (lines 64-67, 88-95)
- `packages/luca-framework/src/utils/sanitize.ts` -- the other copy of `sanitizeJsonParse` (lines 44-47, 55-62)
- `.planning/phases/07-architecture/07-RESEARCH.md` -- Finding #1 (HIGH severity) and Finding #6 (MEDIUM severity)
