# Plan 16-03: Context Assembly & Orchestrator Update

## Objective

Build the context assembly functions that the orchestrator uses to construct tier-appropriate context for each sub-agent invocation, and update the lu-execute-phase skill source to use context-aware sub-agent spawning with result envelope parsing. This plan implements the runtime behavior: given an agent name and complexity level, assemble the correct document set respecting isolation modes and progressive disclosure.

## Context

- **Context module types (from 16-01):** `src/context/types.ts`, `src/context/defaults.ts`, `src/context/result-envelope.ts`
- **Schema integration (from 16-02):** `src/agents/types/agent.schemas.ts` (context field), `src/complexity/types.ts` (contextPromotions)
- **Context tier resolution (from 16-01/16-02):** `src/context/resolve-context-tier.ts` + `resolveContextTierFromMatrix`
- **lu-execute-phase skill source:** `src/skills/general/lu-execute-phase.skill.ts` (lines 276-352: executor spawning with hardcoded context)
- **Current context passing pattern (from 16-RESEARCH.md audit):**
  - lu-executor receives: plan content + STATE.md + WORKING.md (~T2 level)
  - lu-verifier receives: plans + summaries + STATE.md + WORKING.md (violation: should NOT get WORKING.md per Decision 6)
  - Code reviewers receive: git diff + CLAUDE.md (already close to cold isolation)
  - Harness fix executor: minimal context (already T0)
- **Default agent context profiles:** `src/context/defaults.ts` (DEFAULT_AGENT_CONTEXT_PROFILES)

## Design Decisions Applied

1. **Context assembly functions in src/context/ module** (Decision 7): Build-time compilation, not runtime TypeScript
2. **Clean separation: agents = HOW, orchestrator = WHAT** (Decision 8): Assembly happens in orchestrator, agent just receives the assembled context
3. **Writer/reviewer isolation** (Decision 6): Cold (reviewers: diff + BRAIN.md), warm (verifier: plans + summaries, NO WORKING.md)
4. **Progressive context disclosure** (CTXM-04): Documents loaded on-demand, not all upfront
5. **Conflict resolution: keep all findings, tag with source agent** (Decision 5): Result envelope aggregation

## Tasks

### Task 1: Create src/context/context-assembler.ts — Core Assembly Function

**Goal:** Build the context assembly function that takes an agent name, complexity level, and available documents, then returns the correctly scoped context document set.

**File:** `src/context/context-assembler.ts` (new)

**Primary function:**

```typescript
/**
 * Assembles the context document set for a sub-agent invocation.
 *
 * Given the agent's context profile and the current complexity level,
 * resolves the effective context tier, applies isolation overrides,
 * and returns only the documents the agent should receive.
 *
 * @param agentName - Name of the agent being spawned
 * @param complexityLevel - Current task complexity level
 * @param availableDocuments - All available context documents
 * @param overrideProfile - Optional context config override (from agent frontmatter)
 * @returns The filtered document set for this agent
 */
export function assembleContext(
  agentName: string,
  complexityLevel: ComplexityLevel,
  availableDocuments: ContextDocumentSet,
  overrideProfile?: ContextConfig,
): AssembledContext;
```

**Return type:**

```typescript
export const assembledContextSchema = z.object({
  /** The filtered document set for this agent */
  documents: contextDocumentSetSchema,
  /** The resolved effective context tier */
  effective_tier: contextTierSchema,
  /** The isolation mode applied */
  isolation_mode: isolationModeSchema,
  /** Advisory budget allocation (if configured) */
  budget: budgetAllocationSchema.optional(),
  /** Agent name for traceability */
  agent_name: z.string(),
});
```

**Assembly logic:**

1. Look up agent profile: use `overrideProfile` if provided, else look up `DEFAULT_AGENT_CONTEXT_PROFILES[agentName]`, else use `FALLBACK_CONTEXT_PROFILE`
2. Resolve effective tier: `resolveContextTierFromMatrix(profile.default_tier, profile.promotable_to, complexityLevel)`
3. Get base document keys: `TIER_DOCUMENTS[effectiveTier]`
4. Apply isolation overrides: if `profile.isolation !== 'none'`, use `ISOLATION_OVERRIDES[profile.isolation]` to add/remove documents
5. Filter `availableDocuments` to only include the allowed keys
6. Return `AssembledContext` with resolved metadata

**Progressive disclosure support (CTXM-04):**

Add a separate function for on-demand document loading:

```typescript
/**
 * Returns the list of document keys that should be loaded for this agent.
 * The orchestrator can use this to load documents lazily rather than
 * reading all files upfront.
 *
 * @param agentName - Name of the agent being spawned
 * @param complexityLevel - Current task complexity level
 * @param overrideProfile - Optional context config override
 * @returns Array of document keys to load
 */
export function getRequiredDocumentKeys(
  agentName: string,
  complexityLevel: ComplexityLevel,
  overrideProfile?: ContextConfig,
): string[];
```

This enables the orchestrator to read only the files needed for each sub-agent rather than loading everything upfront.

### Task 2: Create src/context/result-aggregator.ts — Result Aggregation

**Goal:** Build the result aggregation function that synthesizes sub-agent outputs into a phase-level summary without re-loading full sub-agent context (CTXM-03).

**File:** `src/context/result-aggregator.ts` (new)

**Primary function:**

```typescript
/**
 * Aggregates multiple sub-agent result envelopes into a phase summary.
 *
 * Merges artifacts, deduplicates issues, tallies statuses, and produces
 * a consolidated view for the orchestrator. Keeps all findings and tags
 * each with the source agent (Decision 5: no auto-resolution).
 *
 * @param results - Array of parsed result envelopes from sub-agents
 * @returns Aggregated phase result
 */
export function aggregateResults(results: ResultEnvelope[]): AggregatedResult;
```

**Aggregated result type:**

```typescript
export const aggregatedResultSchema = z.object({
  /** Overall status: 'success' if all succeeded, 'partial' if any partial, 'failed' if any failed */
  overall_status: resultStatusSchema,
  /** Combined summary from all agents */
  summary: z.string(),
  /** All artifacts from all agents, tagged with source */
  artifacts: z.array(
    resultArtifactSchema.extend({
      source_agent: z.string(),
    }),
  ),
  /** All issues from all agents (kept per Decision 5, no auto-resolution) */
  issues: z.array(resultIssueSchema),
  /** Per-agent status breakdown */
  agent_statuses: z.array(
    z.object({
      agent_name: z.string(),
      status: resultStatusSchema,
      duration_ms: z.number().optional(),
    }),
  ),
  /** Issue counts by severity */
  issue_counts: z.object({
    critical: z.number(),
    high: z.number(),
    medium: z.number(),
    low: z.number(),
    info: z.number(),
  }),
  /** Total duration across all agents */
  total_duration_ms: z.number(),
});
```

**Aggregation logic:**

1. Determine overall status: `failed` if any failed, `partial` if any partial/timeout, `success` if all succeeded
2. Concatenate summaries with agent name headers
3. Merge artifacts arrays, adding `source_agent` from metadata
4. Merge issues arrays (they already have `source_agent` from the envelope)
5. Deduplicate issues by `file + line + message` key (keep first occurrence, preserve source_agent)
6. Count issues by severity
7. Sum durations

**Verification:**

- [ ] Mixed partial inputs produce `overall_status: 'partial'`
- [ ] Issues from different agents are preserved with source attribution
- [ ] Duplicate issues (same file:line:message) are deduplicated
- [ ] Severity counts are accurate
