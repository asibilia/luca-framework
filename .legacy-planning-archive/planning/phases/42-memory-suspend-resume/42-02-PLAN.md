# 42-02: Milestone Tags for MEMORY.md, Milestone-Scoped Recall, Memory Bridge Updates

## Objective

Add milestone tags to MEMORY.md entries (MEM-05), implement milestone-scoped recall with temporal relevance scoring (MEM-04), and update the memory bridge and cognitive pre-flight to leverage milestone-aware recall. After this plan, memory recall prioritizes entries from the current milestone while still surfacing relevant entries from previous milestones.

## Context

### Current State

- `memoryEntrySchema` has: id, category, title, content, tags, agent, confidence, added_at, last_recalled_at, recall_count, token_estimate
- No `milestone` field exists on memory entries
- Memory recall (procedure-recall.ts) scores by tag overlap and trigger similarity but not by milestone proximity
- The memory bridge `read-memory` command supports --tags and --category filters but not --milestone
- Cognitive pre-flight loads MEMORY.md but doesn't weight by milestone

### Design Decisions

1. **Milestone field**: Optional string on MemoryEntry (e.g., "v1.5.0"). Entries without explicit milestone inherit from STATE.md current_milestone at time of learning extraction.
2. **Temporal relevance scoring**: Milestones are compared by version semver proximity. Current milestone = 1.0 weight, previous = 0.7, two back = 0.4, older = 0.2.
3. **Backward compatible**: Entries without milestone field default to weight 0.5 (neutral).
4. **Scoring composition**: Final score = (tag_overlap _ 0.3) + (milestone_relevance _ 0.4) + (confidence_score _ 0.15) + (recency _ 0.15).

### Task 3: Milestone-Scoped Recall Scoring (42-02-T3)

**Goal:** Create scoring function for milestone temporal relevance.

**File:** `src/memory/milestone-recall.ts`

```typescript
interface MilestoneRecallConfig {
  /** Current milestone version string */
  current_milestone: string;
  /** Weight multiplier for milestone relevance (default: 0.4) */
  milestone_weight?: number;
  /** Weight multiplier for tag overlap (default: 0.3) */
  tag_weight?: number;
  /** Weight multiplier for confidence (default: 0.15) */
  confidence_weight?: number;
  /** Weight multiplier for recency (default: 0.15) */
  recency_weight?: number;
}

interface ScoredMemoryEntry {
  entry: MemoryEntry;
  score: number;
  milestone_proximity: number; // 0.0 - 1.0
  tag_overlap: number; // 0.0 - 1.0
}

/**
 * Score and rank memory entries by milestone proximity and relevance.
 *
 * @param entries - All parsed memory entries
 * @param queryTags - Tags to match against (from phase/task context)
 * @param config - Scoring configuration
 * @returns Entries sorted by descending score
 */
function scoreMilestoneRecall(
  entries: MemoryEntry[],
  queryTags: string[],
  config: MilestoneRecallConfig,
): ScoredMemoryEntry[];
```

**Milestone proximity calculation:**

- Parse version strings using simple semver comparison
- Same milestone: 1.0
- Adjacent minor version (e.g., v1.5 → v1.6): 0.7
- Two versions apart: 0.4
- Three+ versions apart: 0.2
- No milestone on entry: 0.5 (neutral)

**Verification:** Scoring function returns higher scores for current-milestone entries. Entries without milestone get neutral weight.

### Task 4: Bridge read-memory --milestone Integration (42-02-T4)

**Goal:** Add --milestone flag to memory bridge read-memory command.

**New CLI options:**

```bash
# Score by milestone relevance
bun run src/memory/bridge.ts read-memory --milestone=v1.6.0

# Combined with tag filtering
bun run src/memory/bridge.ts read-memory --milestone=v1.6.0 --tags=state-machine --limit=5
```

**Output format when --milestone is used:**

```json
{
  "entries": [
    {
      "id": "p-zod-safeparse",
      "title": "Zod safeParse at API boundaries",
      "category": "pattern",
      "milestone": "v1.6.0",
      "score": 0.92,
      "milestone_proximity": 1.0,
      "tags": ["state-machine", "validation"]
    }
  ],
  "total": 5,
  "milestone": "v1.6.0"
}
```

**Changes to `src/memory/bridge.ts`:**

- Import `scoreMilestoneRecall` from `./milestone-recall.ts`
- In `handleReadMemory()`, detect `--milestone` arg
- When present, score entries and sort by score before applying limit

**Verification:** Bridge returns milestone-scored results when --milestone is provided. Regular read-memory still works without --milestone.
