### 2. Convert doctor CheckResult to Zod schema (W5)

**Type:** auto
**TDD:** false
**Depends on:** none

The `CheckResult` interface in `doctor/types.ts` should be converted to a Zod schema per the schema-first-parsing rule. This is a type definition change only -- consumers construct literal objects that match the shape, so structural typing ensures compatibility.

**What to do:**

1. Read `packages/luca-framework/src/utils/doctor/types.ts` to find the `CheckResult` interface.
2. Convert the interface to a Zod schema:

```typescript
import { z } from "zod";

/**
 * Internal schema: Doctor check result.
 *
 * Represents the outcome of a single diagnostic check.
 * Uses camelCase -- internal-only, not an API payload.
 */
export const CheckResultSchema = z.object({
  name: z.string(),
  status: z.enum(["pass", "fail", "warning"]),
  message: z.string(),
  fixCommand: z.string().nullable(),
  details: z.string().nullable(),
});

export type CheckResult = z.infer<typeof CheckResultSchema>;
```

3. Verify that the `export interface CheckResult` is replaced by the `export type CheckResult = z.infer<...>` pattern.
4. Check all consumers in `doctor/checks/` to ensure they still compile. Since they construct literal objects matching the shape, no changes should be needed.
5. Run `bunx --bun tsc --noEmit` to verify.

**Files to create/edit:**

- `packages/luca-framework/src/utils/doctor/types.ts` (convert interface to Zod schema)

**Verification:**

- `bunx --bun tsc --noEmit` passes
- `CheckResultSchema` is exported as a Zod schema
- `CheckResult` type is inferred from the schema via `z.infer<>`
- All doctor check files still compile without changes

### 4. Add lodash filter/cloneDeep in init.ts (DX)

**Type:** auto
**TDD:** false
**Depends on:** none

Per the lodash-preference rule, replace built-in Array methods with lodash equivalents where appropriate in `init.ts`. Focus on:

- `Array.filter()` calls -> `filter()` from lodash
- Any deep clone operations -> `cloneDeep()` from lodash
- `Array.sort()` calls -> `orderBy()` from lodash

**What to do:**

1. Read `packages/luca-framework/src/commands/init.ts` to identify Array method usage.
2. Replace appropriate built-in calls with lodash equivalents:
   - `arr.filter(...)` -> `filter(arr, ...)`
   - Deep object copies using spread or `JSON.parse(JSON.stringify(...))` -> `cloneDeep(...)`
3. Add individual lodash imports at the top of the file: `import filter from "lodash/filter"` etc.
4. Do NOT replace simple cases where lodash adds no value (e.g., `.length`, `.join()`, `.includes()`).
5. Run `bunx --bun tsc --noEmit` to verify.

**NOTE:** If init.ts has already been significantly modified by Plans 1-3, the executor should read the current state of the file. If no Array.filter/sort calls remain, this task may be a no-op or very small.

**Files to create/edit:**

**Verification:**

- `bunx --bun tsc --noEmit` passes
- lodash imports use individual import pattern (e.g., `import filter from "lodash/filter"`)
