# 40-01: Package Scaffold + Core Machine Extraction

## Objective

Create the `packages/luca-state/` package directory and extract all core state machine source files from `src/state-machine/` into it. By the end of this plan, the package will contain the complete machine definition, types, guards, actions, events, actors, and utility files -- all compiling with zero imports referencing framework paths outside the package.

This is the foundation plan. Plans 40-02 and 40-03 depend on the package scaffold and core files created here.

## Context

The state machine currently lives in `src/state-machine/` and has 4 import dependencies on framework modules:

- `../shared/cli-utils.ts` -- used by bridge.ts, cli.ts, snapshot.ts (3 pure functions)
- `../shared/types` -- used by persistence.ts (1 type: `Result<T>`)
- `../complexity` -- used by guards.ts (`meetsThreshold`, `ComplexityLevel`, `StepActivation`)
- `../iteration/budget` + `../iteration/types` -- used by guards.ts (`shouldStartIteration`, `budgetStateSchema`)

Resolution: all dependencies are inlined as self-contained copies within `src/utils/`.

## Tasks

### Task 1: Create Package Scaffold (40-01-T1)

**Goal:** Set up the `packages/luca-state/` directory with all configuration files following the existing `luca-framework` package pattern.

**Files:**

- `packages/luca-state/package.json`
- `packages/luca-state/build.config.ts`
- `packages/luca-state/tsconfig.json`
- `packages/luca-state/bunfig.toml`

**Implementation:**

```json
{
  "name": "luca-state",
  "version": "0.0.1",
  "description": "Standalone XState v5 state machine for the Luca agentic workflow",

    "build": "unbuild",

```

**build.config.ts** -- Single entry point for now (bridge entry added in Plan 40-02 after bridge.ts is extracted):

```typescript

  declaration: true,

```

**tsconfig.json** -- Extend root config:


Create the `bin/` directory (empty for now; populated in Plan 40-02).

### Task 2: Create Self-Contained Utility Files (40-01-T2)

**Goal:** Inline the ~80 lines of utility code that guards.ts, bridge.ts, cli.ts, and snapshot.ts depend on from framework modules.

**Files:**

- `packages/luca-state/src/utils/cli-utils.ts`
- `packages/luca-state/src/utils/complexity-utils.ts`
- `packages/luca-state/src/utils/budget-utils.ts`

**cli-utils.ts** -- Copy from `src/shared/cli-utils.ts` (3 functions: `getArg`, `hasFlag`, `escapeRegex`). No changes needed to function bodies. Update module JSDoc to reference the package context.

**complexity-utils.ts** -- Self-contained copy of:

- `COMPLEXITY_LEVELS` const array (from `src/complexity/types.ts`)
- `ComplexityLevel` type (derived from const array)
- `COMPLEXITY_ORDER` record (from `src/complexity/types.ts`)
- `StepActivation` type (from `src/complexity/types.ts`)
- `meetsThreshold()` function (from `src/complexity/types.ts`)

These are all pure type/value declarations with no further dependencies.

**budget-utils.ts** -- Self-contained copy of:

- `BUDGET_STATUSES` const array (from `src/iteration/types.ts`)
- `budgetStatusSchema` Zod schema (from `src/iteration/types.ts`)
- `BudgetStatus` type (from `src/iteration/types.ts`)
- `budgetStateSchema` Zod schema (from `src/iteration/types.ts`)
- `BudgetState` type (from `src/iteration/types.ts`)
- `assessBudget()` function (from `src/iteration/budget.ts`)
- `shouldStartIteration()` function (from `src/iteration/budget.ts`)

Only the budget-related schemas and the two functions used by guards.ts are needed. The rest of `src/iteration/types.ts` (iteration records, convergence, loop config, etc.) is not used by the state machine and should NOT be copied.

### Task 3: Extract types.ts with Local Result Type (40-01-T3)

**Goal:** Copy `src/state-machine/types.ts` into the package and add the `Result<T>` discriminated union type inline (previously imported from `../shared/types`).

**Files:**

- `packages/luca-state/src/types.ts`

**Implementation:**

1. Copy `src/state-machine/types.ts` verbatim into `packages/luca-state/src/types.ts`
2. Add the `Result<T>` type at the top of the file (after the zod import):

```typescript
/**
 * Discriminated union for operation results.
 *
 * Used by persistence functions for success/failure returns.
 */
export type Result<T> =
  | { success: true; data: T }
  | { success: false; error: string };
```

3. No other import changes needed -- `types.ts` only imports from `zod`

### Task 4: Extract guards.ts with Rewired Imports (40-01-T4)

**Goal:** Copy `src/state-machine/guards.ts` and replace all framework imports with local package imports.

**Files:**

- `packages/luca-state/src/guards.ts`

**Import rewiring:**

| Old Import                   | New Import                        |
| ---------------------------- | --------------------------------- |
| `from "../complexity"`       | `from "./utils/complexity-utils"` |
| `from "../complexity/types"` | `from "./utils/complexity-utils"` |
| `from "../iteration/budget"` | `from "./utils/budget-utils"`     |
| `from "../iteration/types"`  | `from "./utils/budget-utils"`     |

Specifically, change these lines:

```typescript
// OLD:
import { meetsThreshold } from "../complexity";
import type { ComplexityLevel, StepActivation } from "../complexity/types";
import { shouldStartIteration } from "../iteration/budget";
import { budgetStateSchema } from "../iteration/types";

// NEW:
import { meetsThreshold } from "./utils/complexity-utils";
import type { ComplexityLevel, StepActivation } from "./utils/complexity-utils";
import { shouldStartIteration } from "./utils/budget-utils";
import { budgetStateSchema } from "./utils/budget-utils";
```

Function bodies remain unchanged.

All intra-module relative paths (`./types`, `./guards`, etc.) remain valid because the file layout within the package mirrors the original.

### Task 7: Create defaults.ts with DEFAULT_COMPLEXITY_MATRIX (40-01-T7)

**Goal:** Create a self-contained `defaults.ts` that exports `DEFAULT_COMPLEXITY_MATRIX` for use by tests and as a package API. This avoids any dependency on `src/complexity/defaults.ts`.

**Files:**

- `packages/luca-state/src/defaults.ts`

**Implementation:**

Import types from `./utils/complexity-utils` (not from the framework's `src/complexity/`). Define the `ComplexityGate` interface locally (simplified version without the `CognitionTier` and `ContextTier` promotion fields, since those types come from `src/agents/` and `src/context/` which are framework-only).

The matrix values must exactly match `src/complexity/defaults.ts` `DEFAULT_COMPLEXITY_MATRIX`. Include all fields: `cognitivePreflight`, `research`, `discussion`, `planVerificationIterations`, `harnessFixIterations`, `verifyFixIterations`, `verificationMode`, `codeReviewAgents`, `uat`, `learningCapture`.

For the promotion fields (`cognitionPromotions`, `contextPromotions`), use `Record<string, string>` instead of the typed enums since those enums are framework-internal.

**Files:**

- `packages/luca-state/src/index.ts`

**Implementation:**

Mirror the structure of `src/state-machine/index.ts` with these additions:

The barrel should be organized with clear section comments matching the current pattern.

### Task 9: Verify TypeScript Compilation and Zero Framework Imports (40-01-T9)
