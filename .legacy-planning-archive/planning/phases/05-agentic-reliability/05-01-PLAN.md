# Phase 5 Plan 01: Verify Stall Detection & Agent Health, Add Skill Dependency Schema

## Objective

Verify that #53 (stall detection) and #52 (agent health) are already addressed by existing infrastructure. Add skill dependency schema (#54) with topological sort and conflict detection.

## Context

Codebase analysis reveals extensive existing infrastructure:

- **#53**: State machine has `verification_attempts` counter, `max_verification_attempts` (default 3), `canRetryVerification` guard, `VERIFY_HALTED` → `paused`. Stall detector uses 2-of-3 signal rule. Config exposes `iteration.stale_threshold`.
- **#52**: `src/agents/__helpers/health-check.ts` validates agent config completeness. Runtime tool/model checks don't apply — agents are compiled TS definitions, not running services.
- **#54**: No skill dependency metadata exists. Skill schema has name/description only.

## Wave 1: Verify Completed Work

### Task 1.1: Verify #53 stall detection is complete

Confirm the full verification retry pipeline is wired:

1. `canRetryVerification` guard in `src/state/guards.ts` checks `verification_attempts < max_verification_attempts`
2. `VERIFY_FAILED` transitions to `executing` if guard passes, `failed` if not
3. `VERIFY_HALTED` transitions to `paused` with `recordHalt` action
4. `incrementVerificationAttempts` and `resetVerificationAttempts` actions exist
5. Config.json `iteration.stale_threshold` is respected

**Verification:** Grep confirms all 5 elements exist. No code changes needed.

### Task 1.2: Verify #52 agent health check is complete

Confirm `checkAgentHealth()` validates required fields (name, description, sections) and `checkAllAgentsHealth()` bulk-checks an array of configs.

**Verification:** Read `src/agents/__helpers/health-check.ts`. Functions exist. No code changes needed.
